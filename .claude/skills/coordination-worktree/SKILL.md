# /coordination-worktree — 文件信箱通讯层 + worktree 工作模式

存在理由:多会话协作里,平台的会话间消息要么需人工点确认、要么在空闲期送不到;一个共享目录+一套命名约定,是唯一实证在无人值守下也能可靠送达、可审计、可回放的通道。worktree 则让每条线在同一仓里互不踩脚。项目具体路径读项目根 `PROJECT-PROFILE.md`。

## 一、协调目录=通讯层
1. **一个项目一个协调目录**(如 `<项目>/coordination/`),扁平存放,历史件按月归档到 `_archive/YYYYMM/`(Monitor 只扫顶层)。**落盘即送达,收件=对方 Monitor 叫醒后消费**;不发平台消息、不点确认框。
2. **文件名即路由**:`致<收件角色>-<发件角色>-<件型>-<主题>-<YYYYMMDD-HHMM>.md`(定向件);`<角色>-<件型>-<主题>-<HHMM>.md`(该角色的产出件)。角色 token 必须出现在文件名里,各角色的 Monitor pattern 按角色 token 收件并从真实文件名回测(见 /moniter-on)。
3. **固定的文件类型清单**:执行令/一行令(派活)·回执(收到并将做什么)·进度(30 分钟一落或转折时)·交回(完工,六节:目标与出处/改动清单/红绿验证(先复现出错再验证修好)/测试证据/规范或文档摘要/自检与遗留)·探活(对端疑死)·注记(主动提醒,不要求回复)·SELFTEST(通道实测(发一个真事件看它能否回到会话),阅后即焚)·心跳/状态(脱离进程写,**不进人读流**)。
4. **时刻**:文件名与内文时刻先 `date` 实取再落笔;估写=违规。
5. **会话级活性判据**:判对端活只认它的**进度/回执/交回件 mtime**;心跳/TICK/标记文件 由脱离进程写,只证进程活。停更超 40 分钟→探活件;探活 30 分钟无回执→备援。
6. **收货门**:交回件不是收货;主编排独立核对(数字回原文/关键宣称回源库面或真机/抽样复跑)后才收货;执行体降级时加码核对。**引用他方数字必回原件逐字对;收件读全文,禁 tail 抽读后宣称「未落」;令件前提当刻 ls 确认。**
7. **台账**:决策/事件台账是 SSOT(owner 原话逐字,事件按时刻前插);文件信箱件是过程,台账是结论。checkpoint/handoff 只记路径。
8. 禁入文件信箱:凭据、密钥、明文口令(只写位置指针);签名尾注类平台默认物按项目铁律。

## 二、worktree 工作模式
1. **一线一树**:每条修复/功能线从**钉死的基座 commit** `git worktree add --detach <目录>/<线名> <sha>` 拉出;工单写明基座 sha,开工先 `rev-parse HEAD` 亲验。
2. **改动面白名单+禁区**写进工单;禁碰主线、发版树与他人树;**合并权归主编排**(cherry-pick/ff/tag 由编排做,线只 commit 不 push)。
3. **禁 `git stash`**:整仓所有 worktree 共享一个 stash 栈,并行线 pop 会互相弹错树(实证)。要证明测试会抓错,只用 `git show HEAD:<path>` 导出对比、单文件 checkout、或「改坏→红→复原→绿」。
4. **写前自核**:`git status --short`,树上出现陌生 modified 文件=并发污染信号,停手上报,禁顺手 checkout 清掉(可能是别人唯一副本)。主编排解缠序:先双树全量 diff 快照,再 `git apply --check` 原子预检后搬运。
5. **编号预分配**:迁移号/工单号/端口由编排在派线时分配,防撞号;弃用的号留空不补。
6. **跑批期树冻结**:全量测试在某树上跑时禁改该树;并行封版另起 worktree 或等 DONE 标记文件。
7. **清理**:线并入且树净后 `git worktree remove`;发版 tag 落成后统一清;快照 patch 留 scratchpad 作证。
8. **期望 commit 清单**:合流后编排开列「线名→最终 SHA→来源注记」,构建方按清单核 `git log` 集合相等+文件面同族——专治 stash 互踩后「tag 装错东西」。

## 三、角色速记
- 主编排:唯一汇合点与裁决者;发令、收货、合流、台账。
- 独立会话线(部署/复核/顾问):有自己的 Monitor 与心跳,靠文件信箱通讯,会话级活性按 §一.5 判。
- 子代理:由编排派出,交回件落文件信箱;换代后无法续聊,只能按交回件收货。
