# /keep-pushing — 无人值守自主推进模式

owner 离机,从本 turn 起进入无人值守窗,直到 owner 回来发话。存在理由:一次误用需人工确认的工具卡死流水线 8 小时;一次「等一份其实已到的件」卡死 6 小时。项目事实(协调目录/台账/心跳/铁律)读项目根 `PROJECT-PROFILE.md`,本 skill 零项目词。

## 0 · 生效声明(一条不跳)
1. **盘点现场**:在飞后台任务/子代理;文件信箱未消费件(按 mtime 扫协调目录);上一轮承诺未闭环的事。凡「等着我的」,本窗第一批处理。
2. **叫醒机制实证**:文件信箱 Monitor 按 /moniter-on 重架并通道实测(发一个真事件看它能否回到会话);周期兜底用 **平台定时唤醒**(ScheduleWakeup/loop)。后台任务完成通知与 cron 在会话空闲期可延迟数十分钟到数小时(实证 63 分钟、6 小时各一次),**关键步骤禁只依赖它们**。
3. **写当窗计划**:目标态(args 给了用 args,没给=推进头号目标到只剩 owner 决策)+依赖图(只有真依赖才串行)+候 owner 清单(空表起步),落协调目录 `<前缀>-值守计划-<日期>.md`。
4. 向各活跃 lane 落一份通告:本窗无人值守,通讯只走文件信箱。
5. 跑一次 `/compass` 全检;写值守开关文件 state=active;架轻检循环(定时唤醒,20-30 分钟一次 `/compass 轻检`)。

## 1 · 通讯铁律
- **文件信箱=唯一通道**:落盘即送达,收件=Monitor 叫醒后消费。
- **绝对禁用一切需人工点击确认的工具**(`send_message`/AskUserQuestion/任何「ALWAYS prompts」工具)。会触发弹窗的动作:先找不弹窗的等价路;找不到且非关键→入候 owner 清单,继续干别的。
- **时刻机械法**:带时刻的产物先 `T=$(date '+%F %T')`,文件名与内文只引 `$T`,禁手打时刻(提醒式规则实证无效)。

## 2 · 调度纪律
- **依赖图并发**:互不依赖的工单同时派;禁日历日串行。
- **分层用模(20260916 owner 重申,必填)**:子代理 model+effort 必填,禁继承主会话(hook 拦):施工 sonnet·high(涉及前端可 opus5·high)/ 机械扫 haiku·low / 复核 sonnet·max(涉及前端或跨层可 opus5·max)/ 盲测 sonnet·high 一员顺序走;主循环只编排/终审。执行体降级时收货加码。harness 给足(/5gate 用量纪律第 7 条)。
- **每交付必独立复核**:worker 自我声明≠收货;复核后才合流。
- **落盘必复验**:merge/写文件/测试结果落盘后用独立 wc/ls/git 实测;**收件读全文(或 grep 目标关键字),禁 tail/head 抽读后宣称「未落」**;宣称「对方没交」前必 ls+grep;**引用他方数字必回原件逐字对**。
- **令件前提当刻确认**:工单里写的「某件已交回/某步已做」发令时 ls 确认,模板里的前提不随转正为真。
- **对端活性只认会话级副作用**(进度/回执/交回件 mtime);脱离进程写的心跳/标记文件不算。派出去的 lane 超 30 分钟无会话级动作→落探活件;两次无回应→记候 owner 清单,改道推进。
- **不脑补**:证据不足就取证,取证不了就挂清单。

## 3 · 推进主循环(每次被叫醒)
```
consume(新件/完工通知)→ 独立验证 → 裁决(收货/打回/派复核)
→ dispatch(下一批可派工单)→ record(台账/值守计划勾销)
→ 还有可推进项?有→继续派;全部剩余=owner 专属决策→ §4 收口
```
- turn 结束的唯一合法状态:所有活性工作已委派且被叫醒机制覆盖,或已达 §4。**「静候」前必列出所有不依赖等待项的未完成产物,清单非空禁静候**;等待只对真依赖合法。
- 破坏性/不可逆动作(生产发布、真库写、force-push、删非己产物、对外发送)仍禁,挂清单——除非项目档案记有 owner 明示授权口径。

## 4 · 收口(只剩 owner 决策时)
1. 候 owner 清单定稿:每项一句现状+选项+推荐(说人话)。
2. owner 第一眼报告(项目有 HTML 交付惯例则出 HTML;内部台账用 md)。
3. 证据路径全落盘,Monitor 保持常驻。
4. 关值守开关文件(state=closed;owner 回来发话时同样要关)。
5. 最后一条给 owner:干成了什么/在飞什么/候拍板什么/证据在哪。不发提问式结尾。

## 5 · 与既有制度的关系
不覆盖项目制度(验真/收货门/署名禁令/HTML 交付/说人话…);冲突时项目制度优先,但 §1 通讯铁律无例外。

## 6 · 停摆恢复(用量限制 / 网络断连;20260907 实战沉淀)
停摆的形态:主会话与各 lane 同账号同时不响应;lane 的在飞子代理直接被 429/ECONNRESET 杀停(通知会延迟到恢复后才到主会话);**Monitor 进程不死、心跳照刷、自发 TICK 事件排队**,恢复后一并涌回——所以心跳新鲜不证明会话活,TICK 同批到达 = 期间未观测。
1. **开窗时先落预案**(owner 一句「usage 可能不够」就该落):文件写清「恢复后主编排三步 + 各 lane 对称义务」,并通告各 lane;对称义务 = date → 读自己最新 checkpoint → 无条件重架 Monitor + SELFTEST → 落 `<lane>-回执-limit恢复-<HHMM>.md` 并会话直推主编排(上岗状态 / Monitor 代次 / 停摆窗自取 / 在飞子代理逐个按树或交回件 ls 判定 / 未消费件)。
2. **主编排恢复三步**:①先 date、读自己 checkpoint、按停摆起点前 30 分钟 mtime 窗扫信箱;②无条件重架 Monitor + SELFTEST(旧代 TaskStop + 残留进程清扫),`list_sessions` 重取会话 id;③给每条 lane 落探活件并会话直推,30 分钟无回执按备援(独立复核代理只读其最后交回件出判定,不代写产出)。**恢复后不先干活,先重架和探活,再处理排队的 TICK。**
3. **在飞工作只按树态续接,零重做**:cherry-pick 冲突态 → 续解;工作区有未提交改动 → 续做;已 commit 但交回件没写 → 只补交回件;零产物 → 原令重派。禁 stash、禁 amend、禁重派已完成的活。
4. **周期兜底用 Monitor 自发 TICK**(循环每 N 轮 echo 一行「TICK」),不用平台定时唤醒——后者在会话空闲期实证多次零触发。
5. **如实记账**:停摆窗起止只许标「推算」(最后落盘时刻 → 恢复提示时刻),台账写「期间未观测」,禁写「全程正常」;生产读数恢复后自取一次(健康 / 构建物身份 / 服务重启计数)。
6. **对端活性判据不变**:只认会话级副作用(进度/回执/交回件 mtime);`list_sessions` 的 lastActivity/isRunning 可作辅证(isRunning=true 且无落盘 = 在跑长 turn,等代理;不是死)。
