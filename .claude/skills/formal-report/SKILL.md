# /formal-report — 正式进度报告

读者是 owner,不是下游 agent。**全文按 /human-explain 写**(结论先行、业务语言、禁 AI 腔与黑话——禁词表以那边为准,这里不重抄)。

## 1 · 骨架:进度汇报固定四问(表格第一列固定用这四个标签)
| 类型和状态 | 内容 |
|---|---|
| 做了什么 | 每条挂证据(文件/commit/verdict/读数),没证据的不写「完成」 |
| 目标是什么 | 当前目标态一句话+离终门还差哪几站 |
| 在等什么 | 等谁的什么信号;信号到了触发什么。只写「等」不写信号=不合格 |
| 卡在哪 | 卡点/为什么没卡;有停摆先写停摆时长与根因 |
表格纪律:单元格短摘要;路径/命令/哈希/日志不进单元格;证据放表后「依据与验证」节;禁命令块;禁 HTML/隐字符排版技巧。

## 2 · 数字纪律
- **数字只许实测值**,每个数字标来源(测试脚本原文/库读数/文件 mtime/接口响应);推算值必须标「推算」并写推算式。
- 凡出现「全绿/完成/达成/验收」字样,必须并排**决策完成度四态**:已合流可见 X / 在飞 Y / 已裁未派工 Z / 候 owner W。缺表禁用这些词(回归门≠完成门)。
- 「已排除/无残留/非缺陷」类全称否定:先列查过哪些面。
- 引用他人数字回原件逐字对;时刻 date 实取。

## 3 · 必备节
- **依据与验证**(表后):证据指针一行一条。
- **未做与降级**:诚实清单,空也写「无」。
- **下一步建议**(结尾):当前处境一句话+下一动作;需要人做什么就点名具体路径/事实/批准;不需要人动就明说并点名下一个 agent 动作。「只说等」不合格——等待必须写明等的信号与信号到了做什么。
- 末尾两行:`Response ID`、`Response log path`(无落盘文件写 `chat reply`)。

## 4 · 语言
用用户偏好语言;中文报告标题/表格/证据/下一步全中文,英文只留稳定技术名与精确文件名,不写整段英文。
