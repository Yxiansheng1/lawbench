# Human Explain / 说人话

## Purpose
把当前对话里的技术状态、工程术语、架构概念翻译成人能直接听懂的自然语言。本 skill 只管**怎么说**;汇报该包含什么、什么算证据,归 /formal-report。触发:`/human-explain` 或 `/说人话`。

## Rules
1. 自然中文短句,像同事面对面聊天。
2. 结论先行:先说「所以怎样」,再补细节。
3. 提到任何 ID、术语、文件名,先用一句话说它对产品/交付的意义,再给 ID;数字后面跟一句它对用户 / 业务 / 交付意味着什么。
4. 状态不明确就说清哪里不明确,不编。
5. 保留必要英文术语(PR、CI、merge、文件名、状态值),其余全中文。
6. **业务语言铁律(owner 2026-09-06 打回后加)**:给 owner 的说明里**一个代号都不许出现**——工单号 / 任务编号、迁移号、commit 哈希、门次或阶段符号(①②之类)、内部代称(版本代号、基线代号、补丁代号)、分支或工作树名、角色或会话代号,一律翻成「它是什么、对用户 / 业务 / 交付意味着什么」的一句话:说「记录每个账号今天能看什么能做什么的那张基线表」不说基线代号,说「负责某某重构那条线」不说会话代号,说「过了第一道验收关(自测加独立复核)」不说门次符号。**必须给路径或编号时**(owner 要点开看、要转发),放在段末括号或末尾「关键路径」一节,正文里不带。落笔前自检:通读一遍,凡是一个不在项目里的人读不懂的词,当场替换;替换不了就删。实锤(2026-09-06):一整份汇报全是编号、哈希、阶段符号,owner 原话「说了等于白说,根本就不知道你做了什么」。

## Forbidden patterns
- 「不是 X,而是 Y」「这不仅是 X,更是 Y」
- 「本质上」「从某种意义上说」「这意味着」
- 「鲁棒」「闭环」「抓手」「赋能」「沉淀」「打通」「对齐」「落地」「链路」
- 「让我们来看看」「接下来我将」「首先需要指出的是」
- 不用比喻、类比、修辞替代直接说明

## Output shape
1-2 句结论 → 具体在干什么(每条一句)→ 为什么重要 → 下一步/需要谁做什么决定。不需要 header、分隔线、表格,除非内容确实需要对比。

## Boundaries
解释模式:不写文件、不起 agent、不改状态。解释完再执行用户要的操作。信息不够就说「我需要看 X 才能确认」,不猜。
