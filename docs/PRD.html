律所本地 AI 平台 — PRD（第三版）

技术实现和接口契约见 Spec.html

依据：甲方《涉密业务本地AI工作台-实施方案-精简版》、《本地 AI 平台建设提纲（修订版）》、沟通记录、《服务器现状报告》、Spec（第一版）的源码核对结论、《五个业务能力编排》。 本文只写做什么、做到什么程度；技术实现和接口契约放在 Spec。需求编号供 Spec、开发工单和测试引用。

相对第二版的主要变化：

  • 客户端改用 DSH 官方桌面端（源码核对确认官方已有桌面端），我方功能以 DSH 插件接入，不用 MCP。
  • 本次只交付 Windows 客户端，macOS 预留。
  • 395 是一台 Windows 11 电脑：不用内存盘，改为全程在内存中处理、不产生临时文件。
  • PDF 拆页渲染、Word 修订版生成都改在律师本机完成，395 只接收律师选定的页面图片和待抽取文本。
  • 原件不复制：案件文件夹中律师自己的文件就是原件，"导入"是扫描和解析。
  • 五个入口下的 Skill 按《五个业务能力编排》更新。
  • 预算区分 Agent 任务和流水线任务；识别在各种情况下的行为写明。

1. 背景与目标

律师处理的案卷敏感，不能用公网 AI。律所有两台服务器：6000D（双 RTX 6000D，Qwen3.8-27B）算力贵，只做推理；AI Max+ 395（Windows 11）做预处理，主要是把扫描页、图片识别成 md。律师在自己电脑上的工作台里办案，案卷留在本机。

平台构成：

  • 底座：6000D 推理 + 395 预处理，两个节点分工。
  • 能力：Skill 体系（基础能力 / 业务 Skill / 业务入口）。
  • 入口：律师工作台（内网，本次交付）；客户门户（外网，本次不交付）。

目标：律师能在本机完成"导入案卷 → 选业务入口 → 整理 / 审查 / 起草 → 核对出处 → 导出成果"，先在内部团队试用，再推广全所，现场验收通过。

2. 用户与场景

角色 规模 做什么 用什么
律师 约 60 人，同时在线约 20 人；先内部团队试用 办案 桌面工作台、小工具
管理员 1–2 人 发放 / 停用 Key，看用量和任务 网关 /admin 看板、395 /admin 页面
责任律师 每个 Skill 一名 审定 Skill 内容，维护测试集，评判质量 工作台 + 测试集

典型场景

A. 刑事阅卷：律师拿到几百页扫描卷宗，把 PDF 放进案件文件夹，点"导入"。文字部分在本机解析；需要识别的页面由律师确认后提交 395，律师可以先去做别的，识别完成后收到通知。律师点"生成案件 wiki"得到案件概览，再进入"刑事阅卷"，生成刑事阅卷笔录、证据审查意见，每一步的结果都可以修改，每条都能点回原文。

B. 刑事文书：在同一案件中进入"刑事文书"，选用阅卷笔录和证据审查意见，按律师确定的辩护方向起草辩护词，或写质证意见、各类申请书。出稿前做一次审查，按问题清单改稿。涉及法条处标"法律依据待律师核实"，律师修改确认后导出 Word。

C. 合同审查：律师把对方发来的合同 Word 放进案件文件夹并导入，进入"合同审查"。AI 先问：代表哪一方、审查目的、重点关注什么。然后输出审查意见，并在本机生成带修订痕迹的 Word，律师在 Word / WPS 里逐条接受或拒绝修改。

D. 合同起草：进入"合同起草"，AI 按必问问题收集交易类型、双方、标的、价款、特殊约定，列出待补事实，起草合同初稿；可以再用"合同审查"审一遍自己的初稿。

E. 通用文书：进入"通用文书"，选择律师函、法律意见书、案件分析报告、工作函等类型，基于案件材料起草。

F. 长截图：当事人发来几十屏的聊天长截图，律师用"长截图切分"小工具切成短图，再放入案件或打印作证据附件。

3. 保密要求（不满足即验收不通过）

编号 要求
SEC-01 原件、识别和转换文本、wiki、索引、对话记录、草稿、成果都存在律师本机的案件文件夹内。
SEC-02 发往服务器的数据只限第 4.5 节路由表列出的内容，每种都由律师的某个操作授权（提交前显示发送范围）。AI 不能自行发起外发，不在后台自动上传。
SEC-03 客户端只连律所的两台服务器：无云登录、自动更新、错误上报、统计、反馈上传，运行时不下载组件，依赖全部打进安装包。
SEC-04 案卷不做切块向量检索，服务器端不建案卷索引。（预留的知识库只用于法规、类案等公共资料，不收录案卷。）
SEC-05 案件隔离：AI 只能读写当前案件文件夹，且只能通过我方的案件工具；不能执行任意命令、不能联网；要防住 ../、符号链接、junction。
SEC-06 每位律师用自己的 Key。Key 只管服务调用，不管本地文件访问；前提是律师用个人电脑、个人系统账号。
SEC-07 案卷里的文字不能扩大 AI 权限；打开案件时不加载案件文件夹里的配置、指令文件、Skill 和插件。
SEC-08 原件只读，AI 只能写工作区和成果目录（成果目录须经律师确认）。
SEC-09 6000D 不保存请求和回答正文；网关审计日志只记元数据（用户、时间、token 数、耗时、状态）。
SEC-10 不回退到任何公网模型或公网 OCR。
SEC-11 含正文的临时文件、缓存、工具输出只能写在案件工作区；案件目录外的日志不含正文。系统交换文件、休眠文件由律所终端安全负责。
SEC-12 395 处理即返回、不留存：395 的全部任务（识别、去水印、9B 抽取）在同一个请求内处理并返回结果；全程在内存中处理，不产生临时文件，不写硬盘；不设共享目录；395 的日志只记元数据（用户、时间、页数、耗时、状态）。395 系统盘开启 BitLocker、关闭休眠；Windows 页面文件的残余风险已告知甲方。
SEC-13 两台服务器只能通过律所局域网或 WireGuard 访问，不暴露公网；模型接口和律师工作台一律不出内网。
SEC-14 案件文件夹不得位于云同步目录（OneDrive、坚果云、百度网盘同步盘等）：打开案件时检测到常见同步目录即拒绝，并提示移到本机普通文件夹。

如实告知律师：推理和 395 处理时，内容会发到律所服务器，服务器处理期间能接触到内容；处理结束后 6000D 和 395 都不保存正文。

4.3 395（预处理节点）

能力 说明 档位

4.4 两节点衔接

编号 需求
F-NODE-01 处理即返回：客户端每次发给 395 的请求，都在同一个请求内返回结果；395 不保存任务文件和结果，不设共享目录（SEC-12）。
F-NODE-02 短任务（9B 抽取）：直接发送、直接返回，界面显示处理中。
F-NODE-03 OCR 长任务：客户端在本机把 PDF 拆页并渲染为图片，逐页发给 395，每页识别后立即返回并写入案件文件夹；律师提交后可以继续做别的事；界面显示进度，全部完成后通知（通知不含案件名和材料名）。
F-NODE-04 任务状态在客户端：待处理页、已完成页、所属案件都记录在该案件的工作区；切换案件、关闭或重启客户端后，从中断的那一页继续，不需要重新提交。
F-NODE-05 识别只在律师电脑开着软件时进行。关闭窗口（软件留在托盘）或切换案件：继续；从托盘完全退出、关机、合盖睡眠、断网：暂停，正在发送的那一页作废；重新打开软件或恢复网络：自动从第一个未完成的页继续。界面在提交时提示此要求。
F-NODE-06 任务可以随时取消；已返回的页保留，未发送的页不再发送。
F-NODE-07 降级：395 不可用时，客户端暂停发送，显示"等待 395 恢复"，恢复后自动继续；推理不受影响。可选由 6000D 临时接管识别（占用推理算力，由管理员开启，默认关闭）。
F-NODE-08 6000D 不读取 395 的任何数据；客户端把需要的 md 文本放进推理请求。

与提纲的差异及原因：提纲设计为"OCR 结果和阅卷笔录存到共享目录，6000D 读取 md 文本"。本方案改为 395 处理即返回、不设共享目录，原因是：保密的前提要求案卷只留在律师本机，只在处理时经过服务器。共享目录会让案卷内容在服务器上留存，需要额外的访问隔离、清理和审计机制，也扩大了泄露面。改为逐页处理、立即返回后，服务器上没有任何案卷留存；"提交后后台处理、完成后通知"的体验由客户端实现，律师不用在界面上干等。代价是 OCR 期间律师电脑需保持开机联网（F-NODE-05）。

提纲中"Word 修订输出放在 395"改为本机生成：修订版生成是纯程序处理，不需要模型；放在本机，合同不必发往服务器，也少一个依赖 395 的环节。

4.5 工作台与 Harness

  • 客户端采用 DSH（DeepSeek Harness）官方桌面端定制（官方仓库 apps/desktop），锁定一个提交，不跟随上游升级。
  • Harness 负责：Agent 循环和工具调度；权限闸门（只有"律师工作台"一种配置，AI 只能用我方案件工具，不能执行命令）；只从受信任位置加载 Skill；按"wiki → 全文检索 → 回读原文"组织上下文；会话存案件文件夹；参数和预算；取消。
  • 我方功能以 DSH 插件形式接入（不用 MCP），业务逻辑在本机常驻的工作台服务中。
  • 路由原则（推理与预处理分离）：识别、去水印、字段抽取走 395；分析、审查、起草、wiki 生成走 6000D；格式转换、拆页渲染、修订版生成和其余操作在本机完成。

5. 先验证再定版

以下各项测通后再冻结组件和工期。每项测试前先定好样本和通过标准。

# 验证项 通过标准
G-1 DSH 官方桌面端 去掉全部对外连接（更新、遥测、账号、插件市场）后能正常运行；能接律所网关、中文界面、换品牌
G-2 案件隔离 读不到案件外文件（含 ../、链接、junction）；AI 请求的工具列表里只有我方案件工具；案件内配置、指令文件、Skill 不被加载
G-3 工具接入 我方插件注册的案件工具能被 DSH 调用，并经本机工作台服务完成读写
G-4 数据落点 找出客户端运行时写入的所有位置，能指向案件目录或确认不含正文
G-5 395 OCR 在 395（Windows 11，AMD 核显）上跑通候选 OCR 模型，测速度（页 / 分钟）和准确率（数字、姓名、日期）
G-6 395 小模型 9B 模型在 395 上的速度和字段抽取准确率
G-7 模型能力 27B 工具调用稳定；思考档位是否有差异；长输入质量
G-8 原文引用 PDF 到页、Word 到段落、Excel 到单元格
G-9 中文检索 两字姓名、简称、日期、金额、案号都能搜到
G-10 Word 修订输出 生成的修订版 docx 在 Word 和 WPS 中都能正常显示修订、逐条接受或拒绝
G-11 离线安装 断网能装能用，抓包只见律所服务器
