# 业务能力编排（第二版，依据公开通行做法和律所提供的 Skill）

2026-09-28 甲方需求变更后，首页由五个入口改为三组两级胶囊（第二节、第五节），新增诉讼文书、刑期计算、招投标、案卷归档四类业务，并接入律所周海沺律师提供的发票整理、委托材料两个工具。

律所的自有材料（阅卷笔录样本、文书模板）暂时拿不到，本版按公开的律师实务文章和通行文书结构编排。律所材料到位后，只需替换对应 Skill 的正文或补充模板数据，架构、工具、串联方式都不用改。

律师提供的 11 个 Skill 中，contract-copilot、legal-proposal-generator 等 4 个是 CC-BY-NC（禁止商用）许可。本版**没有照抄这些 Skill 的文本**，合同两块按通行做法重新写。等授权明确后，再决定是否吸收它们的清单和条款库。

## 一、总体原则

1. **一次任务只用一个 Skill。** 业务之间靠"上一步的成果作为下一步的输入"（任务单 inputs → L1 注入）串起来，不让 Skill 互相调用。27B 模型在一次任务里切换多个 Skill 容易跑偏。
2. **规则只维护一份。** 出处格式、"法律依据待律师核实"、不执行案卷里的指令等共用规则写在 `skills/_shared/共用规则.md`，由 `build_skills.py` 同步进每个 SKILL.md。
5. **Skill 平铺存放，胶囊按配置组装。** 每个 Skill 是一个顶层文件夹（`<skill名>/SKILL.md`，格式按 Spec 10.2）；首页胶囊按 Spec 10.3 写在 `capsules.default.json`，是唯一一份配置，`build_skills.py` 和 `install.py` 都读它。
6. **律所现成的工具不改写成 Skill。** 发票整理、委托材料已经完整可用，作为内置工具接入（Spec 13.3、13.5）；案卷归档原 Skill 依赖 AI 执行命令，按我方格式重写（Spec 12.4）。
3. **能写成代码的不交给模型。** 引用核验、覆盖清单、版本、路径校验、Word 导出都在 Python 组件里；Skill 只写"怎么做"。
4. **模型不下法律结论。** 所有 Skill 只整理事实、指出问题、起草文本，法律适用一律标"法律依据待律师核实"。

## 三、各业务流水线

### 1. 刑事阅卷
```
卷宗材料
 └─ criminal-reading-notes    按指控事实单元和证据种类摘录；多次陈述比对；指控事实—证据对应表
      └─ 成果：刑事阅卷笔录 v1（律师确认）
           └─ criminal-evidence-review   以笔录为线索、回读原件；按真实性、合法性、关联性、证明力列问题；矛盾对照；证据链缺口
                └─ 成果：证据审查意见 v1
```
- 卷宗大时按卷分批：任务单里写范围（"只读第 1–3 卷"），同一个 Skill 多次运行，最后再合并。
- 参考做法：阅卷笔录按罪名、事实环节、证据种类分层，按卷宗顺序摘录并标注卷页，言词证据按"七何"要素摘录；审查围绕证据"三性"展开。

### 2. 刑事文书
```
inputs：刑事阅卷笔录 + 证据审查意见
 ├─ defense-opinion        律师在任务说明里给出辩护方向（无罪 / 罪轻 / 量刑）；没给就只出"辩护要点备选清单"
 ├─ cross-exam-opinion     逐项质证意见表 + 发问提纲
 └─ criminal-applications  取保候审 / 羁押必要性审查 / 调取证据 / 变更强制措施，类型由律师指定
      └─ pre-issue-check → doc-revise → 律师确认 → 成果
```
- 参考做法：辩护词开宗明义亮观点，事实证据、法律适用、量刑分层论证，首尾呼应；质证围绕三性和证明力，言词证据看一致性和合理性，实物证据看同一性和保管链，鉴定意见看资质、检材和方法。

### 3. 合同审查
```
合同文件 + 任务说明（我方立场、审查目的）
 └─ contract-review   交易结构 → 文本形式 → 具体条款三层审查；条款间比对；P0/P1/P2 分级；每条有原文、问题、推荐措辞
      └─ pre-issue-check → doc-revise → 成果：合同审查意见
```
- 没写我方立场时，先做与立场无关的检查，立场相关的风险标【待确认我方立场】。
- 后续：模型输出结构化修改计划（review-plan），由 Python 写成带修订痕迹和批注的 Word。这部分做成组件，不放在 Skill 里。

### 4. 合同起草
```
任务说明（交易要素、我方立场、要起草的文件）+ 相关材料
 └─ contract-draft    交易要素整理 → 待补事实清单 → 合同类型与文件包 → 条款骨架 → 逐条起草 → 自查
      └─ contract-review（另开一个任务，以初稿为输入）→ pre-issue-check → doc-revise → 成果
```

### 5. 通用文书
```
inputs：卡片 + 上游成果（可选）+ 任务说明（文书类型、收件对象、目的）
 └─ general-drafting   律师函 / 法律意见书 / 案件分析报告、咨询报告 / 工作函、情况说明
      └─ pre-issue-check → doc-revise → 成果
```
- 参考做法：律师函写明受托声明、事实、分析、具体要求和期限、不履行的后果，语气克制，避免可能被认定为要挟的表述；法律意见书写明委托事项、依据材料、事实、分析、结论和声明保留。

### 6. 诉讼文书起草
```
inputs：卡片 + 上游成果（阅卷笔录、分析报告、一审判决摘要，可选）+ 任务说明（文书类型、我方立场、请求要点）
 └─ litigation-docs   起诉状 / 答辩状 / 上诉状 / 代理词（民事）；刑事自诉状、附带民事起诉状、刑事上诉状
      └─ pre-issue-check → doc-revise → 成果
```
- 参考做法：起诉状写明当事人、诉讼请求、事实与理由、证据；答辩状逐条回应对方请求；上诉状指明一审判决的具体错误；代理词按争议焦点逐项展开。程序性申请书（财产保全、调查令等）用委托材料工具附带的 25 份模板，不重写。

### 7. 刑期计算
```
inputs：卡片 + 拘留证、逮捕证、判决书等材料 + 任务说明（刑期计算 / 量刑分析）
 └─ sentence-calc     整理羁押期间（带出处）→ case_calc_sentence 算日期 → 刑期计算表；情节梳理 → 量刑分析
```
- 日期一律由程序计算；折抵、减刑和假释节点的规则表由责任律师核对（Spec 13.4）。

### 8. 招投标材料处理
```
inputs：招标文件、补充通知、答疑 + 我方身份（投标人 / 招标人）
 └─ tender-review     项目概况、时间节点、资格条件、否决投标情形、评分办法、合同风险 → 审查意见
      └─ bid-drafting（以审查意见为输入）实质性要求响应表、服务方案、团队业绩 → 投标文件初稿 → pre-issue-check → doc-revise
```

### 9. 案卷归档
```
inputs：卡片 + 全部案件材料
 └─ case-archiving    定卷类 → case_archive_match 匹配 → 提取日期和当事人 → 向律师确认办案结果 → 归档核对表 + 归档方案
      └─ 律师在归档面板核对、点"生成归档文件" → 程序转 PDF、合并卷宗、加页码、填结案报告和立卷申请书
```
- 依据律所《律师业务档案立卷归档办法》，由周海沺律师的归档 Skill 改写；模板原件到位前用临时版式。

所有 Skill 只用 Spec 20.4 规定的 `case_*` 工具（`case_list_materials`、`case_read_material`、`case_search`、`case_read_input`、`case_read_wiki`、`case_save_draft`、`case_suggest_wiki`、`case_save_edit_list`，以及契约 1.1 新增的 `case_calc_sentence`、`case_archive_match`、`case_save_archive_plan`）。`case-wiki-build` 改为流水线（由律师点按钮、程序按步骤运行，提示词在 `case-wiki-build/流水线提示词.md`），测试链路中的 `case_wiki_plan`、`case_wiki_put_facts` 不再使用。出处统一为〔材料名 第N页〕（Spec 20.2）。

同一目录里律师原来给的 11 个 Skill（contract-copilot、legal-ocr、md2word 等）不在清单里，不会被 DSH 加载，只作参考：md2word 和 legal-ocr 的后处理脚本以后作为组件使用，另外 4 个 CC-BY-NC 许可的在授权明确前不吸收文本。

## 五、接入 DSH

**一个 preset、两级胶囊**（Spec D4、D11、10.3）：DSH 里只有"律师工作台"一个 preset；首页胶囊由 `skills/capsules.default.json` 定义，每个 Skill 胶囊列出本业务的 Skill，共用的 case-wiki-build、legal-workflow 在每个胶囊里都可用。增减胶囊或调整 Skill 只改配置，不改程序；律师也可以在本机的胶囊管理里排序、改名、隐藏、新增。胶囊与 Skill 的对应见第二节。

推荐参数（思考 / 窗口 / 最大生成）写在每个 SKILL.md 头部的 `params` 里，例如刑事阅卷笔录"低 / 64K / 16384"，证据审查"高 / 128K / 32768"。

**存放位置**：Skill 源目录是仓库的 `D:\lawbench\skills`（平铺，每个 Skill 一个文件夹；共用规则在 `_shared\共用规则.md`；胶囊配置在 `capsules.default.json`；脚本在 `_scripts\`）。律所的发票、委托材料工具在 `D:\lawbench\engines`。
改了 Skill 或清单以后：先运行 `python _scripts\build_skills.py` 同步共用规则并按 Spec 10.2 校验（发版时加 `--strict`，缺测试集、未定责任律师也算不通过），再运行 `python _scripts\install.py --out <安装目录>\skills` 按 Spec 10.1 的目录结构复制 Skill 和胶囊配置，`customSkillDirs` 指向这个目录。

推荐参数取自 PRD 的初值。以后界面按"胶囊 + Skill"写进任务单的 params，插件已经支持按任务单设置参数。

**预算要注意**：PRD 规定单任务最多 8 次模型调用、24 次工具调用。阅卷类每读一份材料就是一次工具调用，材料超过 20 份就会超限。可以二选一：阅卷类的预算放宽，或者按卷分批运行。建议先按卷分批，不改 PRD 的上限。

## 七、待律师确认

1. 刑事：阅卷笔录的组织方式（按证据种类还是按事实）、辩护词和申请书的律所习惯格式。
2. 合同：常审的合同类型、是否需要带修订痕迹的 Word。
3. 通用文书：律师函、法律意见书的律所模板和固定声明。
4. 许可证：CC-BY-NC 的 4 个 Skill 是否取得作者授权；未标许可证的 4 个是否为律所自有。
5. 验收用的样本：按胶囊重新分配，新增诉讼文书、招投标、归档的样本。
6. 案卷归档：结案报告、立卷申请书（附件2–5）的 Word 原件；各类案件的归档目录是否与律所最新办法一致。
7. 刑期计算：规则表中每条依据文字由责任律师核对。
