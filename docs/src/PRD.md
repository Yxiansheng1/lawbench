## 1. 背景与目标

律师处理的案卷敏感，不能用公网 AI。律所有两台服务器：6000D（双 RTX 6000D，Qwen3.8-27B）算力贵，只做推理；AI Max+ 395（Windows 11）做预处理，主要是把扫描页、图片识别成 md。律师在自己电脑上的工作台里办案，案卷留在本机。

平台构成：

- **底座**：6000D 推理 + 395 预处理，两个节点分工。
- **能力**：Skill 体系（基础能力 / 业务 Skill / 胶囊）。
- **入口**：律师工作台（律所内网；所外经甲方部署的 EasyTier 访问；本次交付）；客户门户（外网，本次不交付）。

目标：律师能在本机完成"导入案卷 → 点胶囊 → 整理 / 审查 / 起草 → 核对出处 → 导出成果"，以及发票整理、委托材料、结案归档等日常办公事务，先在内部团队试用，再推广全所，现场验收通过。

本文档覆盖整个平台，不分期，按下面三档交付：

## 2. 用户与场景

| 角色 | 规模 | 做什么 | 用什么 |
|---|---|---|---|
| 律师 | 约 60 人，同时在线约 20 人；先内部团队试用 | 办案、日常办公 | 桌面工作台（含发票整理、委托材料）、小工具 |
| 管理员 | 1–2 人 | 发放 / 停用 Key，看用量和任务 | 网关 `/admin` 看板、395 `/admin` 页面 |
| 责任律师 | 每个 Skill 一名 | 审定 Skill 内容，维护测试集，评判质量 | 工作台 + 测试集 |

### 典型场景

**A. 刑事案卷分析**：律师拿到几百页扫描卷宗，把 PDF 拖进案件，自动复制到案件文件夹并解析。文字部分在本机解析；需要识别的页面由律师确认后提交 395，律师可以先去做别的，识别完成后收到通知。律师点"生成案件 wiki"得到案件概览，再点"刑事案件 → 案卷分析"，生成刑事阅卷笔录、证据审查意见，每一步的结果都可以修改，每条都能点回原文。

**B. 刑事文书**：在同一案件中点"辩护词起草"，选用阅卷笔录和证据审查意见，按律师确定的辩护方向起草辩护词；"质证意见起草""取保候审/不予逮捕申请"同样用法；"刑期计算"按羁押期间算出刑期起止和二分之一节点。出稿前做一次审查，按问题清单改稿。涉及法条处标"法律依据待律师核实"，律师修改确认后导出 Word。

**C. 合同审查**：律师把对方发来的合同 Word 拖进案件，点"民事与商事 → 合同审查"。AI 先问：代表哪一方、审查目的、重点关注什么。然后输出审查意见，并在本机生成**带修订痕迹的 Word**，律师在 Word / WPS 里逐条接受或拒绝修改。

**D. 合同起草、诉讼文书**：点"合同起草"，AI 按必问问题收集交易类型、双方、标的、价款、特殊约定，列出待补事实，起草合同初稿；可以再用"合同审查"审一遍自己的初稿。"诉讼文书起草"按我方立场起草起诉状、答辩状、上诉状、代理词。

**E. 日常办公文书**：点"日常办公 → 律师函起草"或"通用文书"（法律意见书、案件分析报告、民事阅卷笔录）；"招投标材料处理"先审查招标文件，再起草投标文件。

**F. 长截图**：当事人发来几十屏的聊天长截图，律师用"长截图切分"小工具切成短图，再放入案件或打印作证据附件。

**G. 新委托**：签约前点"日常办公 → 文件生成"，打开委托材料工具，填写或导入案件信息、识别证件，生成委托合同、授权委托书、所函，保存到新案件的"01委托手续"。

**H. 结案归档**：结案后点"案卷归档"，AI 按律所归档目录逐项匹配材料、提取委托日期和结案日期、向律师确认办案结果，律师核对后点"生成归档文件"，得到卷宗.pdf（带页码）、发票.pdf、立卷申请书，打印手签后上传金助理。

**I. 发票报销**：月底点"发票整理"，选报销年月、导入从邮箱下载的发票文件夹，程序查重、入账、生成贴票包，报销后点"确认已报销"。

## 3. 保密要求（不满足即验收不通过）

| 编号 | 要求 |
|---|---|
| SEC-01 | 原件、识别和转换文本、wiki、索引、对话记录、草稿、成果都存在律师本机的案件文件夹内。拖入或粘贴的文件一律复制进案件文件夹，不存在软件自己的目录里。（发票不是案卷，存在律师指定的日常办公文件夹。） |
| SEC-02 | 发往服务器的数据只限第 4.5 节路由表列出的内容，每种都由律师的某个操作授权（提交前显示发送范围）。AI 不能自行发起外发，不在后台自动上传。 |
| SEC-03 | 客户端只连律所的两台服务器：无云登录、自动更新、错误上报、统计、反馈上传，运行时不下载组件，依赖全部打进安装包。 |
| SEC-04 | 案卷不做切块向量检索，服务器端不建案卷索引。（预留的知识库只用于法规、类案等公共资料，不收录案卷。） |
| SEC-05 | 案件隔离：AI 只能读写当前案件文件夹，且只能通过我方的案件工具；不能执行任意命令、不能联网；要防住 `../`、符号链接、junction。 |
| SEC-06 | 每位律师用自己的 Key。Key 只管服务调用，不管本地文件访问；前提是律师用个人电脑、个人系统账号。 |
| SEC-07 | 案卷里的文字不能扩大 AI 权限；打开案件时不加载案件文件夹里的配置、指令文件、Skill 和插件。 |
| SEC-08 | 原件只读：已在案件文件夹里的文件任何时候都不改动、不删除；向案件文件夹新增文件只能由律师的导入操作完成（只新增、不覆盖）。AI 只能写工作区和成果目录（成果目录须经律师确认）。 |
| SEC-09 | 6000D 不保存请求和回答正文；网关审计日志只记元数据（用户、时间、token 数、耗时、状态）。 |
| SEC-10 | 不回退到任何公网模型或公网 OCR。 |
| SEC-11 | 含正文的临时文件、缓存、工具输出只能写在案件工作区；案件目录外的日志不含正文。系统交换文件、休眠文件由律所终端安全负责。 |
| SEC-12 | **395 处理即返回、不留存**：395 的全部任务（识别、去水印、9B 抽取）在同一个请求内处理并返回结果；全程在内存中处理，不产生临时文件，不写硬盘；不设共享目录；395 的日志只记元数据（用户、时间、页数、耗时、状态）。395 系统盘开启 BitLocker、关闭休眠；Windows 页面文件的残余风险已告知甲方。 |
| SEC-13 | 两台服务器只能通过律所局域网或甲方部署的 EasyTier 虚拟网访问，不暴露公网；模型接口和律师工作台一律不出内网。 |
| SEC-14 | 案件文件夹不得位于云同步目录（OneDrive、坚果云、百度网盘同步盘等）：打开案件时检测到常见同步目录即拒绝，并提示移到本机普通文件夹。 |

如实告知律师：推理和 395 处理时，内容会发到律所服务器，服务器处理期间能接触到内容；处理结束后 6000D 和 395 都不保存正文。

## 4. 系统架构

### 4.1 三层两节点

| 层 | 组成 | 位置 |
|---|---|---|
| 入口 | 律师工作台：DSH 官方桌面端（中文、双品牌、去掉云功能）；客户门户（本次不交付） | 律师电脑 |
| 能力 | Skill 体系；我方插件和本机工作台服务（材料解析、检索、流水线、识别队列、导出、修订版生成） | 律师电脑 |
| 底座 | 6000D：推理 + 网关；395：OCR、去水印、9B 小模型 | 律所服务器 |

```
律师工作台（DSH 桌面端 + 我方插件 + 本机工作台服务）
   │  权限闸门：AI 只能用案件工具，仅限当前案件文件夹
   │  本机完成：解析、格式转换、PDF 拆页渲染、检索、导出、修订版 Word
   │              │
   │推理           │逐页 / 逐段发送，同一请求内返回（不落盘）
   ▼              ▼
6000D 网关       395 预处理服务（Windows 11）
   │              ├ OCR（页面图片 → md）
两路 27B         ├ 去水印（工作副本）
（一卡一实例）    └ 9B 小模型（字段抽取、分类）
```

### 4.2 6000D（推理节点）

- 只跑两路 27B 主模型，一卡一实例，显存全部留给权重和 KV cache。
- 前面是统一网关，所有调用记审计日志（只记元数据，SEC-09）。
- 按真实场景压测并发：长卷宗与短对话混合。

### 4.3 395（预处理节点）

| 能力 | 说明 | 档位 |
|---|---|---|
| OCR | 页面图片转 md，保留页码；OCR 接口做成可插拔，换模型不改调用方 | 完整 |
| 去水印 | **只在本次请求的图片副本上做**：原件不变，引用仍指向原件页码；印章、签名、手写批注不属于水印，不得去除；效果不稳定时默认关闭，由律师按需勾选 | 限定范围 |
| 9B 小模型 | 材料分类、约定字段抽取（当事人、日期、金额、案号）等机械性任务（范围见 4.7） | 限定范围 |
| Embedding / Reranker | 服务将来的知识库和类案检索 | 预留 |

395 内存带宽约 256GB/s，只承担以上批处理和小模型任务，不承担交互式大模型对话。395 以 Windows 服务方式运行，开机自启、崩溃自动重启。

### 4.4 两节点衔接

| 编号 | 需求 |
|---|---|
| F-NODE-01 | **处理即返回**：客户端每次发给 395 的请求，都在同一个请求内返回结果；395 不保存任务文件和结果，不设共享目录（SEC-12）。 |
| F-NODE-02 | **短任务**（9B 抽取）：直接发送、直接返回，界面显示处理中。 |
| F-NODE-03 | **OCR 长任务**：客户端在本机把 PDF 拆页并渲染为图片，逐页发给 395，每页识别后立即返回并写入案件文件夹；律师提交后可以继续做别的事；界面显示进度，全部完成后通知（通知不含案件名和材料名）。 |
| F-NODE-04 | **任务状态在客户端**：待处理页、已完成页、所属案件都记录在该案件的工作区；切换案件、关闭或重启客户端后，从中断的那一页继续，不需要重新提交。 |
| F-NODE-05 | 识别只在律师电脑开着软件时进行。关闭窗口（软件留在托盘）或切换案件：继续；从托盘完全退出、关机、合盖睡眠、断网：暂停，正在发送的那一页作废；重新打开软件或恢复网络：自动从第一个未完成的页继续。界面在提交时提示此要求。 |
| F-NODE-06 | 任务可以随时取消；已返回的页保留，未发送的页不再发送。 |
| F-NODE-07 | **降级**：395 不可用时，客户端暂停发送，显示"等待 395 恢复"，恢复后自动继续；推理不受影响。可选由 6000D 临时接管识别（占用推理算力，由管理员开启，默认关闭）。 |
| F-NODE-08 | 6000D 不读取 395 的任何数据；客户端把需要的 md 文本放进推理请求。 |

**与提纲的差异及原因**：提纲设计为"OCR 结果和阅卷笔录存到共享目录，6000D 读取 md 文本"。本方案改为 395 处理即返回、不设共享目录，原因是：保密的前提要求案卷只留在律师本机，只在处理时经过服务器。共享目录会让案卷内容在服务器上留存，需要额外的访问隔离、清理和审计机制，也扩大了泄露面。改为逐页处理、立即返回后，服务器上没有任何案卷留存；"提交后后台处理、完成后通知"的体验由客户端实现，律师不用在界面上干等。代价是 OCR 期间律师电脑需保持开机联网（F-NODE-05）。

提纲中"Word 修订输出放在 395"改为本机生成：修订版生成是纯程序处理，不需要模型；放在本机，合同不必发往服务器，也少一个依赖 395 的环节。

### 4.5 工作台与 Harness

- 客户端采用 **DSH（DeepSeek Harness）官方桌面端**定制（官方仓库 `apps/desktop`），锁定一个提交，不跟随上游升级。
- Harness 负责：Agent 循环和工具调度；权限闸门（只有"律师工作台"一种配置，AI 只能用我方案件工具，不能执行命令）；只从受信任位置加载 Skill；按"wiki → 全文检索 → 回读原文"组织上下文；会话存案件文件夹；参数和预算；取消。
- 我方功能以 DSH 插件形式接入（不用 MCP），业务逻辑在本机常驻的工作台服务中。
- 路由原则（**推理与预处理分离**）：识别、去水印、字段抽取走 395；分析、审查、起草、wiki 生成走 6000D；格式转换、拆页渲染、修订版生成和其余操作在本机完成。

**路由表**（每种操作在哪里处理、发送什么、谁授权）：

| 操作 | 处理位置 | 发送的数据 | 律师的授权动作 |
|---|---|---|---|
| 文字材料解析（docx、xlsx、csv、文字版 PDF、md、txt） | 本机 | 不发送 | 点"导入" |
| 老格式转换（doc、wps、xls）及 Word ↔ PDF | 本机（随安装包内置 LibreOffice） | 不发送 | 点"导入" |
| PDF 拆页、页面渲染 | 本机 | 不发送 | 点"提交识别" |
| OCR、去水印 | 395 | 律师选定页面的图片 | 点"提交识别"，提交前显示页数 |
| 9B 字段抽取、分类 | 395 | 律师选定材料的 md 文本 | 在 wiki 生成中勾选"使用 395 抽取"后点运行 |
| 分析、审查、起草、wiki 生成 | 6000D | 当次需要的文本片段 | 发起任务 / 点"生成 wiki" |
| Word 修订版生成 | 本机 | 不发送 | 点"生成修订版" |
| 全文检索、wiki 存储、导出 md / docx | 本机 | 不发送 | — |
| 拖入导入（复制进案件文件夹） | 本机 | 不发送 | 拖入或点"导入"，确认目标文件夹 |
| 归档：Word 转 PDF、合并卷宗、页码、结案报告和立卷申请书 | 本机（优先调用本机 Word / WPS，其次内置 LibreOffice） | 不发送 | 确认办案结果后点"生成归档文件" |
| 刑期计算 | 本机程序 | 不发送 | — |
| 发票整理（归档、识别、查重、台账） | 本机（Windows 自带的文字识别） | 不发送；不连邮箱 | 在发票整理页点对应按钮 |
| 委托材料生成、证件识别 | 本机（识别用本机 CPU） | 不发送 | 在委托材料窗口操作 |

### 4.6 组件和许可证

## 6. Skill 体系

### 6.1 三级结构

| 层级 | 内容 | 律师是否可见 |
|---|---|---|
