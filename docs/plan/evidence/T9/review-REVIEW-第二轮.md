**P3-A · 检索词前后带空格时，所有命中都被标成"扩展匹配"（本次引入的回归）**
- 问题：判断是否完全匹配的 `fts._literal` 改成调 `normalize(s, thousands=False).lower()`，这个函数不去首尾空格。旧写法 `" ".join(...split())` 会去。而查询串本身在 `expand.variants` 里是 `.strip()` 过的，两边对不上。
- 影响：搜 `" 下图为书桌位置"` 或 `"下图为书桌位置 "`，命中照样出来，但 `match` 从 `exact` 变成 `expanded`，排序也跟着靠后。律师复制粘贴、或者模型调工具时带了尾部空格，都会碰到。不会漏命中，也不会给错出处。
- 证据：探针 `test_rv_p34_api`。查 `'下图为书桌位置'` 得到 `('〔a 第2行〕','exact')`；查 `' 下图为书桌位置'` 和 `'下图为书桌位置 '` 都得到 `('〔a 第2行〕','expanded')`。
- 最小修复：`_literal` 末尾加 `.strip()`（写成 `normalize(s, thousands=False).strip().lower()`），再补一条首尾带空格的用例。
- 归类：本次引入的回归，小项，不阻断。
