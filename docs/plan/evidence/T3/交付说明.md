**路径闸门**：
- 根目录用 realpath；根目录本身是链接或 junction，报 `CASE_ROOT_IS_LINK`。
- 云同步目录三路检测，命中报 `CASE_IN_SYNC_FOLDER`：`OneDrive*` 环境变量、注册表 `HKCU\...\OneDrive\Accounts\*\UserFolder`、目录名关键字（不分大小写）。
- AI 传入的路径拒绝以下几类：
  - 绝对路径、盘符、UNC；
  - `..`，包括 Windows 去掉尾部点和空格后等于 `..` 的写法；
  - `:`（备用数据流）、NUL、控制字符；
  - 第一级是 `.xxx`、`工作区`、`成果`，含尾部点和空格的变体；
  - 超长名（单级超过 255）、超长路径（超过 1024）。
- 逐级 lstat，遇到符号链接或 reparse point 就拒绝，指向案件内的也拒绝。
- 最终 realpath 必须以 ROOT 加分隔符开头，Windows 下不分大小写；解析后第一级落在保留目录的，再拒一次。
- 写入只限 `工作区\`、`成果\`。
- 原件区只提供"补建空文件夹"一种写法，已有的一概不动。
- 拒绝时只记操作名和原因代号。

**net.py**：
- 白名单只放行设置里四个地址的"主机+端口"，外加 `127.0.0.1`。
- `follow_redirects=False`，收到 3xx 报错；`trust_env=False`，不读系统代理。
- 地址选择：先试所内，不通试所外。6000D 探 `/v1/models`，395 探 `/health`，各 1.5 秒；结果缓存 60 秒，连接出错时重探一次，两个都不通报 `SERVER_UNREACHABLE`。
- 本机转发只接受 `POST /v1/chat/completions` 和 `GET /v1/models`，其余一律 404，不要令牌。
  - 流式透传，`Authorization`、`X-Session-Id` 原样带上，回传 `X-Queue-Wait-Ms`。
  - 连不上返回 502 + `SERVER_UNREACHABLE`。
  - 日志只记元数据。

### 材料移除（第 7 项）怎么做的

- **步骤**：
  1. 编号有不在本案的：整个请求回 MATERIAL_NOT_FOUND，什么都不做。

## 任务卡在 running 的服务端兜底（执行令 20261011-0408）

- **做了什么**：`GET /api/tasks` 读列表时，对话任务（`kind=agent`）仍是 running、且 `result.json` 最近一次写入（begin、progress、存草稿都会写）距今超过该任务 `budget.minutes`（默认 45 分钟）的，把 `result.json` 的 status 和 `task.json` 的 state 写成 `abnormal`（异常中断），日志 `task.stale`（只记案件编号）。草稿不动。流水线任务在本进程里自己收尾，不在此列。
- **代码**：`service\lawbench\case\task.py` 的 `_close_stale`，在 `list()` 里逐个任务调用。
- **用例**（`service\tests\test_core.py`，3 个）：50 分钟无进度 → 读回 abnormal、已写回文件、草稿还在；30 分钟 → 仍 running，之后 end 正常到达得到 completed；已结束的任务放再久也不动。任务相关三个测试文件 72 例全过。
- **偏离（请主编排定）**：
  1. 执行令原文"返回前把它判为 `aborted`（reason `stale`）……契约不改（status 枚举已有 aborted；若 reason 枚举需加 `stale` 则加进 1.4）"。实际 `files/result.schema.json` 的 status 枚举是 running / completed / cancelled / budget_stopped / output_limit / failed / interrupted / abnormal，**没有 aborted**（aborted 是 `core/task_end` 请求里的 reason，对应 cancelled），result.json 也没有 reason 字段。我用了现成的 `abnormal`（和"上次硬退出留下的任务"同一个状态），契约没动。要区分"超时没报结束"和"硬退出"的话需要加字段，属于改契约。
  2. 执行令原文"`GET /api/task/{id}`（及 `task/current`、列表）"。服务没有 `GET /api/task/{id}`；`/api/task/current` 只返回待执行的选择，不带 status。带 status 的只有 `/api/tasks`，所以只在这一处做。
  3. "最近一次 progress（或 begin）"的时刻契约里没有字段，用的是 result.json 的文件修改时间。
- **遗留**：判为 abnormal 之后客户端迟到的 `task/end` 会得到 TASK_NOT_FOUND（和硬退出后的任务一样）；用量保持最后一次 progress 报的数。
