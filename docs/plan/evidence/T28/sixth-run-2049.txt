真因：build.sh python 步原来 ind python/bin -type f ! -name 'python3*' -delete 只删文件、不删链接。
本机下载钉版的 python-build-standalone 包（sha256 81a359f1… 核对通过）核对 python/bin：
  2to3 -> 2to3-3.12、idle3 -> idle3.12、pydoc3 -> pydoc3.12 是链接，目标文件被删 → 包里留下 3 个悬空链接；
  codesign --verify --strict 遇到悬空链接就报 "No such file or directory"。
新规则（文件和链接都删，只留 python3*）后保留：python3 -> python3.12、python3-config -> python3.12-config、python3.12、python3.12-config，全部可解析。

修法：
1. build.sh：python/bin 清理同时删链接；清理后确认 bin/python3 可执行。
2. build.sh：scan 步加 check_links（stage 里任何悬空链接 → 失败并点名，out/dangling-links-stage.txt），成品 .app 同样查。
3. sign-adhoc.sh：开头打印收到的 app 路径；签名前先找悬空链接，有就点名退出；最后 verify 失败时打印 codesign --verify --strict --deep --verbose=4 的末 40 行。
4. build.sh：DSH 打包失败时写 out/targets-tree.txt（.desktop-build/targets 五层目录、各 .app 父目录 ls -la、.app 内悬空链接），随 build-logs artifact 上传。
