### 7.2 实测中发现并修的一处（T26 第 2 步的回归，请复核员一并看）

桌面端连真服务时首页"最近案件"报"工作台服务暂时连不上"。抓网络请求：网关回 `gateway/arguments-invalid ... lawbench/caseRecent: unexpected "request"`。原因：第 2 步返修加的 `host\http-json.ts` 写了 `import { request } from 'node:http'`，打包（esbuild）时顶层多了一个叫 `request` 的绑定，它就把 Host 每个 API 方法的形参 `request` 改名成 `request2`；DSH 网关按形参名取参数，**所有带 `request` 的远程方法在打包后的桌面端都调不通**（`caseRecent`、`caseOpen`、`materialsImport`、`invoiceRun`、`archiveBuild`……）。源码级测试走的是没打包的 TS，查不出来。修：
- `http-json.ts` 改成 `import { request as httpRequest } from 'node:http'`；
- `scripts\build.mjs` 构建后新增一步：在纯 ESM 进程里导入 `lib\host.js`，逐个核对 `LawbenchRemote` 原型方法的形参名与 `REMOTE_METHODS` 一致，不一致构建失败并列出方法（实测把别名改回去，构建报出 `importPastedImage(request2) turnNotice(request2) … caseRecent(request2) …`）；`host\index.ts` 为此导出 `REMOTE_METHODS`。
- 影响面：`http-json.ts` 是第 2 步第一轮返修（P2-1，换掉 fetch 的 300 秒头超时）加的；那之后的桌面端截图都在它之前做，此后桌面端带 `request` 的方法一直不通，直到本次。

### 7.5 偏离与请主编排定

- **读方案走 Host**：服务没有读归档方案的接口，契约不改；Host 只读这一个文件并按契约校验。若主编排要服务出接口，界面只换一处调用。
- **"顺序"的理解**：工单写"表格可改名称、顺序、日期、承办律师"。项的编号由归档目录定（服务按编号合并、校验编号与名称），所以"顺序"做成每项里材料的合并顺序；项之间的先后不改。
- **对话框加宽**：DSH 对话框固定 380px，放不下表格。我方只用行内样式，这里给对话框加类名、注入一条 `width:min(820px, …)` 规则（同页只注入一次）。
- **金助理编号、案情简介、意见、律师费是否结清**：工单没列，界面只读显示（编号、律师费），不改；要改的话加在同一表单里即可。
- **律师说明**：界面没有，按钮在"成果"里该任务旁。
