# 材料删除：现状与最小方案（候契约 1.4，不实现）

2026-10-06，线 B，回执行令 `致B-ORCH-执行令-材料删除接口与读全容量-20261006-2043.md` 第 1 节；与候 owner N61 同一件事。

## 现状：没有删除接口

- `/api` 的 25 个接口里没有删除材料，也没有单独重建索引的接口。
- 律师在资源管理器里把原件删掉，再调一次 `POST /api/materials/scan`，这份材料会标成 `source_deleted`（列表显示"原件已删除"）。但它的材料文本、识别页、检索索引都还在，AI 照样能读、能检索到。这正是 N61 说的隐私问题（Spec 第 7 节"删原件保留文本"的设计结果）。
- 服务端删原件与 SEC-08"原件区只有导入（只新增、不覆盖），已有原件没有改写接口"冲突。所以真要做，先要 owner 定 SEC-08 怎么放宽。

**给线 A 的一句话**：现在界面上的"移除此材料"没法真正做到从索引和检索里去掉。最多只能提示律师到资源管理器删原件，再点"重新扫描"，结果只是标成"原件已删除"，文本仍可检索。要真删，等下面的接口。

## 最小方案：`POST /api/materials/remove`

**请求**
```json
{ "case_id": "<uuid>", "material_ids": ["M0003"], "delete_original": true }
```
- `material_ids`：1–100 个，必须是本案的。
- `delete_original`：是否同时删原件。建议只允许 `true`，理由见"取舍"。

**做什么**（每份材料，在案件锁里）
1. 原件**移到 Windows 回收站**（`SHFileOperationW` + `FOF_ALLOWUNDO`），不永久删除，律师删错了能从回收站还原。路径照常过闸门（`resolve_read`），只认原件区里的文件，不跟链接。
2. 删派生数据：`工作区\材料\文本\<rel>.md`、`工作区\材料\识别页\<编号>\`、检索库里这份材料的行（`search_units` 和 FTS）。还在跑的识别任务，这份材料的页取消。
3. `index.json` 里**保留这一条**，状态改为新的 `removed`，清掉 `text_path`。保留是为了：编号不复用（`next_seq` 本来就不回退）；旧草稿里引到它的出处，点开时能说清"这份材料已被移除"，而不是"没有这份材料"。
4. 不动已有的任务记录和草稿；wiki 里提到它的页不自动改，返回里提示"请更新 wiki"。

**返回**
```json
{ "ok": true, "value": { "removed": ["M0003"], "already_removed": [], "failed": [{ "material_id": "M0004", "reason": "原件正在被其他程序占用" }], "wiki_needs_update": true } }
```

**幂等**：已经是 `removed` 的放进 `already_removed`，不报错。不在本案的编号报 `MATERIAL_NOT_FOUND`，整个请求不做。

**日志**：`materials/remove` 一条，只记 case_id、份数、各结果的计数、失败的错误码。不记材料名、路径、编号以外的任何东西。

**相关接口随改**：
- `materials_list` 不列 `removed`，或列出但标"已移除"（二选一，界面定）；
- `/api/source` 和 `case_read_material` 对 `removed` 的材料回 `MATERIAL_NOT_FOUND`，提示"这份材料已被移除"；
- `materials/scan` 跳过 `removed` 的编号。

## 取舍（请定）

1. **要不要允许"只从索引去掉、原件留着"**（`delete_original: false`）。允许的话，原件还在原件区，下一次扫描会把它当新材料加回来，就得在 `index.json` 加一份"忽略清单"，契约改动更大。所以建议只做"连原件一起移到回收站"。
2. **SEC-08 的放宽口径**：建议写成"原件区不提供覆盖和永久删除；律师逐份确认后可把原件移到回收站"。
3. **契约改动**：新接口 `materials_remove`、`material_status` 加 `removed`。按事实索引第 8 节第 1 条的流程走。
