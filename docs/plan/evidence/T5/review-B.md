**F2 · T5 · 单份材料的解析没有资源上界：一个很小的 docx 或 xlsx 就能吃掉几 GB 内存，或让扫描长时间不返回**
- 影响：
  - 扫描持有该案件的锁，同一案件的列表和导入全部被卡住。
  - 内存耗尽时整个服务进程退出，本机转发（模型请求）一起中断。
  - 真实报表里"远处有带格式的空单元格"很常见。

## 五、活性地图

- 扫描和导入是同步接口，在线程池里执行，持有按案件分的锁。实验 e21：扫描进行中，同一案件的列表等了 10.2 秒。
- LibreOffice 转换由全局锁串行执行，每次最多 120 秒，所以 N 份 doc 最坏要 N × 120 秒。
- docx、xlsx 的解析没有上界（F2）。
- 实验 e21 在 20 秒的高 CPU 扫描期间：流式转发最大间隔 0.6 秒（基线 0.52 秒），`/health` 1.2 秒。
- 转发的地址选择和材料接口共用 anyio 默认线程池（40 个）。卡死的扫描一多，就可能拖住模型请求。这一条是代码推断。
