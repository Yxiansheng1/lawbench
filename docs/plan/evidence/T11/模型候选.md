## 三、能不能和另一个模型同时常驻（95.8 GB 专用显存）

按"权重 + mmproj + 上下文缓存"粗估（上下文缓存按工单的 `-c` 设置，8K×2 路和 16K×1 路，以 GB 级估计）：

| 组合 | 权重大约 | 结论 |
|---|---|---|
| PaddleOCR-VL-1.6 + Qwen3-8B Q8_0 | 0.94 + 0.88 + 8.71 ≈ 10.5 GB | 同时常驻绰绰有余 |
| GLM-OCR Q8_0 + Qwen3-8B Q8_0 | 0.95 + 0.48 + 8.71 ≈ 10.1 GB | 同上 |
| Qwen3-VL-8B Q8_0 + Qwen3-8B Q8_0 | 8.71 + 1.16 + 8.71 ≈ 18.6 GB | 可以；OCR 并发 N 取 3 也够 |
| 三个 OCR 候选同时放上去做对比 + Qwen3-8B | 约 21 GB | 可以（只在 G-5 对比阶段这样做） |

显存不是瓶颈，决定因素是识别准确率和每页耗时，要以 G-5、G-6 实测为准（`prep395\deploy\bench_g5g6.py`）。

## 四、推荐

- **OCR 首选 PaddleOCR-VL-1.6，候补 GLM-OCR，兜底 Qwen3-VL-8B-Instruct（Q8_0 + mmproj F16）。**
  - 理由：前两个是专为文档识别训练的小模型，公开的中文文档解析指标最高，许可证最宽，速度快。
  - 顾虑：llama.cpp 对 PaddleOCR-VL 标注了"可能效果打折"，而且专用模型不接受"看不清写 ■"这类自由指令。所以 G-5 时三个都用同一批样张跑（讯问笔录 3 页 + 现造 20 页），按字符相似度、关键字段命中率、每页耗时选。
  - 如果专用模型对手写批注、印章压字明显不如 Qwen3-VL-8B，就改用 Qwen3-VL-8B，因为它能按 Spec 6.4 的要求标注"看不清"。
- **9B 首选 Qwen3-8B（Q8_0），候补 Qwen3.5-9B（Q8_0）。**理由：官方 GGUF、Apache-2.0、中文强、体积合适。Qwen3.5 更新，但 GGUF 是社区量化，llama.cpp 官方支持未核实，作对照。
- 两类都不选任何自定义许可证的模型；GLM-4-9B 系许可证未核实，不用。

### 任务提示词（模型卡"Task prompts"原文，专用模型只认这几句）

| 任务 | 提示词（一字不改） | 输出 |
|---|---|---|
| Document（整页） | `Extract all information from the main body of the document image and represent it in markdown format, ignoring headers and footers. Tables should be expressed in OTSL format, formulas in the document should be represented using LATEX format, and the parsing should be organized according to the reading order.` | Markdown；表格用 OTSL，公式用 LaTeX |
| Text region | `Extract the text in the image.` | 纯文本 |
| Table region | `Parse the table in the image into OTSL.` | OTSL 表格 |
| Formula region | `Identify the formula in the image and represent it using LATEX format.` | LaTeX |
| Key information extraction | `Extract key information in the image`，后面跟 JSON schema | JSON |

prep395 用的是 **Document** 那一句：`backends.XIAOMI_OCR_PROMPT`，`PREP395_OCR_MODEL` 的名字里带 xiaomi 时启用。

### 换它之前要知道的三件事

1. **它忽略页眉页脚**：提示词原文里就有 "ignoring headers and footers"。卷宗页眉里的案号、页脚里的页码可能不会出现在识别结果里。这是模型卡规定的用法，改提示词就偏离了它训练时见过的输入。对办案有没有影响，要看第 4 步对比结果里讯问笔录的页眉。
2. **表格输出是 OTSL 标记**（`<fcel>`、`<nl>` 这类），不是 Markdown 表格。这次没有做 OTSL 转 Markdown：卡上的样例里没有表格样例，不知道真实输出长什么样，等对比跑出真实表格页再定。
3. **"看不清写 ■ / [看不清]"它不会照做**：专用模型不认自由指令。契约里的 `unclear` 计数对它恒为 0。原来的 PaddleOCR-VL 也是专用模型，情况相同。

### 备选方案：识别放到 6000D（令 1818，降为备选，不做操作单、不做转发代码）
