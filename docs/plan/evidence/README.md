# docs\plan\evidence —— 工单证据目录

每张工单一个子目录 `T<n>\`，放该卡的测试输出、截图、抓包和交付说明。工单集"五门格"里只填这里的文件路径。

## 放什么

| 文件 | 谁写 | 说明 |
|---|---|---|
| `T<n>\交付说明.md` | 执行该卡的会话 | 六节：目标与出处 / 改动清单与提交 SHA / 红绿验证 / 测试证据路径 / 契约或文档摘要 / 自检与遗留、模糊条款摘录。随分支提交 |
| `T<n>\pytest.txt` 等测试输出 | 执行该卡的会话 | 命令的完整输出，文件名按工单"产出"一栏 |
| `T<n>\*.png` | 执行该卡的会话 | 截图 |
| `T<n>\review-*.md` | 主编排派出的复核员 | 复核记录（事实索引 8.5 的八项清单；高风险卡两份） |
| `T<n>\merge.txt` | 主编排 | 合并后 SHA 和 pytest 全量、契约自检、`build_skills.py` 三项输出（②合流门） |

## 不放什么

- Key、密码、EasyTier 网络密钥、SSH 密码。证据里出现 Key 就当场删掉重跑。
- 真实案卷内容和材料名。测试只用 `tests\fixtures\` 的虚构材料。
- 模型的输入输出正文（`tool-call.txt` 这类证据按工单要求去除内容后再存）。
- 安装包等大文件（只记 sha256）。

## 规矩

- 各线只写自己工单的 `T<n>\`；`merge.txt` 和复核记录由主编排写。
- 工单集文件本身只由主编排在 `main` 上改。
