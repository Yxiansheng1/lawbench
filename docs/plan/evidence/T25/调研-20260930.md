只读调研，engines\ 未改一个字。静态分析由子代理（opus）逐行给出 file:line，线 C 抽查了关键几条（invoke.py 任意路径、workflow.py 退出码、period_plan 的 eml 起止日期、贴票清单写死购买方、cancel 必须 --apply、run 的 --download-links、driver 的 CORS 与 500 堆栈），均与代码一致。实测只在本机临时目录跑，用 tests\fixtures\invoices-01，不碰真实账目。

## 一、实测：直接跑引擎一期，0 条对外连接

证据：`调研-连接-短路径.txt`（主证据）、`调研-连接.txt`（第一次，暴露路径过长问题）。

- 环境变量只传 Spec 13.3 那几个：`INVOICE_BUYER`、`PYTHONUTF8`、`SYSTEMROOT`、`LOCALAPPDATA`、`USERPROFILE`、`TEMP`、`TMP`。
- 连接的抓法：每 100 毫秒对引擎进程树（含子进程，最多 8 个）做一次 `Get-NetTCPConnection`。
- 跑的步骤：env_check、history、plan(local, exclude)、run、report、check_schema。
- **结果：6 步合计对外连接 0 条。**
- 引擎行为符合预期：
  - 发票04 判为重复；zip 里的 02、03 与单张同票，也判为重复。
  - 发票05 判为"抬头错误"。
  - 发票01 判为"待核"（分类缺失，需人工核定），所以 run 退出 2。
- **路径过长导致失败（待定项 P1）**
  - 第一次把缓存放在较深的临时目录，openpyxl 导入失败，env_check 退出 1，check_schema 退出 1。
  - 引擎展开缓存时用了 `\?\`，所以解压能成功；但导入时 Python 走普通路径，超过 259 字符就读不到文件。
  - 本机默认缓存前缀是 168 字符（`%LOCALAPPDATA%` 占 28 字符）。按第一次失败时的实测，余量约 30 字符，所以 `%LOCALAPPDATA%` 长过约 59 字符（Windows 用户名长过约 36 个字符）就会出同样的错。本机 `LongPathsEnabled=0`。

## 二、白名单对照（Spec 13.3 `:1132-1147`）

白名单每个动作都对应引擎里的一条子命令。只要服务不传 `--download-links`、`--imap-host`，这些子命令都不联网。引擎里所有联网代码的位置如下：
- IMAP：`mail_collect.py:100-135`，唯一调用点 `workflow.py:104`（collect 子命令）。
- HTTP：`mail_collect.py:39-41,92-99`，调用点 `workflow.py:106-108`。
- 构建期下载：`build_env_zip.py:41,80,108-110`，会从 python.org 下载并 pip install。
- 其他：MCP 客户端、更新检查、遥测，均未找到。
- 没有任何配置文件或环境变量能打开联网。

绕过口子：
1. **`invoke.py` 接受任意脚本路径**（`invoke.py:13-19`）：绝对路径、`..\` 都能执行，包括会联网的 `build_env_zip.py`。服务必须把脚本名写死，不能来自请求。
2. **`run` 自带 `--download-links`**（`workflow.py:23,63`），服务不得拼这个参数。
3. `collect` 子命令不在白名单里，但能直接调用。
4. 缓存完整性只在首次展开时核 sha256，日常启动只核大小（`runtime_cache.py:105`）。能写 `%LOCALAPPDATA%\invoice-ledger-db` 的进程可以换掉要执行的代码。这属于本机信任边界内的问题，列为已知风险。
5. 子进程继承全部环境变量（`runtime_cache.py:215`），所以"只传白名单变量"要靠服务在启动时清空环境来保证。

## 三、委托材料识别驱动 driver.py

- 监听：`ThreadingHTTPServer`，默认 `127.0.0.1:17801`（`:339,341`），没有认证。
- 跨域：返回 `Access-Control-Allow-Origin` 和 `Allow-Private-Network: true`（`:210,213`），本机任何网页都能调用。Spec 已记为残余风险。
- 出错时 500 响应带 `detail` 字段，是异常堆栈的末尾 800 个字符（`:300,317`）。
- 接口：`GET /health`；`POST /ocr` 请求体是文件原始字节，文件名放 `X-File-Name` 头；上限 50 MB；识别串行执行。
- 依赖：
  - 驱动自带：rapidocr 3.9.2、omegaconf、antlr4。
  - 需要客户端 Python 另装：numpy、opencv-python、onnxruntime、pyclipper、Shapely、six、PyYAML、Pillow、tqdm、colorlog、**requests**（导入阶段就会加载）、**PyMuPDF**（处理 PDF 必需）；python-docx 可选。
  - **pywin32 没用到**。仓库里没有 requirements 或锁文件，README 记录的实测版本是 onnxruntime 1.24.4。
- **首次运行会不会下载模型**：
  - 正常情况不下载。自带的 det、rec、cls 三个模型，sha256 都与 `default_models.yaml` 里的期望值一致（子代理本地算过），一致就跳过下载（`download_file.py:48-61`）。
  - 但文件缺失或损坏时，会用 requests 自动去 modelscope.cn 重新下载（`:63-75`）。
  - rapidocr 初始化失败时，会退到 PaddleOCR（`driver.py:138,180`），PaddleOCR 按一般行为也会联网下载模型（仓库内未验证）。
  - 识别字典不用下载的前提是 rec 模型元数据带有 `character` 键，目前只 grep 到了这个字样，还没实际加载验证。

## 四、契约与引擎之间要服务端转换的地方

- `invoice_run.value.files`：引擎不直接返回文件清单，服务得自己按动作去收集，比如 prepare 生成的 `_打印包\<period>\<batch>\vNNN\`、history 的 `--out`。
- `plan.history_numbers`：契约给的是数组，引擎要一个文件路径，服务得先把数组写成临时 JSON 文件再传。
- `run.channel=eml`：契约只有 `src`，引擎要用 `--eml <路径>`，服务按 channel 选参数（Spec 表里已写）。
- `retainer_driver`：契约是 start/stop/status 加 `port:17801`，服务要自己起停进程（不用 start-engine.bat，它写死了别人电脑上的 Python 路径），再用 `/health` 判断 running。
