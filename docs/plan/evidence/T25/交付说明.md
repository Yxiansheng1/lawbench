## 偏离之处

1. **驱动启动加了 `--engine rapidocr`**（工单命令里没有）：不加时 RapidOCR 初始化失败会退到 PaddleOCR，后者首次运行会联网下模型（调研 P11）。
2. **启动前核模型 sha256**，不一致就不启动并提示重装（调研 P11；Spec 14.1"运行时不下载任何东西"）。依据是驱动自带的 `default_models.yaml`，不另存哈希表。
3. **pyproject 没加 rapidocr 和 pywin32**（工单列了）：rapidocr 3.9.2 由驱动 `vendor\` 自带且优先；pywin32 驱动不用（调研 3.2）。另加了驱动导入时必需的 pyclipper 等。
4. 端口被别的程序占用、模型损坏、启动失败时，**不返回错误码**，返回 `running:false` 加中文说明（契约的 value 有 `message`，没有合适的错误码；委托材料网页其他功能不受影响）。
5. 同一时间只运行一个动作：后到的请求**排队等待**，不报错（契约没有"忙"的错误码）。

## 待主编排定（阻塞"走完一期"；详见 `致ORCH-C-注记-T25两条待定-20260930-1711.md`）

- **A. ENGINE_FAILED 失败体装不下引擎输出**：`common.schema.json#/$defs/fail` 只有 code、message，引擎 `[BLOCKED]` 的原因（如"收集任务有待处理或数量不符项"）律师看不到，而 ENGINE_FAILED 的提示是"请查看下方的输出信息"。暂按工单返回失败体。
- **B. invoices-01 走不完一期**：发票01 判"待核：分类缺失"，`review` 对字段错误直接拒，`exclude` 不在白名单 → prepare 被拒、批次建不起来。建议 `exclude` 并入白名单（参数见 1701 注记）并请 T1 查样本分类。

## 遗留

- 服务退出时没有主动停驱动：由 Host 插件在委托材料窗口关闭时调 `stop`；服务崩溃时驱动进程会留着（下次 `start` 会复用它）。
- 驱动的识别字典是否在 rec 模型里（调研 P11 的最后一条）：本次真驱动识别一张图片成功且全程无对外连接，间接说明不需要下载字典。
- 开发机 `.venv` 为测试装了驱动依赖（onnxruntime 1.24.4 等，从 PyPI）；打包时由 T20 随客户端 Python 预装。
