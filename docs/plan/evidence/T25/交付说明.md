## 返回语义（契约 1.3，1128 令 A 项）

| 情形 | 返回 |
|---|---|
| 退出码 0 | 成功体 `failed:false, attention:false` |
| 退出码 2，输出没有以 `[BLOCKED]` 开头的行 | 成功体 `attention:true, failed:false`（有重复、冲突、待核，看明细） |
| 引擎自己报失败：输出有以 `[BLOCKED]` 开头的行，或退出码不是 0 / 2 | 成功体 `failed:true, attention:false`，原因原样在 `output`（如"收集任务有待处理或数量不符项"） |
| 服务自身故障：引擎起不来、30 分钟超时 | 失败体 `ENGINE_FAILED` |
| 证件识别驱动的模型哈希不符 | 失败体 `ENGINE_FAILED`（不启动） |

`[BLOCKED]` 按"任一行以它开头"判，不只看第一行：`run` 会依次跑三步，前面的步骤先打印了统计 JSON，失败行在后面。

## 对引擎输出的唯一一处后处理：N50 贴票清单另存一份（2023 补充令）

- 引擎在 `贴票清单.html` 里写死了购买方"广东连越（深圳）律师事务所"（`reimbursement.py:86`）。原文件不能改：`prepare` 把打印包里每个文件的 sha256 记进批次记录，`reprint`、`reimburse` 前都要核对（`check_artifacts`，`reimbursement.py:96–118`），改了就重印、报销都过不去。
- 做法：`prepare` / `reprint` 成功后，runner 在同一打印包文件夹里另写 `贴票清单（<购买方>）.html`，只把那一串换成设置里的 `invoice_buyer`（HTML 转义；文件名去掉 Windows 不允许的字符），其他字节不动；返回的 `files` 用副本代替原文件。设置里购买方为空、或清单里没有那一串时，不生成副本，`files` 里是原文件。
- **原文件仍在文件夹里，写着写死的名称**。界面（T26）只给副本的"打开 / 打印"入口。
- **换引擎版本时**要重新核对 `runner.HARDCODED_BUYER` 这一串和 `贴票清单.html` 的文件名。
- 测试：真引擎一期里副本存在、不含写死串、原文件哈希仍等于批次记录、之后的 `reprint`、`reimburse --apply` 照常；四种边界（购买方为空 / 空串 / 清单里没有那一串 / 名称含特殊字符）单测。

## 偏离之处

1. **驱动启动加了 `--engine rapidocr`**（工单命令里没有）：不加时 RapidOCR 初始化失败会退到 PaddleOCR，后者首次运行会联网下模型（调研 P11，1701 令确认）。
2. **启动前核模型 sha256**，依据驱动自带的 `default_models.yaml`，不另存哈希表。`ENGINE_FAILED` 的提示文字是"发票整理未完成…"，用在证件识别上不贴切，界面（T26）可按接口区分文案。
3. **pyproject 没加 rapidocr 和 pywin32**（工单列了）：rapidocr 3.9.2 由驱动 `vendor\` 自带且优先；pywin32 驱动不用（1701 令 P12 确认）。另加了驱动导入时必需的 pyclipper、requests、PyMuPDF 等，单列 `retainer` 组。
4. 驱动端口被别的程序占用、启动失败时，**不返回错误码**，返回 `running:false` 加中文说明（契约的 value 有 `message`；委托材料网页其他功能不受影响）。
5. 同一时间只运行一个动作：后到的请求**排队等待**，不报错（契约没有"忙"的错误码）。
6. 顺手修了两处 main 上因契约升 1.3 变红的 `/health` 断言（main 随后也改了，rebase 时取了 main 的写法）。

## 1701 令补充项

- P3：plan `channel=eml` 缺 `start` / `end` → `INVALID_ARGUMENT`（契约放行、服务再挡），并入 `test_api_refuses_by_contract`。

## 遗留

- 服务退出时没有主动停驱动：由 Host 插件在委托材料窗口关闭时调 `stop`；服务崩溃时驱动进程会留着（下次 `start` 会复用它）。
- 引擎会往台账目录 `_日志\`、任务目录 `运行日志\` 和 `%TEMP%\invoice-ocr-*` 写明细（回写⑦），runner 不处理，Spec 第 14 节落点表已列。
- 开发机 `.venv` 为测试装了驱动依赖（从 PyPI）；打包时由 T20 随客户端 Python 预装。
