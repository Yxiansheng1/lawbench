## 偏离之处

1. **驱动启动加了 `--engine rapidocr`**（工单命令里没有）：不加时 RapidOCR 初始化失败会退到 PaddleOCR，后者首次运行会联网下模型（调研 P11）。
2. **启动前核模型 sha256**，不一致就不启动、报 `ENGINE_FAILED`（1701 令 P11）。依据是驱动自带的 `default_models.yaml`，不另存哈希表。注意 `ENGINE_FAILED` 的提示文字是"发票整理未完成…"，用在证件识别上不贴切，界面（T26）可按接口区分文案。
3. **pyproject 没加 rapidocr 和 pywin32**（工单列了）：rapidocr 3.9.2 由驱动 `vendor\` 自带且优先；pywin32 驱动不用（调研 3.2）。另加了驱动导入时必需的 pyclipper 等。
4. 端口被别的程序占用、启动失败时，**不返回错误码**，返回 `running:false` 加中文说明（契约的 value 有 `message`；委托材料网页其他功能不受影响）。模型损坏按令报 `ENGINE_FAILED`（见 2）。
5. 同一时间只运行一个动作：后到的请求**排队等待**，不报错（契约没有"忙"的错误码）。

## exclude（契约 1.3 并入，1757 注记）

- runner 拼 `workflow.py exclude --job <任务目录> --item <记录ID> --reason … --reviewer … --confirm`，一律带 `--confirm`（确认在界面做）。
- **不可逆**：引擎没有"取消排除"。界面（T26）必须逐项确认，写明"排除后本期不再计入该票"。
- 只写任务目录（`collection.json`、`收集对账表.csv`、`_transaction.lock`），台账与 `_原票` 不动——用例逐字节核对。

## 遗留

- 服务退出时没有主动停驱动：由 Host 插件在委托材料窗口关闭时调 `stop`；服务崩溃时驱动进程会留着（下次 `start` 会复用它）。
- **识别字典实测（1701 令 P11）**：用 onnxruntime 读 `PP-OCRv6_rec_small.onnx` 的元数据，自定义键只有 `character`，共 18708 条——rapidocr 走"onnx 自带字典"分支（`ch_ppocr_rec/main.py:41`），不会去下载字典。
- 开发机 `.venv` 为测试装了驱动依赖（onnxruntime 1.24.4 等，从 PyPI）；打包时由 T20 随客户端 Python 预装。
