## 步骤 2 · 内置 Python（结论记 `PATCHES.md` 结论记录）
- **结论**：复用 DSH 内置的同一份 Python 3.12.14 发行包（同一文件、同一哈希），但单独解压一份到 `<安装目录>\python\`，我方依赖装进它自己的 `site-packages`。Host 以 `-I -m lawbench` 启动服务。
- **为什么不直接共用 DSH 那份解释器**：
  - 共用时依赖只能放单独目录，靠启动壳隔离。服务本身和它的测试能跑通，但服务另起的证件识别驱动用 `sys.executable`、只带运行必需的环境变量，拿不到那个目录里的依赖。
  - 装进 DSH 的载荷，要改 DSH 的打包脚本（载荷带摘要、会被核对）。
- **隔离**：`-I`，再加 `sitecustomize.py`。DSH 这个解释器不带 `-I` 时会加用户目录的 site-packages（本机实测），子进程也要管住。
- **验证**：两种做法各跑一遍服务全部测试。采用的做法 945 通过、6 跳过、0 失败（`python-reuse.txt`）。
- **Host 配置的后续**：打包后 `legal-host` 的 `command` 应为 `["<安装目录>\python\python.exe", "-I", "-m", "lawbench"]`、`cwd` 为 `<安装目录>\service`。这和 `PATCHES.md` 待办里"启动命令打包时定"是同一条，步骤 3 落地。
- **另附**：`packaging\python\sitecustomize.py`、`lawbench-service.pth`；`build.ps1` 的 `python` 步骤。
