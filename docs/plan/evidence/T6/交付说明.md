## 6. 自检、遗留与模糊条款

**偏离工单"产出"清单之处**
1. 多了 `config.py`（环境变量配置与地址白名单）和 `__main__.py`（启动入口）；纠偏放在 `dewatermark.py`（同属图片预处理）。
2. `/admin` 除 HTML 外，请求头 `Accept: application/json` 时返回同样内容的 JSON（测试用）。契约没有定义 `/admin`。
3. 客户端断开的请求在日志里记 `status: 499`、`err: "ClientGone"`（没有响应可发，这个状态只进日志）。
4. `/admin` 口令只配 SHA-256 摘要（`PREP395_ADMIN_PASS_SHA256`），不配明文。

**Spec 没写明、我采用的做法**（请主编排裁决）
- (a) 去水印的"大面积重复"：只实现了"浅灰、低饱和、占全图 ≥1%"三个条件，没有做"重复图案"的周期检测。原文："只去除浅灰色、低饱和度、大面积重复的斜向文字或图案。"扫描噪点里的浅灰点也会被换成底色（对识别无害）。默认关闭。
- (b) `/health` 的 `queue` 取识别和抽取两个队列中**排队**（不含处理中）的请求数之和。原文只给了样例 `"queue": 3`。
- (c) 504 超时只计推理阶段（拿到名额之后），排队等待不计入 120 秒。原文："504 识别超时（单页 120 秒）"。
- (d) 9B 抽取的排队上限沿用 20（原文只写"9B 抽取同时处理 1 个"）。
- (e) 抽取结果里不符合契约的条目（字段不是请求里的、值为空、`loc` 不是"第N页/段/行"）直接丢掉；分类结果不在给定类别内时，有"其他"就返回"其他"，没有就返回 500 `INTERNAL`。
- (f) 抽取请求的大小上限也用 10MB（原文只限 text ≤16000 字）。

**遗留**
- 没连过真 6000D 和真 llama-server：6000D 目前不校验 Key（Spec 6.3、事实索引第 4 节），真机上 Key 校验形同虚设，要等律所开启 `require_key` 后复测；OCR / 9B 的提示词、`■` / `[看不清]` 标注、并发数 N 都要在 T11 用 G-5、G-6 实测校准。
- 部署（WinSW、专用账号、防火墙、BitLocker、llama-server 参数）属 T11。
- 依赖装在本线 `.venv`；`pip install -e .\prep395[test]` 可装全。
