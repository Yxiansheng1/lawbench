## 6. 计量工具（执行令 `致B-ORCH-执行令-T18预算计量工具-20261003-1410.md`，2026-10-03）

- 基于 origin/main `28f8761`；`service\tools\t18_budget.py`（联调工具，不改 `service\lawbench\`；对日志、案件文件只读）。用法写在文件头。
- **读什么（先读代码核过字段）**：
  - 服务日志 `logs.event` 只有 `t / module / op / status / case_id / ms / error`，**没有 task_id、也没有工具名**；`/core/*` 每次调用记一条 `module=core`、`op=task_begin|context|tool|progress|task_end`，`core/tool` 的返回里通常没有 case_id，日志也就不带。所以服务日志只能作旁证（同一时间窗的 core 各操作条数），不能按任务、按工具名拆。
  - 按任务的事实在案件 `工作区\任务\<task_id>\`：`task.json`（kind、skill、session_id、budget、created_at）、`result.json`（status、插件自报的 usage、finished_at）；流水线任务另有 `运行记录.json`。
  - 按工具名、模型次数要靠 DSH 会话记录 `工作区\会话\**\session.v4.jsonl`（DSH 默认 zstd 压缩时是 `.jsonl.zstd`，工具支持两种；压缩的要装 `zstandard`，没装就在说明里报出、该任务实测留空）。事件格式按 DSH 源码（`session-persistence-jsonl`、`session-stats`）：首行 `type: session` 带会话 id；`step/start` 一次 = 一次模型调用；`tool/call` 的 `data.name` 是工具名。**只读 type、time 和 tool/call 的 name，不读 arguments 和消息正文**（自测里放了一个带检索词的 arguments，核过输出里没有）。
- **怎么算**：按 `task.json` 的 session_id 找会话，取任务时间窗（created_at 到 finished_at，前后各放 5 秒）里的事件；任务单（state=pending 的选择）不算一次执行。预算口径：工具次数只计 case_* 里除 `case_save_draft` 以外的（Spec 9.2），`skill`、`ask_user_question` 不计（各占一次模型调用）。超预算按 `task.json` 的 budget 判模型、工具、分钟。"自报"一栏读 `skill-report.md` 第一节的"预估：典型 / 大"（第一阶段没有"实测"列，令里说的"实测次数 / 上限"自报，第一阶段只有预估）；另列插件经 `/core/task/end` 自报的 usage，与会话实测并排。
