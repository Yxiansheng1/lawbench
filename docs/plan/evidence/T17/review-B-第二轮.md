- **问题**：`InputBar.tsx:211-233` 的 `intakeFiles` 先按聊天图片上限检查，不过就直接弹提示返回，不调用 `addFiles`。P-5 的钩子恰恰装在 `addFiles` 里（`apply.ts:487-491`）。拖入、粘贴（`keymap.ts:175` 经 `view-binding.ts:139`）、选择文件（`InputBar.tsx:242`）三条路都先过这道检查。
- **上限**：默认值在 `attachment-local/src/index.ts:34-38`。
  - 单张 20 MB；
  - 一次 20 张；
  - 总计 200 MB。
  - 我方 `cordis.patch.yml` 没有改这些值。
- **影响**：律师往对话框拖 21 张以上的扫描照片，或一张超过 20 MB 的高清扫描件，会看到"一条消息最多添加 20 张图片"这类聊天附件提示，什么也没导入。这与 Spec D13 / U-12、PATCHES.md P-5 行说的"拖入、粘贴、选择文件都走它"不符，提示用语也会误导律师。

  - `intakeFiles` 先问已登记的钩子，钩子接手就跳过图片上限检查；
  - 或者有钩子登记时不做这项预检。

### F3 · P3 · 独立后续：P-15 先 `realpath`、后判断根目录，由此带来两个小问题
- **存在性探测**：外部路径存在时回 403，不存在时回 404，可以借此探测文件是否存在。实测：`outside\c.png` 返回 403，`outside\missing.png` 返回 404。
- **网络路径先被访问**：`\\host\share\...` 这类路径在判断根目录之前就会被 Host 访问一次。实测 `\\127.0.0.1\rvbnoshare\x.png` 返回 404，耗时 10 ms，说明确实发起了 SMB 访问。
- **实际风险低**：界面侧 `fileMediaUrl`（`util/workspace-path/src/index.ts:120-123`）会拒绝以 `\\` 或 `//` 开头的路径，只有直接调接口才能走到这里。
- **最小修复**：`realpath` 之前先拒绝网络路径和设备路径前缀；越界和不存在都统一回 403。

### F4 · P3 · 独立后续：P-15 检查和读取之间有时间差
- **问题**：检查用的是 `realpath` 之后的规范路径，读取 `fs.resolve(path)` 用的仍是原始路径。中间有人换掉链接，就能绕过检查。
- **风险低**：要求有人能在案件文件夹里建链接，律师工作台的 Agent 没有这类工具。
- **修法**：读取改用 `canonical`。

### F5 · NOTE · 臆测：把盘符根目录登记成工作区时，整个盘都可读

- **待定**：案件创建时是否允许选盘符根目录，要交主编排或 T3 决定。
