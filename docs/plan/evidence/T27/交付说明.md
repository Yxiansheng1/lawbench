## 395 运维两坑之 ①③：EasyTier 服务化、两台服务器一键检查（令 2026-10-03 14:10）

**背景**：10-02 晚律所停电，10-03 中午来电。395 的 EasyTier 昨天是手动起的，重启后一度不在；后来网卡列表里又看到 `et_*` 网卡 Up，具体是不是自启没查清。

### 做了什么

1. **服务化方式：选 EasyTier 自带的 `easytier-cli service install`，不用 WinSW。**
   - 依据：开发机 `C:\EasyTier` 是同版本 2.6.4，它的帮助存在 `easytier-service-help.txt`。`service install` 默认开机自启、失败自动重启，`--core-path`、`--service-work-dir` 可指定，参数放在 `--` 之后原样交给 easytier-core。
   - 不选 WinSW 的理由：EasyTier 版本本身支持，少一层包装；WinSW 那套是 prep395 用的。
2. **`deploy\easytier\install_service_395.ps1`**（在 395 上以管理员运行）：
   1. 检查版本是 2.6.x。
   2. 把现有服务定义（`sc qc`、`sc qfailure`）和手动进程的命令行备份到 `C:\EasyTier\backup\`，该目录只有 Administrators 和 SYSTEM 能读，因为命令行里可能有密钥，所以存而不显示。
   3. 没有配置文件时，提示粘贴密钥，写成只有管理员可读的 `C:\EasyTier\lawbench.toml`，模板沿用 A3②'。已有配置文件时只核对权限，有别人能读就停下。
   4. 用 `--check-config` 检查配置，不通过就停下，此时什么都还没改。
   5. 停掉旧服务（`sc delete`）和手动进程。
   6. `easytier-cli service install ... -- --config-file <cfg>`；A3 之后加 `-SecureMode`，追加 `--secure-mode true`。
   7. 再用 `sc.exe` 明确设开机自启、失败重启（5 秒、10 秒、30 秒）和 `failureflag`。
   8. 启动服务，等虚拟地址出来，然后自检。
   - **脚本里没有任何密钥值。**
3. **`check_service_395.ps1`**（只读）逐项给 PASS / FAIL，不显示密钥：
   - 服务在、在跑、开机自启、失败重启；
   - 命令行里有 `--config-file`、没有 `--network-secret`；
   - 没有另外手动起的 easytier-core；
   - 配置文件只有管理员可读；
   - `10.126.126.3` 在一张 Up 的网卡上；
   - 经虚拟网能连到 6000D:8000；
   - `192.168.8.124` 在、而且是静态（Manual）。
4. **`uninstall_service_395.ps1`**：回退。卸掉服务后，按最新的备份恢复：原来是服务就恢复原服务定义，原来是手动进程就照原命令行起起来。`-RemoveOnly` 只卸不恢复。
5. **`deploy\check_servers.py`**（开发机或任何入网的电脑都能跑）：
   - 查 395、6000D 所内所外四个地址：端口、395 `/health`（status、ocr、llm9b 都是 ok，契约版本等于 `contracts\VERSION`）、6000D `/v1/models`；
   - 所内 `/health` 能到，就视为 395 仍在 `.124`；
   - 本机不在局域网或没入虚拟网时，对应两行记"不适用"，不算不通过；
   - 395 所内**端口不通**时，提示可能是换了地址、该怎么查。
   - 端口检查和本机地址判断复用 `deploy\easytier\check_remote.py`；HTTP 不走系统代理。
6. **`check_remote.py`** 的 HTTP 检查改为不走系统代理。`scripts\check_6000d.py` 走系统代理，10-03 中午把"连不上"显示成了代理返回的 502；`check_remote.py` 有同样的写法。`scripts\check_6000d.py` 本身这次没改，需要的话请另派。
7. **文档**：
   - README 现状表里 node-395 一行写明"10-03 是否自启未查清"，新增第 6 节"395 服务化与检查"；
   - `操作单-上线前.md` 的 A3②' 加了一段：已经服务化的话，只换配置文件里的密钥，再跑 `install_service_395.ps1 -SecureMode`。

### 偏离与没验证的

- **三个 ps1 没有在 395 上跑过**：按令 395 上的实操由用户做。服务装上之后 `sc qc` 里的 BINARY_PATH_NAME 具体长什么样，只能在 395 上第一次运行时核对；`check_service_395.ps1` 就是核对这个的。
