## 只读、闸门与日志

## 需要主编排知道的 / 交主编排定的（按最稳做法先走，已标明）

1. **Word 会按文档里的链接取图（实测）**：本机 Office16，docx 里一张"链接到文件"的图片（`r:link` + `TargetMode="External"`）指向本机监听，`Documents.Open` 前已关 `Options.UpdateLinksAtOpen`，导出 PDF 时仍发了 8 个请求（INCLUDEPICTURE 域那种没发）。Spec 14.3 ③"Word / WPS 打开文档时不更新链接"这一招拦不住。现在的做法：交给 Word / WPS 之前查外链，**按文件头分流、不看扩展名**（第一轮复核 P1-2：docx 改名 `.doc` 曾走二进制检查漏判）——压缩包查所有关系文件里的 `TargetMode="External"`（超链接除外）、链接类域、altChunk 内嵌 HTML 里的外部地址；OLE 查加密和 14.3 ②a；其他内容（RTF、HTML、文本冒充 Word 文档）一律不交；查不了按有。有外链就只走 LibreOffice；设置里只选了 word / wps 的这类文档报 `CONVERTER_UNAVAILABLE`。LibreOffice 之前同样按文件头查（P1-1）。建议把这条写回 Spec 14.3 ③。WPS 本机没装，未实测，按同样的检查处理。
2. **`Options.UpdateLinksAtOpen` 是律师 Word 的持久设置**：转换时关掉、用完恢复原值；子进程被超时结束时会停在"关"（更安全的一边）。要不要连这一步也去掉（反正有第 1 条的检查），请定。
3. **设置里指定了某一个程序时只用它、不换别的**：Spec 写"按设置选择，默认 auto 依次尝试"，没说指定后失败要不要换。按 12.3"如果在案件目录外搜到正文，把默认值改为 libreoffice"的用意，指定 libreoffice 后不能再退回 Word，所以按"只用它"做。
4. **`converter` 返回哪个**：一次生成里不同材料可能用了不同程序，契约只有一个值。返回**结案报告**用的那个（界面据此提示"请在 Word / WPS 中核对是否为一页"），提示里也写明。
5. **原版与 Spec 不一致处（摘原文）**：
   - 原版第六步 6.4"白底遮罩覆盖原页码区域"用 `Rect(0, h-55, w, h)`（底部 55 磅），Spec 12.4 第 4 步只说"底部先画一条白色矩形"。按原版取 55 磅、页码基线离底边 25 磅。55 磅较高，原文底部正文离页边很近的会被遮住一部分。
   - 原版第七步 7.3 页码写法示例同时有 `'p1-1'` 和 `'p162'`，Spec 只举 `p12-15`。按"首尾同页写 `p162`、否则 `p12-15`"。
   - 原版第四步结案报告示例只给了"一、当事人/委托人"和"八、办案结果"，中间编号未给。临时版式按八项排：一 当事人/委托人（含对方当事人）、二 委托日期、三 结案日期、四 承办律师、五 案由、六 案情简介、七 承办律师分析与意见、八 办案结果。
   - 常法卷：原版说"服务概况"替代"案情简介"、"服务结果"替代"办案结果"；契约 `case_save_archive_plan` 写 `opinion` 是"承办律师分析与意见（常法卷为服务结果）"。按契约：常法卷第六项写"服务概况"、第七项写"服务结果"（填 `opinion`），第八项仍是"办案结果"（填 `result`）。
   - 立卷申请书模板文件名：Spec 写 `立卷申请书模板<_卷类>.docx`，原版民事行政卷叫 `立卷申请书模板.docx`、常法卷叫 `立卷申请书模板_常法卷.docx`。按先找 `立卷申请书模板_<卷类>.docx`，民事行政卷再认 `立卷申请书模板.docx`。
6. **律所模板没到位，填写规则是照原版写的、用仿造的模板测的**：结案报告按段落标签（"："前的文字）填：标签是"案情简介 / 分析与意见 / 服务概况 / 服务结果"的整段换成方案里的内容；其余段落里的【…】按标签填；认不出的原样留并提示。立卷申请书按原版第七步（找"金助理系统"那段、表格 0 第一列是编号）。真模板到位后需要再核一次。
7. **立卷申请书临时版式的措辞是我拟的**（"本人承办的（编号+委托人）案件已办结，符合归档条件，现申请立卷归档。归档材料如下："、签字行），律所模板到位后不再用。律所名称取 `references\特殊情况说明模板.md` 里的"广东连越（深圳）律师事务所"。
8. **`ignored` 里 `~$`、`._` 文件的 name**：这两类不进材料清单、没有材料名，写相对案件根目录的路径（如 `03一审/我方文件/~$起诉状.docx`）。契约 `ignored.reason` 的"工作区或成果"现在不会出现（匹配只看原件区）。
9. **`folder` 字段**：契约写"所在的第一层文件夹名"，照做（`03一审/我方证据/送货单.pdf` → `03一审`）；规则 3 判断"所在文件夹只对应一项"时用的是完整上级目录（`03一审/我方证据`），目录里的 `folders` 包含它本身及其子文件夹。
10. **`citation_passed`**：归档文件没有出处可核，取本任务 `result.json` 的核对结果（AI 保存的"归档核对表"在同一任务里），没有算 false——与 T15 修订版同口径。索引只收 md / docx，`卷宗.pdf`、`发票.pdf` 不登记（契约 `format` 只有 md、docx）；条目标题是归档文件夹名，版本是 1 或 `-vN` 的 N。
11. **读不了的材料**：导入时没通过的（`failed`：加密、读不了、有外链；`source_deleted`）生成时**不碰原件**，跳过并在 `manual` 和 `归档目录.md` 里写明（第一轮复核 P1-1 前只给了保存方案时的提醒、生成照样转换，已改）；能导入但 pypdf 打不开的 PDF 同样跳过写明。一项的材料全被跳过时，这一项不算已归档：申请书、归档目录不列为已归档，必交的计入缺失并生成情况说明（P3-4）。转换程序都不可用则按 Spec 整次失败。
12. **文件夹名**：委托人、对方当事人里 Windows 不许的字符换成 `_`，各取前 40 字。
13. **STSong-Light**：是 Adobe 的中文 CID 字体名，reportlab 只在 PDF 里写字体名、**不嵌入字体文件**，不涉及字体文件分发和许可；显示由阅读器用自带或系统的中文字体替代（本机只核了 pypdf 取文字正常；各阅读器的显示效果没有逐一看过）。若金助理要求 PDF 嵌入全部字体，再改成嵌入一套可分发的字体（候定）。
