## 6. 自检与遗留、偏离、模糊条款

**待主编排定夺：**

1. **"高"档取值与 Spec 8.2 不一致**。Spec 8.2 表："思考：低 / 中 / 高 → `reasoning_effort: "low" / "medium" / "high"`"。6000D 实测返回：`400: Unexpected reasoning effort high. Supported types are xhigh (default), medium, and low.` 我在补丁里把界面"高"映射为 `xhigh`（`reasoningEfforts.high: xhigh`），高档由此可用。请确认并修订 Spec 8.2（流水线列的 `"high"` 同样会被拒）。另外网关把 `xhigh` 标为默认，不带 `reasoning_effort` 时的行为可能等同最高档，这和 G-7（思考三档是否有差异）有关。
2. **P-12 是 Spec 3.2 没有列的源码修改**。桌面端 Host（`apps/desktop-host/src/index.ts`）在补丁行之外直接挂载 Office Skill 和 `load_workspace_dependencies` 工具，配置补丁关不掉。不改就违反 Spec 3.1 工具白名单和 Spec 10.1。我按最小改动去掉了这个挂载，请确认是否记入 Spec 3.2。
3. **P-03a 是临时修改**。关掉 `deepseek-account` 后，官方欢迎窗口读取账号状态失败，桌面端进不了工作区。我让它按"未登录"处理。这个问题 P-3 换成我方首次配置页时会整体消失，这里只是先保证 T4 能跑通。
4. **应用数据目录**。Spec 没给出 `<应用数据>` 的具体位置。`documentsDirectory` 暂用 `%LOCALAPPDATA%\lawbench\dsh-documents`，实测默认工作区建在这个目录下，没有建在"文档"里。请确认应用数据目录的正式位置。
5. **Skill 目录**。preset 的 `customSkillDirs` 取 `LAWBENCH_SKILLS_DIR` 环境变量（开发期指向仓库 `skills\`，打包后应指向 `<安装目录>\skills`）和 `%ProgramData%\lawbench\skills`。Spec 10.1 写的是 `%ProgramData%\<产品名>\skills`，产品名暂用 `lawbench`。
