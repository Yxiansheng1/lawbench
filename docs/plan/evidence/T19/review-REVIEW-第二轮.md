测试缺口：作者的测试样本是 LibreOffice 从 docx 转出的 `.doc`，它总会在 Data 流里单字节存一份地址，所以现有测试仅靠 Data 流那一条检查就能通过，域代码正则这条路径没有被任何测试单独验证过。

NOTE：

1. **工作目录路径太长时 LibreOffice 会崩溃。** 配置目录路径 146 个字符时崩溃（退出码 `0xC0000409`，无输出），115 个字符时正常。真实的 `%TEMP%` 约 50 个字符不受影响。崩溃时提示的是"文件可能已损坏或加密"，属误导。复核员在深路径下跑测试，9 项 LibreOffice 用例因此失败；换到短路径后 38 passed、1 skipped。
2. **Calc 导入 xlsx 或 fods 时会取外链图片**，工具写入的那套配置拦不住。小工具的 Calc 输入只有 `.xls`，本卡不受影响；但工作台导入 xlsx 很可能会碰到。建议交主编排。
3. 外链检查把整个文件读进内存，200MB 文件峰值约 400MB。
4. `olefile` 是 BSD 许可；`tools\README.md` 和打包清单没写这个依赖。
5. 一项界面测试在全量运行时被跳过，单独跑通过。

### 关于这种检查方法的局限（上候 owner 清单）

"查到就拒绝"是主编排上一轮定的。这一轮证明第一版实现能被绕过，修法明确。但复核员同时指出：这是对二进制文件做模式匹配，还有两种写法（碎片表拆分、图形属性引用）按代码走查会漏判，只是没造出样本、没证实能联网。

主编排的判断：修掉已证实的绕法，把未证实的列为已知残留风险，上候 owner 清单由用户决定要不要上更重的手段（例如用系统防火墙禁止转换程序联网，或者不支持旧版 `.doc` 的转换）。

**止损线**：下一轮复核如果又找到**实测能联网**的绕法，不再发第三次返修令，改为小工具不转换 `.doc` 和 `.wps`（提示律师用 Word 或 WPS 另存为 docx），上候 owner 清单。
