## 6. 自检、遗留与模糊条款

**不依赖打印机（按 OWNER 件要求写在这里）**
- 用的程序：LibreOffice 26.8.0.3（`C:\Program Files\LibreOffice\program\soffice.exe`，查找顺序第 4 步命中）、pandoc 3.11（`%LOCALAPPDATA%\Pandoc\pandoc.exe`）、Pillow。小工具不调用 Word / WPS。
- 耗时（`conversion-timing.txt`，本开发机）：LibreOffice 的四种转换每次 6.7–8.3 秒（每次新建配置目录）；pandoc 与 Pillow 的转换 0.1–0.5 秒。每次转换后没有残留的 `soffice.exe` / `soffice.bin` / `pandoc.exe` 进程。
- 弹窗：没有出现。但要说明：本机**当前**的默认打印机是本地虚拟打印机（端口类型 `MSFT_LocalPrinterPort`，驱动为 PDF / XPS 一类），不是连不上的网络打印机，所以 OWNER 件说的场景在本机此刻没能复现；按规矩我没有改系统默认打印机。LibreOffice 以 `--headless` 运行，不走打印接口；即使卡住，也在 120 秒时按进程号结束本次启动的整棵进程树（`taskkill /PID <pid> /T /F`），不动别的 LibreOffice。要在默认打印机为网络打印机的机器上实测一次，归 T21 的人工操作单和 T22。

**Spec 没写明、我采用的做法**
- (a) 最长空白段不止一个时，取靠近 H 的那个（段数少）。原文："选其中最长的一段，在中间切开。"
- (b) 硬切后，结果列表把"此处可能切到文字"标在**被硬切的那一段**上（即切口在它下边界）。
- (c) wps 的转换测试用 LibreOffice 转出的 .doc 改扩展名代替（WPS 文字的 .wps 与 .doc 同为 OLE 复合文档，LibreOffice 按内容识别）；本机没有 WPS，真 .wps 文件没测过。
- (d) 图片 → PDF 是一张图一个 PDF（多页 TIFF 每页一页）；没有做"多张图合成一个 PDF"。原文只写"图片 → PDF：Pillow"。
- (e) Word → Markdown 用 pandoc 的 GFM 输出，不提取图片（不写 media 文件夹）。

**遗留**
- "已安装客户端的内置路径"：产品安装目录名和包内布局要等 T20 定，现在 `finder.py` 按 `%LOCALAPPDATA%\Programs\{lawbench,律师工作台}\resources\{libreoffice\program\soffice.exe, pandoc\pandoc.exe}` 找，T20 定了以后改 `CLIENT_DIR_NAMES` 和路径即可。
- PyInstaller 打包、"没有客户端时自带一份"的打包布局在 T20。

### 7.1 返修二：.doc 外链图片"查到就拒绝转换"（依据 `致C-ORCH-执行令-doc外链裁决及T21续跑缺陷-20260929-2106.md` 第 2 节，Spec 14.3）

测试 36 → 39 项，39 passed，已没有 xfail（`pytest.txt`）。红测见 `red-test-rework2.txt`：关掉检查后，拒绝类测试失败。

- 新增 `tools\convert\extlinks.py`：`.doc`、`.wps` 交给 LibreOffice 之前先检查外链，查到就不调用 LibreOffice，返回中文原因："文档里有指向外部地址的图片或链接，为避免联网没有转换；请在 Word 或 WPS 里断开链接（或另存为 docx）后再试"。检查三类：
  - **OLE 复合文档的正文流**：找链接类域代码 INCLUDEPICTURE、INCLUDETEXT、LINK、IMPORT、DDE、DDEAUTO，后面紧跟以 `http://`、`https://`、`ftp://`、`file://` 开头的目标或 UNC 路径（`\` 开头）的。UTF-16LE 和单字节两种编码都查。
  - **Data 流**：出现单字节存放的上述地址前缀。实测链接图片的路径在这里以单字节存放；普通超链接的地址在这里是 UTF-16，所以不看 UTF-16，否则超链接会被误拒。
  - **不是 OLE 格式的 `.doc` / `.wps`**（可能是改了扩展名的 RTF 或 HTML）：文件里出现上述任何地址前缀就拒绝。
- **会误拒的情形**（宁可误拒）：
  - 改了扩展名的 RTF / HTML 文档里只要有网址（哪怕是普通超链接）就会被拒。
  - Data 流里以单字节存放的其他地址，例如指向 UNC 路径的超链接，也可能被拒。
  - 用 OLE 格式正常保存的 `.doc`，正文里的网址文字和 HYPERLINK 超链接不会被拒，有测试覆盖。
- 测试：
  - `test_doc_with_external_image_rejected_without_fetch`（替换原 xfail）：`.doc` / `.wps` 转 docx、转 PDF 都被拒，监听收到 0 次请求，原文件哈希不变，不留"转换结果"文件夹。
  - `test_doc_with_hyperlink_and_plain_url_still_converts`：正例，带超链接和网址文字的 `.doc` 照常转换，不联网。
  - `test_disguised_rtf_doc_with_remote_image_rejected`：改了扩展名的 RTF / HTML 被拒。
  - `test_xls_external_references_do_not_fetch`：`.xls` 里的外部工作簿引用、WEBSERVICE、HYPERLINK 转换时不发请求（Calc 链接设为不更新已经够用），所以 `.xls` 不加拒绝规则。

**主编排注记里的三个疑点，自查结论**
1. `LOCALAPPDATA` 为空时，`profile_root()` 退回 `<TEMP>\lawbench\lo\`，启动清理只删这个目录下超过 10 分钟的子目录。这个目录是本工具专用的，放不进别的程序的东西。测试里：清理测试把 `profile_root` 指到测试目录；其余测试不调用启动清理（只有界面的 `main()` 调用）；配置目录测试把 `LOCALAPPDATA` 指到测试目录。所以跑测试不会清理真实目录下的东西。
2. 长路径前缀：UNC 已按 `\?\UNC\…` 拼接（见 P2-1）。文件名末尾带点或空格：加了 `\?\` 前缀后 Windows 不再自动去掉末尾的点和空格。不过在资源管理器或文件选择框里正常选到的文件，名字本身就不会以点或空格结尾（Windows 不允许这样命名），`resolve()` 得到的也是规范名，所以实际不会遇到。只有用 `\?\` 这类手段刻意造出来的文件才会有这个问题，本版不处理。
3. 深路径测试和普通测试结束后，真实系统临时目录里没有留下 `lbt-*`：测试失败时 fixture 的收尾照样执行，实测为 0 个。测试进程被强行结束时可能留下，所以在测试 `conftest.py` 加了开跑前清理：删掉超过 10 分钟的 `lbt-*` 顶层目录，不跟随链接。实测放一个旧的 `lbt-*` 目录后开跑，它被清掉了。

**两个小工具窗口同时开的情况（主编排注记要求写明推理）**：每个窗口启动时都会清理 `%LOCALAPPDATA%\lawbench\lo\` 下**超过 10 分钟**的配置目录。一次转换最长 120 秒（超时即结束 LibreOffice 并删配置目录），之后配置目录立即删除（删不掉会提示）。所以另一个窗口正在用的配置目录，建立时间一定不超过约 2 分钟，远小于 10 分钟，不会被误删。工作台服务（线 B 的 T5）的配置目录在 `<应用数据>\临时\lo\`，是另一个位置，互不影响。
