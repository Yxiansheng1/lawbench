### 一、问题清单

**P3-a（T3，范围内）：整份文档被 `$ref` 引用的地方，"拒绝控制字符"不生效；交付说明第 14 节有一句写错了**
- 原因：`contracts._Validator` 是在 2020-12 校验器上扩展出来的。校验沿 `$ref` 进到一个带 `"$schema"` 的整份文档时，jsonschema 4.26 会改用普通的 `Draft202012Validator`，扩展的检查就丢了。
- 影响：
  - 所有整份文件的校验（pointer 为 `""`，比如 index.json、settings.json、capsules.json）都没有收严。交付说明那句"响应、落盘文件同一个校验器，也一并收严"不对。
  - 两个请求的契约同样漏过：`PUT /api/capsules`（各种 id）和 `PUT /api/settings`（地址）。
  - 不过这两个请求实测都被服务自己的检查挡住了，返回 `INVALID_ARGUMENT`，眼下找不到实际后果。
- 证据：
  - `contracts.errors("files/material_index.schema.json","",<rel_path 结尾加\n>)` → 0 条错误
  - settings 文件里 URL 加 NUL → 0 条
  - `api/capsules.schema.json#/$defs/request` 的 group id 加 `\n` → 0 条
  - `common.schema.json#/$defs/rel_path` 加 `\n` → 1 条
- 最小修法（二选一）：
  - 建 registry 时去掉各份契约的 `$schema`（显式用 DRAFT202012 规范）；
  - 或者让 `_Validator` 注册成 2020-12 的对应类。
  - 另补一条用例：capsules 请求或文件级 schema 带结尾换行。
  - 改正交付说明那句话。

**P3-b（T3，本次引入）：Windows 文件名允许的字符，现在被 `rel_path` 拒绝**
- 说明：`rel_path` 带 pattern，现在会拒绝 DEL（0x7F）和 C1（0x80–0x9F）字符。Windows 文件名允许这些字符（Win32 只禁 0x00–0x1F）。
- 影响：
  - 原件区里有这种文件名时，开发和测试模式下 `GET /api/materials` 返回 500（校验返回时失败）；生产模式正常。
  - 生产模式下，`/api/materials/import` 的 `target` 如果是这种文件夹名，会被拒。
  - 场景少见，可能来自乱码文件名。
- 证据（`probe4.txt`、`probe4b.txt`）：文件名 `a\x7fb.txt`、`借\x85条.txt` 能扫描成功、能写进 index；开发模式列表 500，生产模式列表 200。
- 最小修法：交主编排定，二选一：
  - `_CONTROL` 只拦 `\x00-\x1f`，`\x7f-\x9f` 不拦；
  - 或者对 `rel_path` 单独放行。

**P3-c（T10，范围内，很窄）："只用中文数字写时不比对"的豁免，漏核了只写年份的情形**
- 现象：所标位置写的是阿拉伯数字年份，同时有中文金额，比如原文"2025年收到人民币捌万元整"；草稿写"2024年收到"，结果 `passed=True`。
- 原因：`citations._chinese_only` 的金额分支把"年2025"这类只写年份的值排除在"阿拉伯数字"之外，又被中文金额触发了豁免。
- 这违反了执行令的口径："同处有阿拉伯数字照常核"。写了月份的（"2024年3月"）照常报 C。
- 最小修法：`v.startswith("年")` 时单独判断：同处有"年Y"就不豁免。
- 证据：`probe1.txt` 的 cn6、cn7。

**NOTE（交主编排知悉，不阻断）**
- 一处出处引了两个位置、其中一个只有中文数字时，整条值都不核了（另一个位置的阿拉伯数字写错也不报）。证据：cn4。
- 『』不算引号：只在 `squash` 里统一了，没进 `QUOTE`。所以『』里的错引语不核，『』里的评价词会报 G。执行令只点名了‘’和＂，这条在范围外。证据：3-3c、3-3d。
- P2-2 的两个边角，都仍然 `passed=False`，不是漏报：
  - 一处出处里有两个〔年份〕时，E 的 citation 只截到〔京政发〔2024〕；
  - 正文里有没闭合的〔、后面又跟文号时，会误报 E。
  - 证据：2c、2g。
- 独立后续（第一轮就有，不是本次引入）：Skill 说明文件 `SKILL.md` 不是 UTF-8 时，`skill_kind` 抛 `UnicodeDecodeError`。而 `save_draft` 是先写草稿文件、后做核对，结果会返回 INTERNAL，留下一个 result.json 里没有记录的草稿文件。
