## 与 T5 的接缝（1221 注记要求单列）

1. **T5 重解析后再合并**：T5 的 `Materials._scan` 在材料文本格式版本升级、或环境类原因重试时，原件没变也会重新解析并用 `render()` 重写材料文本，扫描页退回"（本页需识别）"，`is_ocr` 置 `none`（`materials.py` `_scan` 里 refresh / retry 分支）。处理：识别结果单独存在 `工作区\材料\识别页\<材料编号>\<页号>.md`，作为唯一主本；`Materials` 加属性 `after_render`，由识别队列挂上 `merge.remerge_after_scan`，`_scan` 在重写文本之后、保存 index 之前（已持该案件的材料锁）对本次重写过的材料调用，按原件当前 sha256 把已完成页合并回去并改 index 条目。用例 `test_reparse_after_format_bump_keeps_ocr_text`。
2. **过期标记在重新识别后清除**：T5 的 `_stale_ocr` 原来是"有任何一个已完成页的任务的版本不等于原件当前 sha256 就算过期"，原件改过后即使对新版本重新识别了，旧任务还在，就永远显示过期。改为：有旧版本任务、并且没有当前版本的已完成任务，才算过期。用例 `test_stale_flag_cleared_after_reocr`。
3. **pdfium 锁**：`ingest\__init__.py` 加 `PDFIUM_LOCK`，`ingest\pdf.py` 的 `parse` 与 `ocr
ender.py` 的渲染共用（pdfium 不是线程安全的；识别的两个发送线程渲染时，若同时有扫描在解析 PDF，会在本地代码里崩溃）。

## 偏离与需要主编排知道的

1. **"识别完成"事件**：服务没有任何事件推送通道（只有一问一答的 `/api/*`）。现在"识别完成"体现在任务列表 `status=done / partial_failed`，界面轮询 `GET /api/ocr/jobs` 见到后发系统通知（不带案件名、材料名），服务端另记一条元数据日志。要不要单开事件接口，请主编排随 T13 / T26 定。
2. **暂停原因只用 `prep_down`**：服务分不清"律师电脑断网"和"395 停机"（两者都是连不上 395；要分清得再去探别的服务器），所以连不上一律记 `prep_down`（界面显示"等待 395 恢复"），`offline` 暂未使用。两者恢复方式相同（每 30 秒探测）。
3. **`key_invalid` 暂停后的恢复**（1323 注记要改）：Key 由 Host 的凭据插件直接写进 Windows 凭据管理器（Spec 8.1、D9），`PUT /api/settings` 里没有 Key，服务看不到"写入新 Key"这一下。所以两条路都做、不改契约：① 有任务因 Key 暂停时，探测线程每 30 秒读一次凭据管理器（本机读，不联网），与出 401 时那把 Key 的指纹（只在内存比）不同就恢复；本机原来没 Key、后来设了也算；② 保存设置（`PUT /api/settings`）时也把这些任务放回排队（第二轮返修后：请求线程只做一个标记，探测线程 1 秒内动库），Key 若仍无效，发一页后再次暂停。用例：`test_key_change_resumes_key_invalid_job`、`test_no_key_then_key_set_resumes`、`test_settings_save_resumes_key_invalid_job`。
4. **原件在提交后被改过**：每个任务在本进程里第一次发送前核一次原件 sha256，与提交时不同就把剩余页标失败"原件已改动，请重新提交识别"，不拿新内容冒充旧版本的结果。
5. **图文混排页**被提交识别时，识别结果整页替换本机提取的文字（该页标"识别所得"）。
6. **改了 T5 的代码三处**：见上一节"与 T5 的接缝"。
7. 预计时间 `estimated_minutes` 按 G-5 实测（并发 2 约 6 页 / 分钟）估算，至少 1 分钟。
8. 一台电脑一位律师，所以"每位律师同时 2 页"实现为全局 2 路。
9. Spec 7.4（6000D 临时接管识别）没有做：Spec 标"待 G-5 之后决定"，设置里的 `ocr_fallback_llm` 默认关，本卡未接。

## 遗留

- **连不上 395 一律记 `prep_down`**（偏离②，1323 注记接受、写为已知限制）：服务分不清律师电脑断网和 395 停机，界面都显示"等待 395 恢复"，`offline` 暂未使用；两种情况恢复方式相同（每 30 秒探测）。

- **被暂停的任务取消后，`_bad_key` 不清空**（第二轮复核 NOTE 3，主编排定记为已知限制）：探测线程照旧每 30 秒读一次凭据管理器，直到 Key 变了为止；本机读、不联网，代价可忽略。
- **证据缺口**（1737 令定不做）：真实盘满（结果文件和 case.db 都写不进）没有实测，只模拟了写文件失败；`case_open` 与任务收尾的竞争没有复现（已在 `_next` 里兜住：已结束的任务出内存）。
- 同一页被反复提交识别时，`识别页\<材料编号>\<页号>.md` 只留最后一次的结果（合并时也取最近的任务），旧结果不保留。
- 395 的模型在水印页重复输出（T11 已知），识别所得的文本会很长；材料文本照实合并，不截断。

## 补：一处用例的上限写错（12:1x 那次没复现的失败）
