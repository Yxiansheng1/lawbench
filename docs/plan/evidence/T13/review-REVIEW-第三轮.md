### 活性说明
- **等待点**：防抖 500 ms；写入间隔最多 1.1 秒；写入和查询共用一个串行队列；每 3 秒轮询一次；Host 请求 30 秒超时。
- **触发条件**：补写只在"查到最后写的那张被取走"时发生，而被取走一定需要一条消息。轮询不会触发轮询，写入也不会触发轮询，所以**不会互相触发成循环**。每条消息最多多写 1 张；每次重启或重载，每个挂上的会话最多多写 1 张。
- **有界性**：轮询没有"上一次还没回来就先不发"的保护。服务卡住时，每 3 秒排进一次查询，每次要等 30 秒超时，也就是每 30 秒积压大约 10 个，排在后面的写入会被拖慢。积压只持续到服务恢复为止，有界。建议加一个在途标志，归独立后续。
- 任务单数量没有上界（A4）。

- **出处文字经过哪些函数**：`onClick` → `citationAt`（用契约正则匹配，按顿号切开，按空格切出材料名和位置）→ `resolveCitation`（和材料列表的名字做 `===` 比对，位置只用固定的正则 `^第(\d+)(?:-(\d+))?([页段行])$` 解析）→ `openTab(TABS.source, { material_id: 来自服务的编号, citation: '〔…〕' })` → `source.tsx` 调 `/api/source`，由 Host 按契约校验后发给本机服务。一路上**没有**拼进路径、URL、选择器、正则，没有 innerHTML、eval、`new Function`。说明文字经 `notice` 以 React 文字渲染。
- **正则耗时**：10 种恶意输入，每种 5 万到 26 万字，包括大量顿号、只有左括号、叹号前全是空格、1 万个合法出处等，全部在 **8 ms 以内**。没有灾难性回溯。
- **材料名匹配**：精确相等，所以
  - 前缀不会开错：`借款合同补充` 不会打开 `借款合同补充协议`；
  - 大小写、全角半角不同的不认；
  - 名字里带 `/` 的相对路径形式可以打开（契约允许）；
  - `../../x` 当作普通名字，找不到就提示；
  - 空格已由线 B 换成下划线（`materials.py:75`），`委托_合同` 能打开；
  - 同名多份时不打开，给提示。
- **捕获阶段监听**：只有命中出处时才 `preventDefault` + `stopPropagation`（`:80-81`），不是出处就完全不干预。DSH 的链接、按钮在跳过范围内。右键不产生 click 事件，不受影响。拖选时选区不是折叠状态，直接返回（`:67`），不会误开。
- **只看助手回答块**：用户消息、原文查看、wiki 建议里出现同样写法，点了不反应（代码层面）。回答还在流式输出时，按当时已显示的文字认；括号没闭合就不认。
- **没有新增外连**：`ui\` 里 fetch、XMLHttpRequest、WebSocket、EventSource、外部 href/src、window.open 都是 0 处（只有原有的 `data:` 图片）。新构建出的 `lib\client.js` 里 URL 和这些关键字都是 0。点击新增的调用只有本机的 `materialsList`，不写日志；Host 日志仍只记方法名、成败、耗时。
