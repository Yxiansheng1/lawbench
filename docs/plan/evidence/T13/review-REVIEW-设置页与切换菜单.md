## 复核员原文## T13 复核结论（line-A `53e2356`、`89c7cf6`、`8dc72d8`，父提交 `fb6246b`）

上一轮的 P1、P3 都已关闭，设置页、切换菜单、去掉"（非办案）"也都核过，没有问题。但这次新加的"关窗口拦截"引入一个新的退出问题：设置里有没保存的修改时退出程序，程序退不掉，留在后台看不见。结论 **AMEND**。

### 问题

**P1｜本次引入的回归｜范围内阻断：有未保存的设置时退出，程序变成看不见的僵尸进程**
- **问题**：`dsh-ext\ui\settings-draft.ts` 的 `installUnloadGuard` 在页面 `beforeunload` 里拦下关闭。DSH 主进程退出时走 `finishQuit`（`dsh\apps\desktop\src\main.ts` 1113–1128 行），顺序是：先藏起主窗口、销毁托盘图标、关掉 Host，最后才调 `app.quit()`。这时页面拦下关闭，整个退出就被取消。
- **影响**：程序进程还在，窗口是藏着的，托盘没了，Host 也关了。"修改尚未保存"的确认框弹在藏起的窗口里，律师看不到。即使看到了点"保存"，Host 已关，`putSettings` 会失败；代码遇到失败直接 `return`，没有任何提示，窗口也不关。
- **怎么会碰上**：
  - 改了设置，直接点窗口右上角的 ×。DSH 主进程收到 `close` 就藏窗口，不会触发 `beforeunload`，所以这时不问，草稿还是"有修改"。之后从托盘退出就中招。
  - 离开设置时选了"取消"，草稿一直是"有修改"，之后退出也中招。
- **证据**：
  - 读了 DSH 源码：主窗口 `close` 事件里 `preventDefault` 然后藏窗口（971–980 行）；`finishQuit` 的顺序如上。
  - 用本机 Electron 44 写了最小复现：页面先有一次真实点击，然后藏窗口、调 `app.quit()`。
    - 不加拦截：依次触发 before-quit → will-quit → quit，正常退出。
    - 加同样的拦截（`preventDefault` 加 `returnValue=''`）：触发 before-quit 和 `will-prevent-unload` 后，4 秒后进程仍在，打印 `STILL_ALIVE windows=1 visible=false`。
  - 没在完整的 DSH 桌面端上复现。
- **另外**：自报的"关窗口拦下"，点 × 时其实不会发生（窗口只是藏起来，草稿留在内存里，倒也不丢）。
- **最小修法**：去掉 `beforeunload` 拦截，改成 `beforeunload` 时不拦、只把草稿丢掉或照常放行。点 × 本来只是藏窗口，内存里的草稿不会丢。若一定要在退出前问，得接 DSH 的 `quitConfirmation`，在主进程那一侧问，不能在页面里拦。补一例："有修改时 beforeunload 不阻止退出"。

**P2｜范围内：选"取消"后在 Windows 桌面端打不开设置**
- **问题**：`reopenSettings()` 在页面上模拟按下 Ctrl+,。但 DSH 在 Windows 桌面端，可改键的快捷键（包括 `settings.open`）只认原生键盘通道：`shortcuts\src\client\index.ts` 第 70–71 行传 `native = true`，`dom.ts` 第 87 行遇到 `native` 就 `return`。模拟出来的按键不会打开设置。
- **影响**：交付说明里"'取消'用 Ctrl+, 重新打开设置"在真机上不成立。律师点了"取消"，人还是到了别的页面。草稿还在，下次进设置能看到修改，所以不丢数据。
- **证据**：上面几处 DSH 源码的静态阅读，没上真机。
- **最小修法**：调 DSH 快捷键注册表的 invoke（`settings.open`），或者 DSH 设置的 open 动作。做不到的话，把"取消"的说法改成"修改留着，下次打开设置还在"。

**P3｜独立后续：Host 新方法 `pathState` 的输入没收紧，同步调用会卡**
- **它接受什么**：任意绝对路径，文件也算"在"。UNC 路径（`\\服务器\共享`）也接受，会发起 SMB 访问。仓库里别处的 Host 方法（`archive-plan.ts`、`task-answer.ts`）用 `/^[\\/]{2}/` 拒掉 UNC，这里没有照做。
- **风险等级**：低。
  - 调用方只有我方界面，传进去的是 DSH 工作区列表里的路径。只回"在 / 不在"一个布尔值，不读内容，不写日志。
  - 能利用它的前提是界面渲染进程已被攻破，而那时现有的 `caseOpen` 等方法已经能做更多。
- **另一个问题**：用的是同步的 `existsSync`。旧位置如果在掉线的网络盘上，会把 Host 卡住到 SMB 超时为止。
- **建议**：限定只查 DSH 已登记的工作区路径，或者拒掉 UNC、`\\?\`、`\\.\` 开头的路径；改用带超时的异步 `stat`。

**P3｜测试没覆盖新代码**
- `ui\index.tsx` 里 `forgetCaseWorkspace` 的"先问 `pathState`、确实不在才撤"这道关，以及 Host 的 `pathState` 本身，作者的用例都没有直接覆盖。
- 证据：变异 M2（不问 `pathState` 直接撤）作者全套 601 项照样全过，只有我自己写的实验用例能抓到。
