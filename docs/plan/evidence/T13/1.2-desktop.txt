# 契约 1.2 输入区任务单：桌面端核对（开发模式，假工作台服务按 1.2 语义；临时假 Key 测后已清掉，演示目录已删）

步骤与读到的输入区状态（CDP 读渲染进程；"状态行"是输入区自己那一行）：
1. 打开案件的新会话，输入区挂上：胶囊"自由对话"，状态行"自由对话"。假服务收到 GET /api/task/current。
2. 选胶囊"合同审查"：0.1 秒时状态行"正在保存选择…"；1.6 秒时"下一条消息按「合同审查」运行（直到你改掉）"。假服务收到 POST /api/task。截图 1.2-01。
3. 重载渲染进程（模拟插件重载；Host 和假服务不重启），回到这个会话：胶囊仍是"合同审查"，状态行"下一条消息按「合同审查」运行（直到你改掉）"，是从 GET /api/task/current 读回的，不是本地记的。截图 1.2-02。
   （契约 1.1 下这一步会回到自由对话，之后约 1.6 秒内发出去却按残留的旧单跑，复核 R5。）
4. 发一条消息（假服务后面没有模型，这一轮以"处理失败"结束）：假服务依次收到 /core/task/begin、/core/context、/core/task/end，紧接着 GET /api/task/current（一轮结束后重读）；胶囊仍是"合同审查"。

假服务调用记录摘录（只有元数据）：
  POST /api/task                       （选胶囊后写入）
  GET  /api/task/current               （重载后回到会话时读）
  POST /core/task/begin → /core/context → /core/task/end
  GET  /api/task/current               （一轮结束后重读，task/end 之后 27 毫秒）

没在桌面端做：写入失败、读失败、写到一半又改、同一案件两个会话交替等，由 tests\dock.spec.ts 在 jsdom 里渲染真实的输入区组件、接按 1.2 语义写的内存服务逐条覆盖（1.2-dock-test.txt）。
