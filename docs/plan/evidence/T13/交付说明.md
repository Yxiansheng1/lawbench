## 1. 做了什么

**Host 插件（`dsh-ext\host\`）**
- `/api/*` 调用层（Q6）：25 个远程方法，由路由表 `dsh-ext\shared\api-routes.ts` 生成。方法名是契约文件名的驼峰；`capsules`、`wiki_suggestions` 一个文件两个 HTTP 方法，加 `get` / `put` / `post` 前缀；`settings`、`connection_test` 沿用 T7 的 `getSettings`、`putSettings`、`testConnection`。
  - 每次调用都按契约校验请求和**完整返回**。请求不合格返回 `INVALID_ARGUMENT`，不发出。返回不合格返回 `INTERNAL`，日志只记方法名和错误条数。服务的失败原样带回错误码和中文提示。
  - T7 沿用的 `getSettings`、`putSettings`、`testConnection` 返修后也按契约校验返回（P3-3），不合契约抛中文错误（沿用 T7 的约定）。
  - 都不抛出，界面按错误码决定显示什么。
  - 日志只记方法名、成败、错误码、耗时。
- `listSkills()`（Q4）：读 Skill 目录里 `SKILL.md` 的头部，按 `frontmatter.schema.json` 校验，并检查正文六部分，按 `skill_manifest.py` 的写法解析必问问题。
  - 目录顺序与服务一致，管理员目录在前，同名以先读到的为准。
  - 目录经 `legal-host` 行的新配置项 `skillDirs` 传入，写法与 preset 的 `customSkillDirs` 相同。
- `importPastedImage()`（Q3②）：只收 PNG / JPEG，最大 20 MB。
  - 存到 `<应用数据>\临时\粘贴\`，用绝对路径调 `/api/materials/import`，`target` 为 `02案件材料/粘贴图片`。
  - 不论成败都删临时文件；启动时清掉残留。
  - Host 不直接写案件文件夹。
- 方法表 `dsh-ext\shared\remote-methods.ts`：Host 和界面共用。`tests\remote-methods.spec.ts` 守着两边的方法名和形参名一致，做过变异验证（Q1）。

**凭据插件**：Key 写入 / 删除后发 `credentials/reference-updated`，授权记录变化时发 `credentials/record-updated`（P3-7）。
- DSH 的模型选择（`ui-model-selection/src/client/service.ts:53-56`）监听这两个事件，会自动刷新模型目录。
- 写入报错（含超时）也发，因为实际可能已写成。监听方出错不影响写入。

**界面插件 `legal-ui`（`dsh-ext\ui\`，Q1、Q2）**：先 `ctx.remote.$mount` 手写的 lawbench 描述，再 `ctx.inject(['remote.lawbench', …])` 取子上下文，写法同 DSH 实验插件 voice-input。
- 各块分别 inject，某个 DSH 服务不在时只缺那一块。
- **首页**（`main` 页面，侧栏"首页"，启动时显示）：分流提示、两级胶囊、管理胶囊、最近案件、新建 / 打开案件、案件卡片拖入导入。
- **胶囊管理**：拖动排序（同组、跨组、分组）、改名、隐藏 / 显示、新增、恢复默认（先确认），没有删除；保存前按 Spec 10.3 的规则先拦一遍。

- **右侧栏三个标签**：材料、成果、原文查看，内容见勾选表。
- **输入区上方**（`conversation.input.dock`）：胶囊 / Skill 选择、必问问题、参数、选用的前序成果。选择一变就写任务单（防抖 0.5 秒）；自由对话且没选前序成果时不写。

- **弹框**（`shell.overlay`）：确认框、提示框、导入确认框、选择案件框。
- **P-5 的我方一半**（`ui\intake.ts`）：导入钩子，等 DSH 补丁提供 `conversationFileIntake` 服务后生效（见第 5 节）。

**其他**

## 8. 桌面端实测中发现并修掉的问题

1. **Host 插件整个没起来**：打进 `lib\host.js` 的 yaml 是 CommonJS，会 `require('process')`，纯 ESM 里没有 `require`。桌面端 Host 加载失败只表现为 `fiberPhase: null`，没有日志；用 Host 进程的调试口定位到的。`node -e` 是 CommonJS 环境，掩盖了这个问题。修法：构建给 ESM 产物补 `createRequire` 垫片，并在构建后用纯 ESM 进程逐个导入检查。
2. **远程返回多一层**：DSH 客户端把远程返回包成 `{ok, value}`，界面加了剥层（有单测）。
3. **拖入被 DSH 当成聊天附件**：DSH 在 `document` 上监听拖入（`ui-attachment/src/client/drop-events.ts:75-78`），拖到材料面板的文件同时被存进 `$DSH_HOME\attachments`。修法：我方拖入处理 `stopPropagation`；测试产生的两个 1 字节虚构文件已删，附件目录复查为空（`attachments-dir-before-after.txt`）。
4. **成果标签无限重渲染**（React #185）：状态选择器每次返回新数组。已改为稳定引用。
