## 8. 纪律判据

1. **契约**：接口和共用数据格式以 `contracts\` 为准。改契约 = 改 `contracts\_build\gen_schemas.py` 并运行 + 升 `contracts\VERSION` + 在 `docs\src\Spec.md` 第 20.12 节记一行 + 主编排同意；开发会话不得私自增减字段。
2. **合并权归主编排**：线 A/B/C 只在自己的分支提交；每张工单完成后把交付说明写进 `docs\plan\evidence\T<n>\交付说明.md`（提交 SHA、证据路径、偏离、遗留），随分支提交；各线不改工单集文件本身（三个工作目录各有一份副本，各改各的会在合并时冲突）。主编排复核后合并到 `main`，并在 `main` 上的工单集该卡"交付说明"一栏填这个文件的路径、回填五门格；各线每次开工前 `git rebase main`。
3. **提交信息**：`T<n>: <做了什么>`，一张工单可以多个提交。
4. **证据**：每张工单的测试输出、截图、抓包等放 `docs\plan\evidence\T<n>\`；五门格只填这些文件的路径。
5. **复核分级**：只改测试、文档或读侧一两行 → 主编排亲自核；产品代码或库函数 → 主编排派复核员，按八项清单（契约一致、边界输入、错误路径、日志不含正文、路径闸门未被绕过、无外连、测试覆盖新代码、无机密入库），单次复核不超过四小时；高风险卡 T3、T17、T25、T26 → `/senior-review` 双人复核（`PROJECT-PROFILE.md` 第 6 节）。
6. **机密与案卷**：`.env.local` 不提交；仓库中不放任何真实案卷，测试一律用 `tests\fixtures\` 下的虚构材料；日志只记元数据（Spec 4.5）。
7. **产品不外连**：产品代码中只允许访问配置里的 6000D（所内 `192.168.8.77:8000`、所外 `10.126.126.1:8000`）、395（所内 `192.168.8.124:9000`、所外 `10.126.126.3:9000`）和 `127.0.0.1`（Spec 14.3、15）；开发工具（pnpm、pip、git）联网不受此限。
8. **文档**：改 `docs\src\*.md` 后运行 `python scripts\build_docs.py` 重新生成 HTML，两者一起提交；不直接改 HTML。
9. **engines\**：律所提供的工具原样使用，不改代码；确需改动先交主编排决定，并记入该目录的 `CHANGELOG.md`。
10. **Skill**：改 `skills\` 后运行 `python skills\_scripts\build_skills.py --root skills` 和 `python contracts\check_examples.py --skills skills`，都通过才能提交。
11. **Windows**：命令一律按 PowerShell 写；路径用反斜杠；中文文件名在 git 中需 `core.quotepath false`（已设）。
12. **模糊条款**：工单或 Spec 写得模糊处，不自行拍板，摘录原文写进该卡的 `docs\plan\evidence\T<n>\交付说明.md` 并通知主编排，由主编排决定或上候 owner 清单。
