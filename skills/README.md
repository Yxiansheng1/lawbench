# skills\ 目录说明（给开发和测试的人看，不给模型看）

每个业务 Skill 一个目录：`<skill>\SKILL.md`（Spec 10.2），流水线 Skill 另有 `流水线提示词.md`。共用规则只改 `_shared\共用规则.md`，再运行 `python skills\_scripts\build_skills.py --root skills` 同步进各 SKILL.md；首页胶囊只改 `capsules.default.json`。

## 测试集 `<skill>\tests\`（Spec 10.2、F-SKILL-05）

- 至少 4 个样本目录（`样本01-<简称>` …）和一份 `要点.md`。全部虚构（规矩同 `tests\fixtures\README.md`）；律所真实样本到位后替换。
- **文件名以 `_` 开头的不作为案件材料导入**，其余文件按文件名（去扩展名）作为材料导入：
  - `_任务说明.md`：律师在对话里的请求（见下）。
  - `_上游成果-<成果名>.md`：上一步 Skill 的成果，测试时选作前序成果（L1 任务输入）。
  - `_已有成果-<成果名>.md`：案件里已有的成果（legal-workflow 用来模拟进度）。
  - `_L0案件卡片.md`：模拟注入的 L0 案件卡片。
- **`_任务说明.md` 的写法固定**：第一行 `# 任务说明`；分隔线 `---` 以上是律师原话，**只把这一段交给模型**；分隔线以下以"以下为测试说明，不给模型看。"开头，写必问项哪些该请确认、哪些该提问，测试员扮演律师时怎么答，样本派生自哪里，导入时的特殊处理。不要把测试说明用括号夹在律师原话里。
- `要点.md`：开头"测试要点（不给模型看）"；每个样本一节，表 `| # | 要点 | 关键出处 | 判分要求 |`、扣分项、"必问检查："一行；格式参照 `tests\fixtures\wiki-test\大卷宗\评测\标准答案.md`。
- 样本材料是 .md/.txt，用【第N页】【第N段】【表:名】标记模拟 PDF、Word、Excel；T18 实测时由测试工具先转成 docx/pdf 再导入（主编排 2026-10-02 裁定）：每个【第N页】块强制分页并核页数，每个【第N段】块一个 Word 段落（块内换行用段内换行），表格段转 Word 表格，转完用 `case_read_material` 读回核标记序列。没有标记的 .txt 按行定位，原样导入。
