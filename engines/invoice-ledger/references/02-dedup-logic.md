# 判重逻辑、状态机、退出码与硬门禁

## 判重与冲突判定（3.1.0 起拆分为两类）

**核心认知**：后五位可能撞号，**20 位全号才是唯一权威**。但"全号命中"只说明**是同一张发票**，
不说明**关键字段一致**——因此必须把「重复」与「冲突」拆开：

- **重复**：同一张发票的冗余记录，关键字段（金额、日期）**一致** → 无需裁定，留痕即可
- **冲突**：同一标识指向**互相矛盾**的记录 → 必须人工裁定，**不得静默丢弃**

实现：`invoice_db.classify_incoming()`（**纯函数**，本表的唯一事实源；改判定须改函数并同步本表）。

| # | 情形 | 判定 | 冲突类型 | 主表 | 冲突记录表 |
|---|------|------|---------|------|-----------|
| A | 全号命中，金额与日期**均一致** | `dup` | 重复 | 不写入 | `status=已归档` |
| B | 全号命中，金额或日期**不一致** | **`conflict`** | 冲突 | **不写入** | `status=待裁` |
| C | 无全号，三维（后五位＋金额＋日期）命中 | `dup` | 重复(低置信) | 不写入 | `status=已归档` |
| D | 有全号但未命中，三维命中且**全号不同** | **`conflict`** | 冲突 | **不写入** | `status=待裁` |
| E | 均未命中 | `new` | — | **写入** | — |

```
输入新发票（PDF/图片/Excel）
    ↓
提取 (发票全号, 后五位, 金额, 开票日期, 类别)
    ↓
【空键保护】后五位为空 且 全号为空 → 不入库 → 待人工清单，exit 2
【OCR保护】OCR 未提取到 20 位全号 → 不入库 → ⚠OCR待人工，exit 2
【依赖保护】缺 pdfplumber → 中止（exit 1），不得混入"字段提取失败"
    ↓
classify_incoming(...) → new / dup / conflict
    ├─ new      → 追加主表，状态 = 未报（负金额 → 红冲）
    ├─ dup      → 不写主表；冲突记录表留痕（status=已归档）
    └─ conflict → 不写主表；冲突记录表登记（status=待裁），exit 2
```

### 为什么 B、D 必须独立成"冲突"（原实现的问题）

| 情形 | 原实现 | 后果 | 现行为 |
|---|---|---|---|
| B 全号命中但金额/日期不一致 | 当普通重复**静默跳过**（全号命中即不看金额日期）| **金额是报销依据，矛盾被无声掩盖** | 入冲突记录表 `待裁`，exit 2 |
| D 全号未命中但三维命中、全号不同 | 直接**新增入库** | 台账某行缺全号或全号有误时，同一张发票以两个全号各占一行 | 入冲突记录表 `待裁`，exit 2 |
| C 三维命中 | 跳过并标"低置信" | 保留 | 同左（"低置信"只是**提示**，不等于确证）|

### 冲突记录表（与主表同文件）

- 工作表名 `冲突记录`，**建在主表之后**；15 列，字段见 `invoice_db.CONFLICT_HEADERS`
- **append-only**：既有冲突行不得减少（I1 同样适用于本表）
- 与主表**共用同一个 Workbook、同一次 `wb.save()`** → 两表同写同不写
- **跨运行去重**：同 `(全号|文件名, 冲突类型)` 只登记**首次**；重复导入同一目录不会让本表虚增，
  已知项只在当次运行报告里列出
- 读取接口：`_load_conflicts()`；`report` 输出「冲突记录：待裁 N 条 / 已归档 M 条」

### 全号构成（两种发票排版，均归一到 20 位）

| 排版 | 原文 | 全号取法 |
|---|---|---|
| 数电票（单段）| `发票号码：26000000000000000001` | 直接取 |
| **老式票（两段）** | `发票代码：144032609110` ＋ `发票号码：11611829` | **拼接** 12＋8 ＝ 20 位 |

> **2026-09-17 修复**：`extract_fields` 原先只取 `发票号码` 标签的值，遇老式票会得到 **8 位"全号"**，
> 与台账 20 位全号对不上 → 被判为「冲突」（假冲突）。实测某一历史批次中有 **1 张**属此类。
> 已补「发票代码 + 发票号码」拼接逻辑（仅当拼接后恰为 20 位时启用）。
>
> 复现方式：`python -c "..."` 见任务 T010 `tmp/final_virtual_run.py`；**改提取逻辑时必须回归该批**。

## 状态机白名单

**当前由代码实际写入主表的「状态」值**（实测核对，勿凭文档想象）：

| 状态 | 由谁写入 |
|---|---|
| `未报` | `import` 新增行（默认） |
| `红冲` | `import` 检测到负金额 |
| `⚠OCR待人工` | `import` 走 OCR 路径但未取得全号 |
| `已报` | `mark-reimbursed --apply` |
| `冲突-待裁` | **`import` 检测到冲突时标记所涉主表行**（3.5.0 起）|
| `已取代` | **`resolve-conflict --decision 采纳新值`**：原行置此态留痕 |
| `重复-剔除` | **`resolve-conflict --decision 剔除`**：判定该行为重复记录 |

> **3.5.0 之前**后三态只有声明、无写入路径（"预留"）。现由 `resolve-conflict` 打通：
> 冲突在**检测时**就把所涉主表行标为 `冲突-待裁`（金额暂不计入合计），裁定后按决定落为
> `已取代` / `重复-剔除` / 还原原状态三者之一。
> 三者**均不计入金额合计**（`EXCLUDED_FROM_TOTAL`）。

```
允许的迁移：
  未报 → 已报          （mark-reimbursed --apply）
  未报 → 红冲          （导入检测负金额）
  任意态 → 冲突-待裁    （import 检测到冲突，所涉主表行）
  冲突-待裁 → 原状态    （resolve-conflict --decision 维持台账）
  冲突-待裁 → 已取代    （resolve-conflict --decision 采纳新值；另追加更正行）
  冲突-待裁 → 重复-剔除 （resolve-conflict --decision 剔除）

禁止的迁移（代码硬校验）：
  已报 → 未报          （仅 --force 可覆盖）
  红冲 → 已报          （红冲不参与报销）
  ⚠OCR待人工 → 已报     （需人工确认后手动改）
```

**裁定闭环**：`resolve-conflict` 是唯一能把 `冲突-待裁` 落地为正式状态的入口；
默认 dry-run，`--apply` 才写盘。「采纳新值」采用**追加新行**而非就地改值 —— 就地改会改变
既有全号，触发 I1「全号集合只增不减」断言；`已取代` ＋ 追加正是为此设计的路径。
配合 `_build_index` 的**优先取未退休行**规则，裁定后重复导入不会再误判冲突。

**mark-reimbursed 行为**：仅对状态=`未报` 的行生效；红冲/重复/OCR/冲突 行即使批次名匹配也跳过并单独列出。

## 退出码契约

| 码 | 含义 | 触发 |
|----|------|------|
| 0 | 完全成功，无异常 | — |
| 1 | 致命错误，**未开始或无法继续** | 路径不存在、模板不匹配、写入失败、对账失败、**必需依赖缺失**、环境包指纹不符、参数非法 |
| 2 | 存在需人工关注的数据事项 | 重复、**冲突**、待人工、解析失败、OCR 未就绪、部分文件未完成 |

> 规则：**必需依赖（含 winsdk）缺 → 1；Windows 中文 OCR 语言功能缺失或识别失败 → 待人工 → 2。** 不新增码。

## 汇总单/内部目录过滤规则

导入扫描时**跳过**：
- 文件名含 `汇总单`（票根 汇总单(票据/行程).pdf 非发票）
- 文件名含 `PDF合并`
- 路径段含 `_raw_decoded` / `_chrome` / `_` 前缀目录 / `已分类`

## 附：磁盘「同号重复」的常态释义（2026-09-18 实测）

对 4 个发票堆放根实测：**337 个 PDF 仅 197 个唯一全号**。重复的常态是**同一张票在多个阶段目录各存一份**：

```
发票PDF_20260701-0804\<来源>\<原始名>              ← 下载原件
发票PDF_已分类_20260807\<序号>-<类别> <金额> <代码>.pdf   ← 已分类重命名
发票PDF_补充下载_20260708-0807\<来源>\...            ← 补下载再落一份
2026年X月报销\X月第N批\...                          ← 最终归档
```

另：票根通行费**汇总单的 `(票据)` 版与 `(行程)` 版同号**（同一张票的两个视图），
两版金额可能不同（行程版为单程明细、票据版为总额）。

> **判定要点**：`dedupe_check` 报出的"同号重复"**默认按堆放重复理解**；
> 只有当**台账内**出现同号多行、或同一目录内出现同号且金额/日期不一致时，才需按重复报销深查。
> 本次实测：**台账内同号重复 = 0 组**。
