# 06 · 不变量与检查表

> **用途**：本技能的一切改动，在提交前必须按本文两张检查表过一遍。
> **适用时机**：新增脚本、修改写盘/改名/移动逻辑、调整识别规则、调整退出码。
> **定位**：不是建议清单，是**门禁**。任一条不成立即不得交付。

---

## 一、四条不变量（Invarables）

### I1 增量性

**定义**：台账写入行数 ≥ 读取行数（除显式 `reason` 的裁定性变更）；读入行的**全号集合 ⊆ 写出行的全号集合**。

| 项 | 内容 |
|---|---|
| 守护位置 | `invoice_db._append_ledger` / `_replace_ledger` 出口断言 |
| 违反后果 | 静默丢数据（覆盖、丢列、丢行） |
| 检查方法 | 人为构造"写入行数 < 读取行数"，断言必须触发 |
| 已知反例 | `cmd_init` 原以模板全集覆盖（v2.1.0 前）；`_save_ledger` 按 9 列重建会丢 HEADERS 之外的列 |

### I2 回读性

**定义**：任何写盘／改名／移动／展开之后，必须**回读磁盘**比对，不得只信内存对象。

| 项 | 内容 |
|---|---|
| 守护位置 | `_save_ledger` 写后重开校验；`invoice_renamer` 重命名后回读文件名；`runtime_cache.ensure_runtime` 展开后校验清单哈希、全部文件和依赖；`archive_files` 移动后校验大小一致 |
| 违反后果 | 报告与磁盘不一致（报告说改了，磁盘没改） |
| 检查方法 | 制造失败（目标已存在 / 文件被锁），报告必须反映真实状态 |
| 已知反例 | `invoice_renamer` 汇总表只基于内存 `rename_map`，从不回读 |

### I3 失败传递

**定义**：任何未达成预期结果的分支必须影响**退出码或返回值**。只打印的失败不算失败。

| 项 | 内容 |
|---|---|
| 守护位置 | 所有 `except` 分支；子进程 returncode 透传（`_deps.run_in_env` / `invoke.py`） |
| 违反后果 | 上一层认为"成功"，错误被静默吞掉 |
| 检查方法 | 每个入口的退出码与直接调用一致；构造失败场景检查 exit code |
| 已知反例 | `invoice_renamer` 重命名失败仅打印 `[ERROR]`，不影响返回；`extract_fields` 的 `except Exception: return r` |

### I4 识别唯一性

**定义**：任何按特征选取输入或目标名的动作，必须保证**唯一性**，否则显式中止。

| 项 | 内容 |
|---|---|
| 守护位置 | `cmd_init` 模板判定；`archive_files` 源文件匹配；`update_manifest` 清单定位；`runtime_cache.guard` 解释器与环境包判定 |
| 违反后果 | 选错文件（且若是 move/覆盖则破坏性） |
| 检查方法 | 构造两个同样匹配的候选，必须中止而非取首个 |
| 已知反例 | `invoice_db.py:191` `hdr[:6] == HEADERS[:6]` 未定义排除域 → 台账可被当模板；`archive_files.py:121` `startswith(tool)` + `break` 取首个 |

## 二、六类漏洞检查表（C1–C6）

| 类 | 检查问题 | 不通过示例 |
|---|---|---|
| **C1 写入语义** | 写盘函数是否区分"追加"与"覆盖"？覆盖是否必须传 `reason`？ | 一个函数同时服务 `init`（传全集）与 `import`（传追加） |
| **C2 失败传递** | 每个 `except` 分支是否影响退出码/返回值？只打印的失败算不算失败？ | 重命名失败只 `print("[ERROR]")` |
| **C3 回读校验** | 写盘/改名后是否回读磁盘比对，而非只信内存对象？ | 汇总表基于内存对象生成 |
| **C4 输入识别** | 识别规则是否有**排除域**？能否把"技能自己"当成输入？ | 台账前 6 列与模板重叠 → 台账被当模板 |
| **C5 匹配唯一性** | 前缀/glob 匹配是否保证唯一？不唯一时是中止还是静默取首个？ | `glob("最终清单_*.tsv")` 取 mtime 最新 |
| **C6 破坏性前置** | `move`/`rename`/覆盖前是否检查目标是否存在、是否唯一？ | `mapping_archive` 直接 `shutil.move` 无重名保护 |

**改任何一处之前，逐条问一遍**：

| # | 问题 |
|---|---|

## 四、环境层专属规则

| 规则 | 内容 |
|---|---|
| 唯一解释器入口 | 业务脚本一律经当前环境包指纹对应的外部缓存解释器执行；宿主解释器启动时由 `_deps.guard` 自动接管 |
| 不回落宿主 | 技能内缺包即中止；补装来源唯一＝`vendor/env-win_amd64.zip` |
| 运行期不联网 | 联网仅发生在构建期（`build_env_zip.py`） |
| 来源校验 | `env.lock` 的 zip sha256 不符即中止，不静默重解 |
| 原子展开 | `env.tmp` → 校验 → `os.replace` 为 `env`；存在 `env.tmp` 即视为上次中断 |
| 豁免名单 | `build_env_zip.py`、`env_check.py` 不做自举（构建期/诊断期） |
| 绝对路径禁令 | `_pth` 内不得出现绝对路径（换机器即失效） |

## 四之二、阶段门禁（② 归档 / ③ 分类，批次 2 落地）

| 阶段 | 门禁 | 级别 | 失败动作 |
|---|---|---|---|
| ② 解码 | 解码结果非空（0 字节）| 硬 | **不落盘**，计入失败清单 |
| ② 解码 | 魔数校验 ∈ {ZIP, PDF} | 硬 | **不落盘**，计入失败清单 |
| ② 解码 | 原文件名安全化（只取末段，防路径穿越）| 硬 | 不落盘 |
| ② 解码 | 写后回读校验（存在且大小一致）| 硬（I2）| 计入失败清单 |
| ② 归档 | 目标重名 → 自动加序号；移动后回读校验大小 | 硬（I2/C6）| 告警并跳过该项 |
| ③ 分类 | **字段提取失败率 > 10%** | 硬 | **在重命名之前中止**（exit 1），不做任何改名／导出 |
| ③ 分类 | 文件名回验：分类／金额／代码后四位**三比对** | 硬 | **影响退出码**（exit 2）|
| ③ 分类 | 类别须在 14 类白名单内 | 硬 | 纳入文件名回验的"比对 1" |

**阈值常量**：`invoice_renamer.EXTRACT_FAIL_RATE_MAX = 0.10`

**为什么 ③ 的失败率门禁必须在重命名之前**——类别序号（`类别号-类内序号`）是按"类别分组 + 金额升序"
算出来的。若输入有一成以上未解析成功，序号会**整体排错**，而文件名**已经被写进磁盘**；
事后发现也只能逐个手工改回。这里 fail-fast 是唯一安全的选择。

**为什么 ③ 的复查必须影响退出码**——复查是重新打开 PDF、与文件名逐项比对，
是"文件名 vs 内容"的**交叉验证**。只打印不传递（原实现）等于把交叉验证降级成日志。

**退出码语义统一**：失败率 ≤10% 的部分失败属"需人工关注" → `2`（原实现为 `1`）。
`1` 只保留给"无法继续"（参数错误、阈值超限、必需依赖缺失）。

## 五、退出码契约

| 码 | 含义 | 触发 |
|---|---|---|
| `0` | 完全成功 | — |
| `1` | 致命错误，未开始或无法继续 | **必需依赖缺失**、环境包指纹不符、展开失败、参数非法 |
| `2` | 存在需人工关注的数据事项 | 重复、冲突、待人工、OCR 未就绪、部分文件未完成 |

> 规则：**必需依赖（含 winsdk）缺 → 1；Windows 中文 OCR 语言功能缺失或识别失败 → 待人工 → 2。** 不新增码。

## 六、台账六级检测与复核（批次 3 落地）

### 6.1 六级检测（`check-schema`，**只读**）

| 级 | 检测 | 处置 | 退出码影响 |
|---|---|---|---|
| 1 | 可达性（存在／可打开／非同步锁）| 硬：中文提示并退出 | `1` |
| 2 | 结构（表头漂移）| **提示确认**：逐列列出"标准 vs 实际"，不做修改、不静默拒绝 | `2` |
| 3 | 可解析性（必填列空值／金额／日期格式）| 硬 + 报告（列行号）| `2` |
| 4 | 内部冗余互推（文件名反推 vs 台账）| **标单行 + 报待人工** | `2` |
| 5 | 业务规则（全号 20 位／类别白名单／金额符号）| 硬 | `2` |
| 6 | 双向对账（台账文件名 ↔ 归档目录）| 必做但需 `--archive <根>`；>30s 提示缩小范围 | `2` |

- 第 4 级**刻意不比后五位**：文件名格式 2 的 4 位数字是「发票代码后四位」，与后五位语义不同（见 01）
- 第 6 级用**文件名**对账（不解析 PDF）→ 实测 163 文件耗时 0.0s，无需降级为开关；
  但归档根必须显式给出（台账的批次可能分散在多个目录，无法可靠推断）
- 结果同时落 `_日志/台账体检_<时间戳>.txt`（保留最近 10）；**主表保持 9 列，不加列**（3.4）
- **I2 硬约束**：体检前后台账字节数必须一致，不一致即 `1`

### 6.2 复核（`review`，只读台账，仅向 `_日志/` 追加）

**必查项（全查，无抽样）**：OCR 路径／裁定态行（`冲突-待裁`·`已取代`）／冲突表 `待裁`／红冲／
金额离群／冲突表低置信判重。

**金额离群口径（经实测标定）**：**按类别分组**取 `Q3 + 3×IQR`（Tukey 远端）。

| 备选口径 | 实测命中（233 行）| 结论 |
|---|---|---|
| 全局 median×3 | 命中率约 28% | **不可用**——各类别金额分布异质，全局阈值失效 |
| 分组 median×3 | 命中率约 19% | 偏多 |
| **分组 Q3+3×IQR** | **命中率约 5.6%** | **采用** |

> **离群 ≠ 错误**：类别粒度粗（差旅费同时含通行费与机票/住宿），被标出的行应理解为
> "值得看一眼"，须回看原始凭证再判断，**不得据此直接改数据**。

**抽样**：必查项之外的行按 `--sample-rate`（默认 5%）随机抽取，`seed=20260917` 固定 → 结果可复现；
必查项盖住的行不重复抽样。

**复核分工（4.3）**

| 层级 | 内容 | 执行人 |
|---|---|---|
| L1 自动断言 | 全部硬门禁 | 机器，零人工 |
| L2 交叉校验 | 冗余互推、双向对账、幂等 | 机器，零人工 |
| L3-a 阅读性确认 | 表头漂移确认、dry-run 报告过目、对账差异浏览、抽样项 | **可交助理** |
| L3-b 裁定性动作 | `冲突-待裁` 处理、红冲/剔除、金额离群裁定、残留文件删除 | **律师本人** |

> 分界原则：**凡"改台账状态"的一律律师本人；凡"只看不写"的可下放。**

**留痕**：每次生成清单向 `_日志/复核记录.md` **追加**一行（append-only，含时间／范围／总行数／
必查项数／抽样数／执行安排），清单全文另存 `_日志/复核清单_<范围>_<时间戳>.md`。
