# 邮箱适配与当前能力

当前可执行入口为workflow.py的只读IMAP及EML适配，见[完整收集流程](10-collection-and-paper.md)。IMAP授权码仅在用户本机终端交互输入；使用BODY.PEEK及只读邮箱，不主动标记已读。

QQ邮箱或其他服务的主机地址、IMAP开放状态、认证方式、可达历史范围应在实际接入时核实。本次用户选择暂不连接真实邮箱，因此没有完成真实账号验收。

旧版WorkBuddy QQ连接器曾记录GetMe/ListMessages/GetMessage/ListAttachments/DownloadAttachment等工具调用经验。当前环境没有该连接器，历史记录不能证明现在有这些工具，也不能把某次一个月窗口、10次/分钟限流或读取即已读当成当前固定限制。

如在其他环境使用连接器：先核实权限及读取副作用，完整遍历分页，保留邮件ID与附件ID；大附件返回的工具落盘路径只有在文件实际存在且可解码时才认定下载成功。不得直接忽略所有Error。

正文发票链接与附件同时收集；自动下载失败保留原因，登录/验证码/多按钮页面交由已登录浏览器处理，再用workflow.py attach绑定下载结果。只搜带附件邮件会漏掉正文链接。

用户最新反馈MCP仅支持近一个月：接入时优先核查这一限制及窗口计算方式，记录请求范围、实际可达范围和未覆盖区间。暂不可验证时明确标注用户报告/待验证，不承诺下载更早邮件。报销年月与搜索日期分开确认，不能用近一个月直接推定本期报销月份。见[年月与历史票安排](11-period-and-history.md)。

## 3.9.2 实测补充（本机真实账号验证，仅作判别方法，不含任何账号数据）

### 一、"连接器已授权"不等于"工具可用"

曾出现用户认定"连接器已接通"、但代理侧完全无工具的情况。按以下四条逐项核验，**全部通过才算可用**：

1. **会话连接器状态**：本会话注入的连接器清单里是否列出该连接器；
2. **工具索引**：`mcp__qq-mail` 命名空间下是否有工具条目（为空即为未装载）；对具体工具名做一次精确查找应能命中；
3. **运行时配置** `~/.workbuddy/connectors/<uuid>/mcp.json`：`connector:qq-mail` 是否带 `"disabled": true`（可用的连接器不带该标记）；
4. **连接器状态文件** `connector-states.json` / `connector-states.v3.json`：`bound` / `enabled` / `userDisabled` 三项。

`bound:true, enabled:true` 只说明**授权在**；若第 2、3 条不通过，说明**运行时未激活**。处置：在连接器中心重新启用／Trust 后**重启客户端**，工具才会装载。**不得在工具未装载时改用其他接入方式，也不得宣称已下载。**

### 二、窗口判定：必须用探针，不能沿用"近一个月"的说法

用同一日期范围做两次对照查询即可判定窗口类型：① 请求范围内枚举到底（翻页至 `has_more=false`）；② 以**早于请求范围**的区间查询一次（或只给 `before` 不留 `after`）。若第②次返回**空集**，说明服务器不返回更早邮件，属**硬性滚动窗口**；若返回内容，则只是该区间恰好无邮件。记录最早可达邮件的实际时间戳作为窗口下限。"请求范围"永远不等于"已覆盖范围"。

### 三、限流与并发

实测限流为**每分钟个位数级**（`GetMe` 返回的 `rate_limits` 为准，并记录 `requests_per_hour`）。**宿主可能限制每轮只能执行一次工具调用**——批量下载前先实测能否并行投递，不能并行则须重新评估任务可行性，不要默认可以批量拉取。附件元数据（`ListAttachments`）与下载（`DownloadAttachment`）是两次调用，故 `附件数 × 2` 才是调用量下限。

### 四、附件内容的落盘形态（与"工具返回落盘路径"不同）

`DownloadAttachment` 返回的是 **base64 内联内容**（单张 PDF 常达 20 万字符量级）。当结果超出宿主单次结果上限时，宿主会**把结果原样落盘为文本文件**并只回报该文件路径。因此正确做法是：

1. 连续调用下载，接受"结果被落盘"的回报；
2. 用脚本扫描落盘目录（`…/tool-results/mcp-qq-mail-DownloadAttachment-*.txt`），解析 JSON 取 `data.content`，base64 解码后按 `data.filename` 写盘，并按 SHA-256 去重登记。

这样**大体积内容完全不进入上下文**。若结果体积较小而未被落盘，则该次内容会内联返回，须另行写盘，勿在对话中粘贴。

### 五、读取副作用

实测 `ListMessages` / `SearchMessages` / `ListAttachments` / `DownloadAttachment` **均不改变已读状态**。核验方法：以 `is_read=false` 过滤重查同一范围，确认已触碰过的邮件仍在未读集合内。**未成功下载的发票不得被标为已读**；SMTP 发送、删除类操作需用户逐次确认，不得自动执行。
