# 转码（编码）Bug 预防全清单

Windows + 坚果云 + 中文发票场景，编码是最大 BUG 源。以下为逐层设防清单（脚本已内置大部分，维护时勿回退）。

## 源码层

| 风险 | 预防 |
|------|------|
| Python 源码含中文，解释器以 GBK 读取 | 所有 .py 首行 `# -*- coding: utf-8 -*-`，文件以 UTF-8 无 BOM 保存 |
| Windows 控制台 GBK 输出中文乱码/报错 | 脚本入口统一 `sys.stdout.reconfigure(encoding='utf-8', errors='replace')`（Python 3.7+） |
| 正则中的中文被转义污染 | 正则以 `r'...'` 原始字符串书写 |

## 文件读写层

| 风险 | 预防 |
|------|------|
| open() 默认 GBK 读取 UTF-8 文件 | 所有文件读写显式 `encoding='utf-8'` |
| 报告文件 Excel 打开乱码 | 输出用 `utf-8-sig`（带 BOM） |
| 中文路径 + 空格 | 全程 `pathlib.Path`，禁止字符串拼接路径 |
| 坚果云路径格式 | Python 内用 `D:/...`，不用 bash 的 `/d/...`（os.walk 不认） |
| ZIP 内部文件名编码（GBK/CP437） | 仅按内容提取字段，不依赖 ZIP 内部文件名 |

## 数据处理层

| 风险 | 预防 |
|------|------|
| Excel 日期序列号 vs datetime vs 字符串 | `normalize_date()`：datetime→strftime；int/float→序列号换算；str→正则识别 |
| 金额字符串混 ¥ ￥ 逗号 | `replace('¥','').replace('￥','').replace(',','')` 后 `round(float,2)` |
| 全角/半角字符混用 | 正则统一 `[：:]`、`[￥¥]`、`[（()）]` 覆盖 |
| Excel 空单元格 | 统一 `str(c or '')`，不产生 None 传播 |
| 模板 F 列显示截断 | openpyxl 读单元格原始值（非打印显示值） |

## 正则层

| 风险 | 预防 |
|------|------|
| 全角冒号 `：` 与半角 `:` | `发票号码[：:]` |
| 金额符号变体 | `[\xa5￥¥]`（Unicode 码位覆盖） |
| "价税合计（小写）" 括号全半角 | `价税合计[（(]小写[)）]` |
| 多行排版（票根"发票号码："与数值分行） | 兜底 `(?<!\d)(\d{20})(?!\d)` 全文扫描 |
| 20 位数字误匹配非发票号 | 优先标签后匹配，兜底限边界 |

## 文件收集层（Windows 特有）

| 风险 | 预防 |
|------|------|
| `*.pdf` 与 `*.PDF` 在大小写不敏感文件系统上重叠 | 收集后按 `str(f.resolve()).lower()` 去重 |
| 目录遍历到内部目录 | 跳过 `_raw_decoded`、`_` 前缀、`已分类` |

## 幂等与写入安全

| 风险 | 预防 |
|------|------|
| 写坏台账（覆盖/半写） | 原子写：临时文件 → 校验非空 → `os.replace` |
| 覆盖后才发现备份失败 | 写前 `shutil.copy2` + 断言备份存在且 size>0 |
| Excel/坚果云占用导致保存失败 | 捕获 PermissionError → 中文提示 → exit 1（不静默） |
| 保存后数据漂移 | 写后重新读台账，行数一致才返回成功 |
