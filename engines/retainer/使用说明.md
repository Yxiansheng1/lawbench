# 离线诉讼委托材料工具 3.4.1

一、启动

将整个文件夹复制或解压到本地，双击“启动委托工作台.bat”。它会自动在后台启动识别引擎，并打开工作台页面——这是推荐用法。也可直接双击“启动.html”，此时不启用证件识别。

不要单独移动HTML；app、data、vendor目录是运行所需文件。

关于“自动启动引擎”：网页出于浏览器安全限制，无法自行启动本机程序，因此由上述 bat 代为完成，双击一次即可，不需要任何其他操作。首次启动引擎需要数秒；若引擎尚未就绪，页面会给出提示并在就绪后自动接上，无需刷新。不使用证件识别时，其余功能不依赖 Python，也无需启动任何服务。

二、录入与生成

1. 打开“标准案件录入.xlsx”，在“案件录入”表一行填写一个案件。示例表仅含虚构测试数据。
2. 页面导入Excel，选择工作表、表头行；确认字段映射，重复表头手动选择。也可直接新建案件录入。
3. 每次选择一个案件，核对案件类型、主体、收费方式、金额、阶段和补充信息，点击检查，再生成。
4. 下载单份Word或当前案件ZIP；选择完整案件目录会把文书归入“01委托手续”。支持目录写入的浏览器可选择本地目录保存；不支持时下载ZIP。

Excel可映射案件类型、主体类型、委托方、对方/当事人、案由/罪名、律师费、收费方式、阶段、法院、监管场所、法定代表人及职务。其他信息来自原模板，律所、律师、银行账户不作为案件Excel必填字段。文本编号请在Excel中设为文本以保留前导零。公式不计算，错误值或公式单元格会提示，需粘贴为值或在对应表单字段修正。

金额支持50000元、2.5万元、1,234.56元；半风险示例“前期2万+12.5%”。金额按整数分计算，多金额、分期、负金额、超过两位小数或含糊费率会被拒绝。刑事模板为固定收费。年份随本机日期，月份、日期和合同编号留待填写；所函按首个委托阶段处理。

三、证件识别（可选）

把身份证、营业执照、登记证书识别后填入案件字段。识别全程在本机完成，材料不会上传网络。

1. 用“启动委托工作台.bat”打开工作台，第“02”卡片会显示“本机识别引擎已就绪”。若显示未检测到引擎，说明引擎尚未就绪，页面每 3 秒自动重试，就绪后自行接上，无需刷新。
2. 把证件文件直接拖到“拖拽证件文件到此处”的虚线框内即可开始识别；也可以拖到页面任意位置，或点击“或点击选择文件”。支持 PNG、JPG/JPEG 等图片，以及 PDF、DOCX；可一次拖入多份（如身份证＋营业执照）。
3. 证件类型默认为“自动识别”，也可手工指定。识别结果按证件分块列出，可逐项修改；点“填入当前案件”写入委托方、法定代表人等字段。边框着色表示该字段经校验位自动修正（黄）或校验未通过（红）。
4. 识别结果仅作预填，生成文书前必须逐项核对。

识别时的补正验证：住址这类可能跨行的字段会自动把后续行拼接完整——例如身份证住址印成「江西省樟树市义成镇淖港村」与「碰塘组15附1号」两行时，取到的是完整地址而不是前一行。身份号码还会与住址所属省份、出生日期相互印证；住址缺少村组、门牌等末端信息时会提示可能未取全。这些提示只作提醒，不阻断使用，请以原件为准。

识别时的主体判定规则：

- **单位证照（营业执照、登记证书）绝不会被当作自然人**。证照上的“类型”为“有限责任公司/股份有限公司”等，判定为法人（确定）；为“合伙、个人独资、事务所、分支机构、合作社”等，提示属非法人组织或个人独资企业，签署人须按登记证书确认为负责人或执行事务合伙人。
- **身份证（姓名＋身份号码）通常为自然人委托**，主体类型填“个人”。
- **身份证上同时有单位盖章的，通常是该单位的法定代表人**。页面会自动勾选该判断（框内可取消），此时姓名填入“法定代表人”，委托方填单位名称。若同时提供了单位证照，还会交叉比对身份证姓名与证照法定代表人是否一致并给出提示。

说明：PDF 与 DOCX 中的文字直接读取，不使用识别，因而准确且更快；只有扫描件和图片才走识别。老版 .doc 需先在 WPS 或 Word 中另存为 .docx。加密 PDF 无法读取。识别质量受拍摄条件影响，真实证件照片的准确率可能低于规整扫描件。

四、模板维护

模板管理显示三类13份内置模板（个人委托 / 公司委托 / 刑事），检查完整性核对哈希和字段。可导入自定义占位符DOCX，未知字段显示文件及位置；恢复内置模板不需要外部源文件。字段字典在本地帮助中可查看。

合同的收费条款按「收费方式」字段自动注入第六条：固定收费、半风险（前期费用＋风险费用）、全风险（仅按回款金额计费）。金额示例：`50000元`（固定）、`前期2万+12.5%`（半风险）、`回款额的15%`（全风险）。刑事模板不含此机制，其收费条款保持模板原样。

“生成文书”卡片会显示当前模板组的份数与已选份数。模板组为“按案件自动选择”时，案件字段未填全会先按默认组显示，填全后自动匹配；若某组没有模板，该处会提示模板库现有份数，请在“模板管理”中检查或恢复内置模板。生成时若案件字段有问题，页面会滚动到顶部显示具体原因。

模板处理工具支持清理、注入、固定/半风险条款转换，显示修改前后和处理报告。先下载副本核对，校验通过后才可采纳到工作模板。清理合并相邻同格式纯文字片段并保留非文字元素。批量源模板重建按文件映射模板组和文书类型，缺少文件列入报告。原桌面源模板未提供，不能用恢复按钮创造原始源文件；可自行选择源DOCX或本工具导出的资源包。

五、保存与迁移

默认仅在内存处理，关闭页面不自动保存。主动开启“在这台电脑记住工作内容”后保存到当前浏览器存储；不同浏览器或不同路径可能不共享数据。存储失败会明确提示，此时下载工作包备份。恢复工作包后检查案件和模板；工作包含案件信息，是普通未加密本地ZIP。资源包只含模板、规则与配置，不含案件。版本或哈希不匹配会拒绝导入并保留原工作状态。清除本机记忆只清除本工具浏览器存储，不删除已下载文件。

六、离线与检查

所有运行资源随包提供，没有CDN、字体服务或统计接口。页面内容安全策略仅放行一个本机回环地址（http://127.0.0.1:17801，供可选的证件识别驱动使用），其余外部连接一律禁止；不启动驱动时该地址不会有任何流量。导入文件仅作ZIP/XML/JSON数据解析，检测外部资源关系、宏、活动内容和不安全路径。含此类内容的Office文件会被拒绝。运行“离线自检”使用虚构样例，结果可以查看与导出。

生成保留原模板XML格式；长姓名、长案由可能改变实际分页。使用人应在Word中核对排版、签署信息与授权内容。开发验收未完成实际Word渲染，详情见验收报告。

七、维护构建

普通资源维护通过HTML导入导出及高级配置编辑完成。维护者修改data/config.json或data/rules.json后，在根目录运行“go run tools/build.go”生成对应本地JS加载文件；改程序后更新版本、运行测试，使用Rust skill-craft-verify校验，再以Go skill-craft stamp和package构建。tests中的浏览器测试需要本地Playwright；parity_check.py仅用于旧Python版本对照，不是用户运行或构建依赖。
