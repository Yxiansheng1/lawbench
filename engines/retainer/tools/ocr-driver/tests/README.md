# 多轮 OCR 测试机制

用于针对各种特殊场景反复验证「识别 → 字段解析 → 修正」的效果，并防止修改引入退化。

## 一、设计原则

1. **输入固定**：语料一次生成（`make_corpus.py`）后不再变动，各轮输入完全一致，结果才可比较。
2. **分层度量**：行级、字段级、校验级、覆盖层分开统计，避免单一数字掩盖问题。
3. **轮次留档**：每轮写一份 `results/round-N.json`，含全部原始文本行，可回溯任一误识的现场。
4. **可对比**：`--diff N M` 直接列出两轮之间的用例级变化。
5. **全虚构**：语料由脚本生成，不含任何真实证件信息。

## 二、分层指标

| 层 | 指标 | 含义 |
| --- | --- | --- |
| L1 行级 | `totalLines`、`avgScore` | 识别到的文本行数与平均置信度 |
| L2 字段级 | `fieldAccuracy`、`fieldWrong`、`fieldMiss` | 字段准确率（键值均精确匹配才计对）、误识、漏取 |
| L3 校验级 | `codePassRate` | 统一社会信用代码、身份证号通过校验位的比例（含被算法修正的） |
| L4 覆盖层 | `requiredCompleteRate` | 关键字段齐全的用例比例 |

## 三、语料矩阵

10 种畸变 × 2 类证件 = 20 例：

| 变体 | 场景 |
| --- | --- |
| `clean` | 白底印刷体，正面平拍 |
| `rotate3` / `rotate-5` | 正向 / 反向旋转 |
| `blur` | 高斯模糊 |
| `noise` | 高斯噪点 σ=18 |
| `jpeg60` | JPEG 质量 60 |
| `lowres` | 降采样至 45% 再放大 |
| `shadow` | 单侧渐变阴影 |
| `scanbw` | 二值化，模拟复印件 |
| `lowcontrast` | 低对比度 |

证件：`business_license`（营业执照 6 字段）、`id_card_front`（身份证 6 字段）。

**待补充的真实场景**（当前缺失，需真实样本或更逼真合成）：
底纹与防伪图案、反光高光、透视畸变、手指遮挡、印章压字、竖排、繁体、生僻字、多证件同框。

## 四、用法

```bash
python make_corpus.py                      # 生成语料（只在需要重建时执行）
python run_round.py --label "基线"          # 跑一轮，自动编号
python run_round.py --label "改进邻近配对"
python run_round.py --only license-rotate3  # 只跑单个用例
python run_round.py --diff 1 2              # 对比两轮
```

结果：`results/round-N.json`（完整报告）、`_last_run.txt`（本轮摘要）。

## 五、修正与容错手段（`../fieldfix.py`）

| 手段 | 作用 | 对应场景 |
| --- | --- | --- |
| 视觉行重建 | 按 bbox 纵向重叠聚类，拼回被切碎的行 | 标签与值被切成碎片行 |
| 同行多标签切分 | 一行内按标签位置切段，各取其后的值 | `姓名 李四 性别 男 民族 汉` |
| 跨行配对 | 标签与值分处两行时取下一行 | 部分引擎的排版 |
| 全角/半角归一 | 全角数字字母转半角 | 全角排版 |
| 数字域混淆字修正 | `O→0`、`I→1`、`B→8` 等，**仅限代码类字段** | 号码类字段误识 |
| 校验位纠错 | 统一社会信用代码、身份证号：校验失败时做单位替换穷举，**唯一命中才修正** | 号码单字错 |
| 低置信度标记 | 低于阈值标为待人工确认，不静默采用 | 模糊、遮挡 |

姓名等非数字字段**禁止**做字符替换，以免把生僻字改错。

## 六、轮次推进的判定标准

一轮改动只有在同时满足以下条件时才算有效：

1. `fieldAccuracy` 不低于上一轮；
2. 没有任何用例从「通过」变为「未通过」；
3. `codePassRate` 不低于上一轮；
4. 新增的修正手段在报告中可见其触发记录（`status` 为 `fixed`）。

第 1 轮基线：字段准确率 1.0（120/120）、代码校验通过率 1.0、关键字段齐全率 1.0，
平均置信度 0.9865。**后续任何改动都不应使其下降。**

## 七、多格式验证（与多轮测试并列）

多轮测试针对「图像识别的质量」，多格式验证针对「格式装载的正确性」，两者互补。

```bash
python make_format_corpus.py    # 生成 8 个多格式用例（虚构内容）
python run_formats.py           # 逐格式验证并输出报告
```

语料与验证点：

| 用例 | 验证点 |
| --- | --- |
| `license.png` | 图片直接识别 |
| `license-q90.jpg` / `license-q70.jpeg` | 两种压缩质量；`.jpeg` 与 `.jpg` 视为同格式 |
| `license-text.pdf` | **有文本层 → 必须不走 OCR**，直接提取 |
| `license-scan.pdf` | 无文本层 → 渲染 200 DPI 后识别 |
| `license.docx` | 文字直接提取 + 内嵌图片单独识别 |
| `license-noext` | 扩展名缺失 → 按文件头嗅探 |
| `license-old.doc` | 无解析器 → **必须返回中文提示，不得静默失败** |

结果输出：`_last_format_run.txt`（可读报告）、`results/formats.json`（结构化）。

判定标准：每个用例的关键信息命中 3/3；`.doc` 与不支持的格式必须给出明确中文原因。
