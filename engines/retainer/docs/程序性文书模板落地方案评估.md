# 程序性文书模板落地方案评估

**评估日期**：2026-09-16
**评估对象**：将《民事诉讼高频程序性文书标准化模板清单》中的模板落到 retainer-offline 工作台（现行 3.4.1），要求模板集中于单独文件夹，且字段与工作台相匹配
**前置条件**：工作台 3.4.1 的 10 项缺陷已修复并回归通过（详见 `docs/验收报告-3.4.1.md`）

---

## 一、评估结论（先行）

1. **字段匹配度约六成**：程序性文书所需的基础要素（法院、委托方、对方、案由、阶段、年份、案件全称）全部可由工作台现有 19 个占位符直接提供；程序特有要素（案号、请求保全数额、财产线索、待证事实、请求事项内容）工作台没有对应字段，属逐案手填项。
2. **推荐方案**：模板以**独立文件夹**存放（顶层 `procedural-templates/`），字段设计上**只使用工作台已定义的占位符**，其余留统一下划线待填。此为**零代码改动**方案，不触碰工作台核心，风险最低。
3. **可选集成路径**：如希望由工作台直接生成，可将模板以“附加文书（extra）”身份导入现有模板组，同样**无需改代码**；但受现有分组逻辑限制，会与委托材料混组显示。
4. **不建议**的做法：为程序性文书新增案号、财产线索等工作台字段。这会触发 `validateConfig` 的“本版不支持增加案件字段”硬断言，需连带修改字段体系、规则引擎与界面分组，属结构性变更，应单独立项评估。

## 二、工作台字段与占位符能力清单

### （一）录入字段（12 项，与 Excel 表头一致）

| 字段键 | 名称 | 说明 |
|---|---|---|
| case_type | 案件类型 | 自动识别 / 民商事 / 刑事 |
| party_type | 主体类型 | 自动识别 / 个人 / 公司 |
| plaintiff | 委托方 | 必需 |
| defendant | 对方／当事人 | 必需 |
| cause | 案由／罪名 | 必需 |
| fee_desc | 律师费 | 必需，支持 `50000元` 等写法 |
| fee_type | 收费方式 | 自动识别 / 固定 / 半风险 / 全风险 |
| stage | 代理阶段 | 必需，顿号分隔多个阶段 |
| court | 管辖法院 | 可留空，留空时替换为 `______人民法院` |
| detention | 监管场所 | 可留空 |
| legal_rep | 法定代表人 | 可留空 |
| legal_rep_position | 法定代表人职务 | 可留空 |

### （二）占位符（19 个）

| 占位符 | 生成时的实际取值 |
|---|---|
| `{{PLAINTIFF}}` | 委托方全称 |
| `{{CLIENT}}` | 同委托方，用于模板中固定写“委托人”的场合 |
| `{{DEFENDANT}}` | 对方／当事人 |
| `{{CAUSE}}` | 案由，民事自动去掉尾部“纠纷”二字 |
| `{{CRIME}}` | 罪名，自动补“罪”字（刑事） |
| `{{DEFENDANT_CAUSE}}` | 对方名称加空格加案由，用于“甲方因与＿＿纠纷一案”句式 |
| `{{CASE_FULL}}` | 委托方与对方加案由的完整串 |
| `{{CASE_LABEL}}` | 案件简称，如“张三vs李四 买卖合同纠纷” |
| `{{STAGE}}` | 民事为阶段原文；刑事转为 ①②③ 序号串 |
| `{{FIRST_STAGE}}` | 首个阶段加“阶段”二字 |
| `{{STAGE_DESC}}` | 末个阶段加“终结”，侦查与审查起诉阶段加“阶段” |
| `{{YEAR}}` | 本机当前年份 |
| `{{COURT}}` | 管辖法院，留空时为 `______人民法院` |
| `{{DETENTION}}` | 监管场所，留空时为 `______看守所` |
| `{{LEGAL_REP}}` | 法定代表人，留空时为 `______` |
| `{{LEGAL_REP_POSITION}}` | 法定代表人职务，留空时为 `______` |
| `{{UPFRONT_FEE}}` | 律师费人民币大写 |
| `{{UPFRONT_FEE_SHORT}}` | 律师费小写数字（不含货币符号） |
| `{{RISK_RATE}}` | 风险费率文本，如“百分之十二点五（12.5%）” |

**硬约束**：模板中出现上述 19 个以外的占位符，导入时会被 `validateTemplate` 以“未知占位符”拒绝。因此程序性文书模板**只能用这 19 个**。

## 三、程序性文书的字段需求与匹配度

### （一）需求与匹配对照

| 程序性文书需要的要素 | 工作台是否提供 | 采用的占位符或处置 |
|---|---|---|
| 受文法院名称 | 提供 | `{{COURT}}` |
| 委托方（多作申请人） | 提供 | `{{PLAINTIFF}}` |
| 对方（多作被申请人） | 提供 | `{{DEFENDANT}}` |
| 案由 | 提供 | `{{CAUSE}}` |
| 代理阶段 | 提供 | `{{STAGE}}` 或 `{{FIRST_STAGE}}` |
| 年份 | 提供 | `{{YEAR}}` |
| 案件全称（用于当事人栏） | 提供 | `{{CASE_FULL}}` |
| 当事人与案由串（用于“因＿＿纠纷一案”） | 提供 | `{{DEFENDANT_CAUSE}}` |
| 案号 | **不提供** | 统一下划线待填，建议格式 `（{{YEAR}}）粤____民初____号` |
| 请求保全数额／标的额 | **不提供** | 下划线待填 |
| 财产线索（账号、权证号、车牌） | **不提供** | 附件清单形式，逐案手填 |
| 待证事实、证据名称（调查令） | **不提供** | 编号列表，逐案手填 |
| 请求事项具体内容 | **不提供** | 编号列表，逐案手填 |
| 代理律师姓名与执业证号 | **不提供** | 模板内预置律所信息，逐案核对 |
| 送达地址与联系方式 | **不提供** | 下划线待填 |

### （二）匹配度判断

可自动填充的要素共 8 项，集中在**当事人与案件标识**；需手填的要素共 7 项，集中在**程序进展与请求内容**。后者中，案号与担保方式随案件一次确定、同一案件内不再变化；财产线索与请求事项则须逐案撰写，本不适宜字段化。

因此字段匹配的合理目标是：**工作台负责主体信息，模板负责程序骨架，手填部分集中于两处**（请求事项与附件线索）。

## 四、文件夹方案

### （一）位置

建议置于工作台根目录下的**顶层独立文件夹**：

```
retainer-offline (2)/
├── 启动.html
├── app/                    运行层
├── data/                   数据层
├── resources/templates/    13 份委托材料模板（由 build 脚本管理，会被清空重建）
├── procedural-templates/   ← 新增：程序性文书模板，独立于构建流程
├── docs/
└── tests/
```

**不放在 `resources/` 下的原因**：`tools/build.go` 与 `tools/build.cjs` 会先执行删除操作、移除 `resources/templates` 目录后重建它。虽然该操作只作用于 `templates` 子目录，但把非构建产物放在构建管理目录内易生混淆。置于顶层可明确其“不受构建脚本管理”的属性。

### （二）内部结构

按功能分四类子目录，与模板清单的分类体系一致：

```
procedural-templates/
├── README.md                      使用说明与占位符对照表
├── A-程序启动与推进/
│   ├── A1 财产保全申请书.docx
│   ├── A2 律师调查令申请书.docx
│   ├── A3 律师调查令承诺书.docx
│   ├── A4 证据保全申请书.docx
│   ├── A5 先予执行申请书.docx
│   ├── A6 鉴定申请书.docx
│   ├── A7 延期举证申请书.docx
│   ├── A8 延期开庭申请书.docx
│   └── A9 证人出庭作证申请书.docx
├── B-诉的处分与当事人变更/
│   ├── B1 撤回起诉申请书.docx
│   ├── B2 撤回部分被告起诉申请书.docx
│   ├── B3 变更诉讼请求申请书.docx
│   ├── B4 新增诉讼请求申请书.docx
│   ├── B5 撤回部分诉讼请求申请书.docx
│   ├── B6 追加被告申请书.docx
│   └── B7 撤回上诉申请书.docx
├── C-保全配套与执行/
│   ├── C1 续行查封冻结申请书.docx
│   ├── C2 解除保全申请书.docx
│   ├── C3 保全复议申请书.docx
│   ├── C4 强制执行申请书.docx
│   ├── C5 追加被执行人申请书.docx
│   ├── C6 执行行为异议申请书.docx
│   └── C7 限制消费及失信名单申请书.docx
└── D-审级救济与程序障碍/
    ├── D1 管辖异议申请书.docx
    └── D2 回避申请书.docx
```

共 25 份。编号使文件名在资源管理器中自然按类别排序，且便于与模板清单的章节对应。

### （三）格式

采用 **DOCX**，版式与工作台现有模板一致（A4、标题黑体 22pt、正文仿宋 12pt、1.5 倍行距），理由有三：可直接提交法院；可直接用工作台“模板处理工具”的清理与注入功能处理；与现有模板的视觉风格统一。

同时保留一份 **Markdown 母版**（`procedural-templates/README.md` 内含通用母版），便于快速复制文字段落。

## 五、三种落地路径对比

| 项 | 方案 A　独立文件夹 | 方案 B　作为附加文书导入工作台 | 方案 C　扩展工作台字段 |
|---|---|---|---|
| 做法 | 模板存于 `procedural-templates/`，律师手工检索套用 | 以 `extra` 类型导入现有模板组，由工作台生成 | 在 config 与 rules 中新增案号、标的额、财产线索等字段 |
| 代码改动 | 无 | 无 | 需改 config.json、rules.json、core.js、ui.js、packages.js |
| 字段匹配 | 用现有占位符，其余手填 | 同方案 A | 全部字段化，可自动填充 |
| 自动化程度 | 手填两处后即可用 | 主体信息自动填充 | 除请求事项外全自动 |
| 风险 | 无 | 低。模板会与委托材料混在同一分组显示，生成时须核对勾选项 | 高。`validateConfig` 有“本版不支持增加案件字段”硬断言，需连带放开并重建字段体系 |
| 维护成本 | 模板文件独立维护 | 导入后存于浏览器存储，需随资源包导出备份 | 每次改字段都要跑构建与全量回归 |
| 适用判断 | 立即需要、以稳为先 | 希望减少重复录入 | 长期高频、值得投入改造 |

**推荐**：以方案 A 落地文件夹与模板文件，同时把方案 B 作为**可选操作**写入 `procedural-templates/README.md`，供需要时按步骤导入。方案 C 待案号等字段的使用频次得到验证后再单独立项。

## 六、模板字段设计要点

### （一）固定与手填的分界

每份模板按以下规则编写：

1. **可自动填充的部分**：受文法院、当事人、案由、阶段、年份，一律写占位符；
2. **逐案一次确定的**：案号、请求数额、担保方式，用连续下划线 `＿＿＿＿` 表示待填；
3. **逐案撰写的**：请求事项、财产线索、待证事实，用编号列表留空，由承办人填写。

### （二）案号的写法

案号建议写成 `（{{YEAR}}）粤＿＿＿＿民初＿＿＿＿号`。年份用占位符使模板在跨年度使用时自动更新，法院代字与序号手填。注意 `{{YEAR}}` 取的是本机当前年份，若需与立案年份一致，应在生成后人工核对。

### （三）同一模板跨主体复用

保全、续封、撤诉三类在个人与公司委托中通用，只换当事人称谓，无需拆分为两份模板。模板中统一使用“申请人”“被申请人”，在首部信息栏标注“（本案原告／被告／第三人）”由承办人圈选。

### （四）承诺书的特殊处理

律师调查令使用承诺书为**九项固定条款**，属完全可固定文书，正文不得删改，仅替换当事人信息与案由案号。建议直接采用《广东省高级人民法院、广东省司法厅关于在民事诉讼中实行律师调查令的规定》（粤高法〔2020〕34 号）附件 4 的原文，不另行自拟。

## 七、实施注意事项与风险

1. **占位符越界即被拒**。模板若写入 19 个占位符以外的标记，导入工作台时会被拒绝。新增任何占位符都意味着方案 C。
2. **不要用 `{{UPFRONT_FEE}}` 表达请求保全数额**。该占位符的取值是律师费大写金额，与保全标的额无关，混用会导致错误填充。保全数额应留空手填。
3. **`{{CAUSE}}` 会自动去掉尾部的“纠纷”二字**。程序性文书的案由表述若需完整案由，应自行补字，例如写成“{{CAUSE}}纠纷”。
4. **刑事案件的 `{{STAGE}}` 会转为序号串**（①②③）。程序性文书基本用于民事案件，若涉及刑事附带民事，应核对阶段表述。
5. **`procedural-templates/` 不纳入构建脚本**。`build.go` 与 `build.cjs` 只遍历 `original-skill/` 与 `docs/`，不会触及该目录，因此其内容需独立维护、独立备份。
6. **与工作台模板库的关系**。该文件夹的模板与 `resources/templates/` 下的 13 份委托材料模板是两套资产，前者供逐案套用，后者由工作台注入生成，不应互相覆盖。
7. **内容层面仍须律师终审**。模板提供的是程序骨架与固定句式，请求事项的表述、财产线索的完整性、法条援引的适配性均须承办人逐案判断。
