# 架构审查及门禁登记 3.3.0

> **本文档是 3.3.0 的架构快照**，其中模板份数、分组与收费模式的描述反映当时状态。
> 3.4.0 已改为按主体分 3 组共 13 份模板、收费条款支持三种模式并由生成时注入，另新增民事合同收费条款锚点校验。
> 详见 `CHANGELOG.md` 与 `docs/template-refactor/改造执行计划.md`。

一、架构设计

运行入口为启动.html，依赖vendor、data、app本地文件。core提供业务和Word处理，excel负责输入，packages负责数据交换与持久化，ui负责页面状态，idscan负责可选的证件识别入口，自检独立于案件数据。original-skill只用于备份与对照。Go将数据和文档转成file://可加载脚本。证件识别为可选增强：页面只与本机回环驱动（tools/ocr-driver）通信，驱动独立安装、独立运行；未启动驱动时功能入口自动隐藏，其余功能不受影响；除该回环地址外，页面不产生任何连接。结论：业务模块与维护入口齐备；没有通过源码备份冒充运行能力。

二、运行路径

已走通Excel→映射→选案→核对→生成→下载，以及工作包恢复、模板处理预览→验证→采纳→恢复。模板处理生成副本，校验失败不覆盖当前工作资源。修复P1：收费转换误采纳到原收费组；修复P1：浏览器保存失败错误状态；修复P2：切换案件或编辑后旧输出未同步的风险，通过输出失效和模板选择同步处理。当前无已知阻断运行路径；原生目录对话框核验见验收报告。

三、代码实现

金额使用BigInt整数分；ZIP限制压缩包、展开量及文件数，检查CRC、路径、活动内容与外部关系。XML拒绝DTD与实体。DOM文本替换支持跨run并处理所有Word XML部件，维护保留非文字节点。导入包先验证再提交，事务存储返回失败时不显示成功。修复P1：空白注入横跨正文误删；修复P2：含换行的字段下划线遗漏；修复P1：无关字段编辑清除公式错误。均纳入回归覆盖。正则规则由本地高级配置维护，适用于受信任的维护配置；复杂自定义正则可能影响性能。

四、内容一致性

原文件与功能映射见能力迁移表；22模板内容与Python输出逐一对照通过。程序、配置、规则、根元数据当前3.3.0，备份原3.2.0有意保留。律所与账户以模板为实际生成来源，defaults不默默改写模板常量。原桌面源不可用清单与页面说明一致。P2人工核验：真实Word分页尚未验证。

五、门禁与证据

| 规则 | 执行门禁 | 正例 | 反例 |
| --- | --- | --- | --- |
| 金额和费率明确 | money/parseFee | 万元、角分、百分比 | 负数、分期、多金额、越界 |
| 模板字段有效 | validateTemplate | 原22份 | 未知字段、必要字段缺失 |
| 安全Office包 | checkPackage/xml | 原DOCX、标准XLSX | 外部关系、DTD实体、不安全路径 |
| 版本和完整性 | validateConfig/unpack | 工作包、资源包恢复 | 错版、损坏、哈希错误 |
| 离线连接约束 | HTML CSP connect-src 仅放行 127.0.0.1:17801 | file://完整流程；本机驱动识别链路 | 外网请求数为 0；未启动驱动时无任何连接 |
| 保存状态真实 | storage事务与UI异常处理 | 记住并恢复 | 模拟容量不足 |
| 模板副本保护 | 预览、校验、采纳 | 清理、转换、重建 | 不完整模板拒绝 |

用户要求“实际上是把SKILL里面的全部内容、能力都转化为HTML及相关数据文件”，因此逐项登记可执行入口、资产和测试；单纯存档不计迁移完成。现阶段代码修订已完成并回归通过，待核销人工验收项保留在报告，不以静态门禁代替。
