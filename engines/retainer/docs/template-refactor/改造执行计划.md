### 1.2 数据流（务必理解）

```
original-skill/templates/<组名>/<文件>.docx
        │  tools/build.go 遍历 original-skill
        │  组名 = docx 的直接父目录名（无硬编码）
        │  tag  = 由文件名子串推导：合同→contract、授权→auth、身份证明→legalrep、
        │         所函→letter、会见→meeting_letter、其余→checklist
        ▼
data/builtin.js（每项含 id/group/name/tag/base64/sha256/builtin）
        │  同时复制到 resources/templates/<组名>/
        ▼
app/core.js 读取为 R.templates → generate() 生成文书
```

**两个容易搞反的函数**（`app/core.js`）：

- `inject(data, group, tag)`：**模板制作阶段**用，把具体文本转成 `{{占位符}}`（方向：文本 → 占位符）；
- `replaceInPara(p, map)`：**生成阶段**用，把 `{{占位符}}` 换成值（方向：占位符 → 值）。

### 3.1 目录结构：只按主体分组

```

├── 个人委托/   1 民事委托代理合同.docx、2 授权委托书.docx、3 所函.docx、⭐️当事人需提供的材料清单.docx
├── 公司委托/   1 民事委托代理合同.docx、2 民事授权委托书.docx、3 法定代表人身份证明.docx、4 所函.docx、⭐️贵公司需提供的材料清单.docx
└── 刑事/       1、刑事辩护委托合同.docx、2、刑事授权委托书.docx、⭐️贵方需提供的材料清单.docx、会见信.docx
```

组名（`group`）改为：**`个人委托` / `公司委托` / `刑事`**。

### 3.2 两个维度正交

| 维度 | 决定什么 | 入口 |
|---|---|---|
| **主体** | 需要哪一套手续材料（公司多一份「法定代表人身份证明」） | 「使用模板组」下拉 / 「主体类型」字段 |
| **收费模式** | **合同第六条**的条款文案 | 「收费方式」字段 |

收费模式只影响「合同」一份文书的某一段，因此不应出现在文件夹与组名中。

### 3.3 生成顺序（不可颠倒）

```
取模板 → 若 tag==='contract'：swapFee 注入收费条款 → replaceInPara 填充占位符 → 校验无残留
```

**依据**：`generate()` 有硬断言 `!text.includes('{{')`。若顺序颠倒，`swapFee` 写入的
`{{UPFRONT_FEE}}` 无人替换，断言直接失败。

## 4. 三段收费条款（最终文案）

> 存放位置：`data/config.json` 的 `feeClauses`，**结构为段落数组**（见 5.2）。
> 数组每一项 = 一个独立 Word 段落。

### 4.1 `fixed` 固定收费（2 段）

```text
六、甲乙双方协商确定，本次法律服务采用以下固定收费模式。
甲方应于本合同签订之日起三个工作日内一次性向乙方支付一审程序律师费人民币{{UPFRONT_FEE}}。如案件进入二审程序，甲方同意继续要求乙方处理的，二审程序律师费按照一审程序律师费金额的60%收取。如案件进入执行程序中的立案阶段，甲方同意继续要求乙方处理的；乙方继续代理执行程序中的立案阶段，相关费用不再额外收取。
```

### 4.2 `semi_risk` 半风险（4 段）

```text
六、甲乙双方协商确定，本次法律服务采用以下半风险代理收费模式。
1.半风险代理模式收费。甲方应在本合同签订后三日内支付前期律师费{{UPFRONT_FEE}}（前期律师费仅为一审阶段费用），如案件进入二审程序、执行立案程序，乙方继续代理，相关费用不再额外收取。
2.除前期费用外，甲方同意按"回款金额"的{{RISK_RATE}}向乙方另行支付风险律师费。"回款金额"系指自本合同生效之日起，乙方为甲方提供法律服务，促使甲方与对方当事人通过和解、调解、裁决、判决、执行或其他任何方式实际收回或抵扣的全部款项。如果甲方实际收到的是现金以外的资产，乙方有权选择以评估金额或实际变现金额为依据计算律师费；且甲方每次收到回款或获取到偿债资产就应按照前述约定支付律师费，无需等到案件的全部应收款项得到清偿再支付律师费。甲方确认：选择上述风险收费方式前，乙方律师已告知其风险收费的含义、不能采取风险收费的案件类型、风险收费各个环节的最高收费金额等内容。
3.甲方已支付的前期律师费为乙方已提供法律服务的对价，无论案件处理结果如何，均不予退还。甲方未经乙方书面同意单方解除本合同的，已支付的前期律师费不予退还；乙方已实现回款的，甲方应按本合同约定标准支付风险律师费。甲方未经乙方书面同意与对方当事人达成和解、调解或撤回起诉、撤回申请的，视为乙方已完成委托事项，甲方应按本合同约定标准支付风险律师费。
```

### 4.3 `pure_risk` 全风险（3 段）

```text
六、甲乙双方协商确定，本次法律服务采用以下全风险代理收费模式。
甲方同意按"回款金额"的{{RISK_RATE}}向乙方支付风险律师费。"回款金额"系指自本合同生效之日起，乙方为甲方提供法律服务，促使甲方与对方当事人通过和解、调解、裁决、判决、执行或其他任何方式实际收回或抵扣的全部款项。如果甲方实际收到的是现金以外的资产，乙方有权选择以评估金额或实际变现金额为依据计算律师费；且甲方每次收到回款或获取到偿债资产就应按照前述约定支付律师费，无需等到案件的全部应收款项得到清偿再支付律师费。甲方确认：选择上述风险收费方式前，乙方律师已告知其风险收费的含义、不能采取风险收费的案件类型、风险收费各个环节的最高收费金额等内容。
乙方已实现回款的，如甲方未经乙方书面同意单方解除本合同，甲方应按本合同约定标准支付风险律师费。甲方未经乙方书面同意与对方当事人达成和解、调解或撤回起诉、撤回申请的，视为乙方已完成委托事项，甲方应按本合同约定标准支付风险律师费。
```

### 4.4 对原始文本的四处修正（重要，勿遗漏）

| # | 原文问题 | 修正 | 原因 |
|---|---|---|---|
| 1 | `支付前期律师费{{UPFRONT_FEE}}元` | 删去末尾「元」 | `{{UPFRONT_FEE}}` 本身已含「元」，否则产出「伍万元整元」 |
| 2 | `"回款金额"系指通过合同生效之日起…` | 改为 `自本合同生效之日起…` | 原句语法不通 |
| 3 | 半风险用「通过和解」、全风险用「达成和解」 | **统一为「通过和解」** | 同一概念表述须一致，避免解释争议 |
| 4 | `提供部分法律服务` 的「部分」 | **删去「部分」二字** | 「部分」可能被解释为「乙方仅提供部分服务」，对律所不利；如本意为阶段性服务，建议写「阶段性」 |

> 第 4 项为实质性措辞取舍，**正式启用前请律师终审**。

### 4.5 增补条款的落位

三条实务条款写在 **4.2 的第 3 段**与 **4.3 的第 2 段**，分别覆盖：

1. **前期费用不退**（仅半风险适用，因全风险无前期费）
2. **甲方单方解除合同时的费用处理**
3. **甲方绕开律师私下和解/撤诉的防范**（风险代理最易被规避的漏洞）

### 阶段 3 · 核心机制（`app/core.js`）

**3.1 重写 `swapFee()`** —— 本次改造的核心难点。
现状只能「替换首段 + 删除旧子段」，**无法新增段落**，会导致「模板是固定版、用户选半风险」
时产出「标题是半风险、正文还是固定」的自相矛盾合同。

改为「替换首段 → 删除全部旧子段 → 按需插入新段」，且**新段必须克隆首段格式**：

```js
async function swapFee(data, type) {
  const clauses = R.config.feeClauses[type];
  assert(Array.isArray(clauses) && clauses.length, '未知收费类型');
  let found = false;
  const out = await transformDoc(data, (p, report, location) => {
    const s = ptext(p);
    // 双锚点兼容：新写法 + 旧模板残留写法
    if (!(s.includes('甲乙双方协商确定') && s.includes('收费模式')) && !s.includes('本合同律师费约定如下')) return;
    assert(!found, '发现多处收费条款，请先整理模板');
    found = true;

    // 1) 收集紧随其后的旧子段（1./2. 或 （1）（2））
    const old = [];
    for (let n = p.nextSibling; n && n.nodeType === 1; n = n.nextSibling) {
      const t = n.localName === 'p' ? ptext(n) : '';
      if (/^\s*(?:[1-9][.．、]|（[1-9]）)/.test(t)) old.push(n);
      else if (!t.trim()) continue;
      else break;
    }
    // 2) 取格式模板：首段 pPr + 首个 run 的 rPr
    const pPr = [...p.children].find(c => c.localName === 'pPr');
    const firstRun = els(p, 'r')[0];
    const rPr = firstRun && [...firstRun.children].find(c => c.localName === 'rPr');
    // 3) 替换首段、删除旧子段
    replaceRange(p, 0, s.length, clauses[0]);
    for (const n of old) n.remove();
    // 4) 插入新子段（克隆格式，保证与合同其余条款一致）
    let anchor = p;
    for (const text of clauses.slice(1)) {
      const np = p.ownerDocument.createElementNS(W, 'w:p');
      if (pPr) np.append(pPr.cloneNode(true));
      const nr = p.ownerDocument.createElementNS(W, 'w:r');
      if (rPr) nr.append(rPr.cloneNode(true));
      const nt = p.ownerDocument.createElementNS(W, 'w:t');
      nt.setAttributeNS('http://www.w3.org/XML/1998/namespace', 'xml:space', 'preserve');
      nt.textContent = text;
      nr.append(nt); np.append(nr);
      anchor.after(np); anchor = np;
    }
    underlinePlaceholders(p);
    report.push({ location, before: s, after: clauses.join('\n') });
  });
  assert(found, '未找到收费条款锚点（应含「甲乙双方协商确定」且含「收费模式」）');
  return out;
}
```

**关键**：不克隆 `pPr`/`rPr`，新插入的段落会用默认字体字号，在合同里一眼看出格式不齐。

**3.2 `generate()` 接入**（顺序不可颠倒）
```js
let base = bytes(t.base64);
if (t.tag === 'contract') base = (await swapFee(base, info.fee_type)).bytes;  // 先注入条款
const filled = await transformDoc(base, p => replaceInPara(p, map));           // 再填占位符
```

**3.3 `parseFee()` 支持全风险**
```js
if (type === 'pure_risk') {
  assert(amounts.length === 0, '全风险收费不应填写前期金额');
  assert(rate !== null && Number(rate) > 0 && Number(rate) <= 100, '全风险收费需要 0 至 100 之间的费率');
  result.upfront = '零元整'; result.upfront_short = '0';
  result.risk_rate = '百分之' + integerCN(rate.split('.')[0], true) + `（${rate}%）`;
}
```
同时放宽 fixed/semi_risk 原有的「金额个数必须为 1」限制，使三态可辨。

**3.4 收费模式自动识别（`normalize()`）** —— 由纯关键词改为**结构化优先**：

| 解析结果 | 判定 |
|---|---|
| 有金额、无费率 | `fixed` |
| 有金额、有费率 | `semi_risk` |
| **无金额、有费率** | **`pure_risk`** |
| 均未解析出 | 回退 `riskKeywords` 关键词 |

> 现有纯关键词判断无法区分半风险与全风险（两者都含「风险」）。

## 6. 已知陷阱（务必阅读）

1. **生成顺序**：必须 `swapFee` → `replaceInPara`。颠倒会导致 `{{UPFRONT_FEE}}` 残留并触发断言失败。
2. **`inject` ≠ 填充**：`inject()` 是模板制作阶段的反向操作，与生成无关。
3. **`group.split('-')`**：组名改造后此写法全数失效，见阶段 4。
4. **`~$` 锁文件**：Word 打开文档时会生成，`build.go` 不加过滤会误收。
5. **`_deprecated-templates/` 不可放回 `original-skill` 下**，否则被 build.go 收录。
6. **模板缺「七、」编号**：「六、」之后直接是收款账号段，再跳「八、特别约定」——这是模板固有现象，**不要"修正"**。
7. **旧模板存在 6 处非收费差异**（标题排版、第四条子段结构、固定版多两段、第十条有效期、第十一条生效表述、签署栏）。本轮已选定 `个人委托/1 民事委托代理合同.docx` 为基准，**不做合并**，仅记录备查。
8. **`{{UPFRONT_FEE}}` 已含「元」**，条款里再写「元」会重复。
9. **压缩/解压用 `tar`**，不要用 `Expand-Archive`/`Compress-Archive`（实测 667 秒 vs 9.3 秒）。
10. **给 Windows 写 .bat 时内容保持纯 ASCII**，或存为 GBK；UTF-8 中文会在 cmd 下乱码甚至导致脚本崩溃。

### 逻辑冲突排查（2026-09-15 补做）

用户要求「修复潜在的代码运行逻辑冲突，确保不会出现该问题」，遂对本次改造的连带面做了系统排查，发现并修复 4 类问题：

**① 刑事案件的合同被误注入民商事收费条款（严重）**

`core.js` 的生成入口原为：
```js
if (t.tag === 'contract') src = (await swapFee(src, normalized.fee_type)).bytes;
```
只判断 `tag`，未判断案件类型。而**刑事辩护委托合同同为 `contract`**，其第六条为
「六、甲方应在本合同签订之日起根据国家制订的收费标准，依下列条件支付乙方如下费用：」，
**不含任何锚点文本**，因此 `swapFee` 的 `assert(found, '未找到收费条款锚点…')` 会失败，
**导致刑事案件完全无法生成文书**。

同时，模板管理页 `ui.js` 已明确限制「收费条款转换**仅用于民事委托合同**」——两处判定不一致，属典型遗漏。

修复：
```js
if (t.tag === 'contract' && normalized.case_type === 'civil') ...
```

**② `build.go` 只写不删，副本目录残留旧分组**

`resources/templates/` 由 `build.go` 复制生成，但脚本只写入不清理。分组由「个人-固定」等改为「个人委托」后，
**旧分组目录仍留在磁盘上**（实测残留至 22 份），造成「副本 = 3 组 13 份 + 旧 4 组 22 份」的混杂状态，
`_craft_meta.json` 的哈希清单也同时收录新旧路径。
修复：重建前 `os.RemoveAll("resources/templates")`。清理后副本为 **3 组 13 份**，
`_craft_meta.json` 由 92 项收敛至 74 项。

### 阶段 4 遗漏项的补正（3.4.1）

本计划阶段 4 与「完善点评估」均记载需逐一核对 `app/ui.js` 中 `split('-')` 一类的旧组名用法，实际执行时遗漏一处，构成 3.4.0 的功能性缺陷：源模板重建映射表的模板组默认值仍拼装 3.3.0 旧组名（`个人-固定` 等），该值不在选项中，按 HTML 规范会将 `selectedIndex` 置为 -1、`value` 置为空串，导致注入时 `party` 取空值、全部带主体限定的规则失效，处理结果一律报「未知模板分组」。3.4.1 改为直接映射三主体组，并已回归验证。

**方法论沉淀**：改造数据结构或命名时，「同类判定条件的逐一核对」不能以计划条目代替实际检索。3.4.1 的复查方式为对全目录检索旧组名字面量，命中应逐条判定其存废，其中 `app/uitest.js` 与 `app/packages.js` 的旧版本号为有意保留（分别用于旧包模拟与旧版兼容白名单），不作修改。
