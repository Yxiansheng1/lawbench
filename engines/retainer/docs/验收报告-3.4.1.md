## 四、未完成的验收项目与边界

1. **Python 版本对照未执行**。`tests/parity.cjs` 与 `tests/parity_check.py` 用于比对现行 HTML 版与 v3.2.0 Python 存档版的输出一致性，本次未运行（需 Python 环境与 `python-docx` 依赖）。`docs/test-results/parity-results.json` 仍为 2026-09-13 的 3.3.0 快照。**不得以本报告替代该项验证。**
2. **实际分页已核验（2026-09-16 补做，原为本项未核销事项）**。本机已配置 LibreOffice，采用官方 MSI 的管理安装方式提取至本地目录，不注册、不写系统，取得方式与用法见 `tools/render-check.ps1` 头部说明。据此对交付文档作了真实渲染核验：程序性文书模板 25 份、注入后的程序性文书 4 份（法院名替换为 24 字长名以测试极端情形）、既有委托材料模板与工作台生成样本 12 份，全部渲染正常，页面为 A4（595 × 842 pt），标题 22pt 黑体、正文 12pt 仿宋，内容未越出纸张边界。

   渲染核验中发现并修正一处真实缺陷：延期举证申请书原有一行因含不可断的长标记（法院占位符与其后长句同处一行）而溢出版心 11pt，已将该句拆为两段解决。另有少量行因中文避头尾规则产生标点悬挂，超出版心约一个字符宽（实测最大 12.4pt），仍在页边距余量之内，属中文排版的正常现象，不予处理。

   **结论：无需再以 Word 人工逐份核对分页。** 如需复核，执行 `tools/render-check.ps1` 可重现渲染结果；版式数值可用 PyMuPDF 读取 PDF 后比对上述标准。
3. **原生目录选择对话框未自动化**。目录写入接口以模拟 File System Access API 验证重名保护与内容完整性，原生对话框未作端到端验收。
4. **构建工具链**。本次本机无 Go 环境，改用等价的 `tools/build.cjs` 生成数据加载脚本与模板副本，该脚本已通过字节级复现校验（`data/config.js`、`data/rules.js` 与 Go 版输出完全一致）。**Go 环境可用时仍应以其重新生成一次。**
5. **构建烙印为手工重算**。`_craft_meta.json` 的哈希与时间戳由脚本按 `skill-crafting` 的既有结构重算，未经过该工具链的 `verify` 与 `stamp` 流程。
6. **`template-checksums.json` 记录失配**。`data/source-manifest.json` 中该文件的记录哈希与实际文件不符，属构建顺序问题，建议先以 `tools/refresh-checksums.py` 重算再执行一次构建。

## 五、结论

3.4.1 已完成 10 项缺陷修复，内置自检、页面工作流与双浏览器端到端测试全部通过，版本号六处一致，缺陷项均已回归验证；实际分页已通过 LibreOffice 渲染核验。第四部分其余各项仍为未核销边界，其中 Python 版本对照应在发布对外交付前补做。自动检查与结构校验通过不代表对法律条款内容作实体审核，商事合同的收费条款与实务约定仍需律师终审。
