# 程序性文书模板（procedural-templates）

本目录收录 25 份民事诉讼常用程序性文书模板，共 4 类。

**重要**：本目录**不被工作台自动读取**。它既不是 `resources/templates/` 下的委托材料模板，也不参与工作台的文书生成。使用方式见下文第二部分与第三部分。

## 一、目录结构

```
procedural-templates/
├── README.md                    本文件
├── 通用母版.md                  可复制的通用骨架与固定句库
├── A-程序启动与推进/             9 份
├── B-诉的处分与当事人变更/        7 份
├── C-保全配套与执行/             7 份
└── D-审级救济与程序障碍/          2 份
```

## 二、直接套用（推荐）

1. 找到与本案程序动作对应的模板，另存为本案文件名；
2. 手工替换文中的 `________` 待填项（案号、金额、财产线索、请求事项等）；
3. 核对首部信息栏与落款；
4. 在 Word 或 WPS 中复核分页与版式后提交。

## 三、可选：由工作台自动填充主体信息

模板中的当事人、案由、法院、年份已写成工作台可识别的占位符。如需自动填充，可把模板作为「附加文书」导入工作台：

1. 打开工作台 `启动.html`；
2. 进入「模板管理」页；
3. 在「分组」中选择与本案主体相符的组（个人委托／公司委托／刑事）；
4. 在「文书类型」中选择「附加文书」；
5. 点「导入占位符模板」，选择本目录中的模板文件；
6. 回到「案件与文书」页，核对案件字段后勾选该文书生成。

导入后模板存于浏览器存储，换机时请用「保存与资源」页导出资源包备份。

## 六、文书体例与使用注意

### 文书体例

模板已按法律文书的陈述体例编排，使用时无需再调整结构。

1. 全文顺序为：标题、当事人身份信息、请求事项、事实与理由、此致、落款、附项。案号为法院立案后编制、案由由法院确定，当事人提交的申请书不设这两栏，案号在事实与理由中表述。
2. 事实与理由以连贯段落陈述，不设小标题。叙述顺序为：案件程序进展、申请所依据的事实、法律依据、如不予准许的后果与请求。不使用写作技法名称或分栏标签，避免呈现套用模板的痕迹。
3. 当事人身份信息栏预留性别或单位类型、住址、证件号码、联系电话等待填项；单位委托的案件另需注明统一社会信用代码与法定代表人。
4. 落款为「申请人：________」与日期，右对齐；附项列于落款之后。
5. 版式：A4，页边距上下 2.54 厘米、左右 3.18 厘米；标题黑体 22pt 居中；各级标题与正文均仿宋 12pt、行距 1.5 倍、首行缩进 2 字符；西文与数字统一 Times New Roman。

### 使用注意

1. 模板提供文书骨架与文书语言，请求事项、财产线索、待证事实须逐案填写，不得照搬其他案件内容。
2. `{{CAUSE}}` 的取值会自动去掉尾部「纠纷」二字，模板中已统一写作「{{CAUSE}}纠纷」，修改时勿删去「纠纷」。
3. 待填标记为下划线字符 `_`，可整体替换为实际内容；不要改为 Word 下划线格式，以免导入工作台后被注入规则误判。
4. 涉及金额的模板，请求数额不得超过诉讼请求数额；保全担保比例以法院要求为准。
5. 法条引用已逐条核验（核验日期 2026-09-16，依据《民事诉讼法》2023 修正本与《民诉法解释》2022 修正本）。法律修改后须重新核验。
6. 模板不构成对具体案件的法律意见。

## 七、维护

本目录由 `tools/build-procedural.cjs` 生成，执行 `node tools/build-procedural.cjs` 可重新生成全部模板。修改模板内容应修改该脚本中的模板定义后重跑，不建议直接编辑 DOCX。
