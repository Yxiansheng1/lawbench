# 人工操作单 · 6000D 残留检查（上线必过第 5 项的 6000D 部分；SEC-09）

6000D 是甲方的网关，我方不改它（PRD F-ACC-02）。AI 不保存、不索要 SSH 密码，由用户登录执行。

## 步骤

1. 先用 `criminal-01` 副本在客户端里做一次对话和一次 wiki 生成（请求里会带案卷正文和特征字符串 `LBFX-CRIM01-7Q3Z`）。
2. 用户 SSH 登录 6000D，执行（只读搜索，不改任何文件）：
   ```bash
   sudo grep -rIl --exclude-dir=proc --exclude-dir=sys -e 'LBFX-' \
     /tmp /var/tmp /var/log "$(dirname "$(readlink -f "$(command -v vllm 2>/dev/null || echo /opt/x)")")" \
     /opt /srv /home 2>/dev/null | tee ~/lbfx-residue.txt
   echo "命中文件数：$(wc -l < ~/lbfx-residue.txt)"
   ```
   网关的 `usage.db`（SQLite）另查：
   ```bash
   sudo find / -name 'usage.db' -not -path '/proc/*' 2>/dev/null | while read f; do
     echo "== $f"; sudo sqlite3 "$f" ".tables"; sudo grep -c 'LBFX-' "$f"; done
   ```
3. 把两段命令的输出（只有文件路径和计数）贴回给主编排。

## 判定

- **通过**：命中文件数为 0；`usage.db` 里 `LBFX-` 计数为 0，表中只有用户、时间、token 数、耗时、状态等元数据字段。
- **不通过**：任何命中。命中路径交主编排，由律所决定网关侧怎么处理（我方不改网关）。
