# 文本格式契约（契约 1.0）

JSON 以外、写成 Markdown 或纯文本、又被多个模块共用的格式。JSON 部分见同目录下的 `*.schema.json`。

## 1. 案件目录

```
<案件文件夹>/                       律师指定；= DSH 工作区 = 会话 cwd
├─ <律师的原有文件和子文件夹>         原件区：除 工作区/、成果/ 和以 . 开头的项以外的全部内容
├─ 工作区/
│  ├─ case.db                       case_db.sql
│  ├─ 材料/
│  │  ├─ index.json                 files/material_index.schema.json
│  │  ├─ _处理状态.md                程序生成，给律师看，无固定格式
│  │  ├─ 文本/<原件相对路径>.md       本文第 2 节
│  │  └─ 识别页/<material_id>/<页号>.md   395 返回的 markdown 原样保存
│  ├─ wiki/
│  │  ├─ case.json                  files/case_card.schema.json
│  │  ├─ 待确认.json                 files/wiki_pending.schema.json
│  │  ├─ 案件/概览.md、当事人.md、时间线.md、争议焦点.md、材料清单.md   本文第 4 节
│  │  ├─ 材料/<material_id>.md       材料摘要页，本文第 4 节
│  │  ├─ index.md、log.md            程序生成
│  ├─ 任务/<task_id>/
│  │  ├─ task.json、reads.json、result.json
│  │  ├─ 草稿/<标题>-v<N>.md、进行中.md、未完成-<YYYYMMDDHHMMSS>.md
│  │  └─ 修改清单/<合同材料名>.json   tools/case_save_edit_list.schema.json#/$defs/args
│  ├─ 会话/<DSH 会话ID>/             DSH 会话记录（格式由 DSH 定，本契约不约束）
│  └─ 临时/                         用完即删；任何模块不得依赖其中文件跨请求存在
└─ 成果/
   ├─ 索引.json                     files/outputs_index.schema.json
   └─ <标题>-v<N>.md / .docx
```

## 2. 材料文本（工作区/材料/文本/*.md）

```
# <材料名>

> Source: <原件相对路径>（<文字版 | 识别所得 | 部分识别>，<N><页|段|行|个工作表>）
> Collected: <YYYY-MM-DD>
> Note: <index.json 中的 note，没有则省略此行>

【第1页】
<原文>

【第2页】
> 识别所得
<识别文本；看不清的字用 ■，整行看不清用 [看不清]；本页尚未识别时为：（本页需识别）>
```

位置标记（只出现在材料文本里，草稿和成果中不得出现）：

| 格式 | 标记 | 说明 |
|---|---|---|
| PDF、图片 | `【第N页】` | 每页一个 |
| Word | `【第N段】` | 正文非空段落顺序号；表格整体算一段，内部转成 md 表格；页眉页脚、脚注附在文末另成一段 |
| Excel | `【表:<工作表名>】` 后接带行号列、列字母表头的 md 表格 | 出处写 `工作表名!B12` |
| csv、md、txt | `【第N行】` | 每 50 行标一次，引用时写具体行号；csv 保留原始分隔的每一行 |

`case_read_material` 的 `start` / `end`：页、段、行为对应序号；Excel 为工作表内的行号，跨工作表时从下一个工作表的第 1 行重新计数，`text` 中保留 `【表:…】` 标记。

## 3. 出处

- 写法见 `common.schema.json#/$defs/citation_text`：`〔材料名 第N页〕`、`〔材料名 第N-M段〕`、`〔材料名 第N行〕`、`〔材料名 工作表!B12〕`；一个括号内多处用顿号分隔，每处都写材料名；另有 `〔未找到依据〕`、`〔推断〕`。
- `〔〕` 只用于出处。`【】` 在草稿和成果中只用于占位和标签（如 `【待补充：缺什么】`、`【待确认我方立场】`、`【律师提供】`、`【P0】`），不得用于出处；形如 `【材料名 第N页】` 的写法按出处格式错误（E 类）处理。
- 材料名唯一规则：优先用原件文件名去掉扩展名；案件内重复时，改用去掉扩展名的相对路径（如 `证据/借条`）；仍重复时用带扩展名的相对路径（如 `证据/借条.pdf`）。材料名中不得含空格和顿号，含有时替换为下划线。
- 法律内容没有律师提供依据的，句末加 `（法律依据待律师核实）`。

## 4. wiki 分节文件

- `案件/*.md`：一级标题为节名；正文每条事实一行或一段，句末带出处。
- 律师修改保护块：`<!-- 律师修改 -->` 与 `<!-- /律师修改 -->` 之间的内容，更新 wiki 时原样放回原位置；原位置不存在时放到文末并加 `> **Status: 待律师核对**`。
- `材料/<material_id>.md`：首行 `# <材料名>`；筛选型摘要（银行流水等）第二行写 `> 筛选条件：…；已列出 X 行 / 共 Y 行`。

## 5. 草稿文件（草稿/<标题>-v<N>.md）

纯 Markdown，出处按第 3 节。文件开头不加元数据，版本、来源、核对结果都在 `result.json`。同标题再次保存时 N 加 1，旧版本保留。

## 6. 流水线提示词（skills/<skill>/流水线提示词.md）

按二级标题分段：`## 通用规则` 必须有；其余每个 `## <步骤名>` 对应流水线的一个步骤，步骤名由该流水线的代码固定引用（案件 wiki：`材料摘要`、`当事人`、`时间线`、`争议焦点`、`概览`、`案件卡片`、`修改`）。
